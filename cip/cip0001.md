# CIP-0001: Restore contemporary build and runnable verification

## Status

- [x] Proposed - Initial idea documented
- [x] Accepted - Approved, ready to start work
- [x] In Progress - Actively being implemented
- [x] Implemented - Work complete, awaiting verification
- [x] Closed - Verified and complete
- [ ] Rejected - Will not be implemented
- [ ] Deferred - Postponed

## Summary

Make GPc build and its existing reference tests runnable again on a contemporary developer platform (starting with this macOS workspace), without yet retiring MATLAB bridges. Add basic CI that checks compilation on every push/PR. Addresses REQ-0001 and REQ-0002. Explicitly leaves REQ-0003 (MATLAB retirement) for a later CIP/release. Rename the default git branch from `master` to `main` as part of bringing the repo into contemporary practice.

## Motivation

The repository still contains substantial modelling code, makefile test targets, and `matfiles/` fixtures, but the practical verification path is broken or unreachable: platform make fragments are stale, `makefile` hard-includes `make.linux`, tests require `_NDLMATLAB`, and there is no CI. Before dropping dated MATLAB pieces we need evidence the current software still works.

This aligns with **Assert Invariants and Verify Against Reference** (restore a real gate) and **Flexibility Without a Performance Tax** (the C++ tools must still compile).

## Detailed Description

### Current state (as of 2026-11-13)

- Build: top-level `makefile` includes `make.inc` when present, otherwise `make.linux`. `make.osx` is the blessed Homebrew macOS path (OpenBLAS + GCC/gfortran 16); `make.macports` is historic only. `make.inc` is gitignored for local overrides.
- Tests: `make USE_MATIO=1 matio-tests` / `make run-matio-tests` is the hard gate (numeric `.mat` via libmatio). Object-level MATLAB I/O remains behind `_NDLMATLAB`.
- CI: Compile, Reference tests, and Coverage workflows on `ubuntu-latest`.
- Policy: keep MATLAB bridges for this CIP; retire later under REQ-0003.

### Approach

1. **Platform make config** — Establish a working `make.inc` (or equivalent include) for the development Mac: compiler, Accelerate or other BLAS/LAPACK, gfortran as needed. Prefer documenting one blessed path over preserving every historic `make.*` fragment in working order.
2. **Core build** — Get `gp` linking and a README smoke example running (help and/or a tiny `learn`). Fix only what blocks that outcome (include paths, Fortran runtime, deprecated flags).
3. **Verification path** — Enable the minimum MATLAB interface needed to compile and run the existing `tests` against `matfiles/`, *or* document a narrower subset that can run if full MATLAB libraries are unavailable on this machine—and then choose the path that actually restores a gate. Prefer making the existing suite work over rewriting fixtures in this CIP.
4. **Compile CI** — GitHub Actions workflow on `ubuntu-latest` that installs g++, gfortran, LAPACK/BLAS and builds `gp` (and preferably `ivm`/`gplvm`) so every push/PR proves compilation. Tests that need MATLAB stay out of this first workflow.
5. **Default branch** — Rename `master` → `main` on GitHub and locally.
6. **Maintainer docs** — Update README build/test sections so they match the restored path; note MATLAB dependency explicitly as temporary.
7. **Out of scope** — Dropping mex/`CMatInterface`; replacing `.mat` fixtures; full reference-test CI until REQ-0002 is green locally; large refactors unrelated to build/test.

### Design tension

REQ-0002 allows keeping the MATLAB gate for now. If MATLAB is not installable in the environment, this CIP must either (a) obtain enough of the MATLAB runtime/libraries to run the current tests, or (b) propose a minimal fixture loader that reads the existing `.mat` files without full mex—still not "retiring" the bridges, but unblocking verification. Prefer (a) if practical; use (b) only if (a) blocks progress, and record the choice here before implementation.

**Decision (2026-11-13):** Choose **(b)**. Full MATLAB/`mex` is not available in CI. Add `_NDLMATIO` so `CMatrix` loads numeric `.mat` fixtures via **libmatio**. Object-level MATLAB I/O (kernel/noise/model structs) stays behind `_NDLMATLAB`; matio-mode tests mirror parameters in C++ and still compare kernels/noise/dist numerically against MATLAB-generated arrays. `make USE_MATIO=1 matio-tests` is the CI gate. Full struct deserialization remains future work under REQ-0003 if needed.

## Implementation Plan

1. **Default branch rename**
   - Rename local and remote default branch `master` → `main`
2. **Compile CI + make hygiene for Linux CI**
   - Fix empty `-I$(MATLABINCLUDE)` hazard when MATLAB is disabled
   - Add `.github/workflows/compile.yml` building `gp` (and other core targets) on Ubuntu
3. **Inventory and platform probe (macOS)**
   - Confirm compilers, BLAS/LAPACK, Fortran availability on the Mac
   - Attempt `make gp` with a corrected include; capture first failures
4. **Fix core build (REQ-0001)**
   - Add/refresh macOS make fragment; wire `makefile` to `make.inc`
   - Resolve link/compile errors until `gp` runs a smoke command
5. **Restore tests (REQ-0002)**
   - Enable `_NDLMATLAB` path or approved alternative loader
   - Build and run `tests` (or documented subset); triage failures
6. **Document**
   - README: build, test, MATLAB dependency, temporary nature of that dependency
7. **Stop**
   - Do not delete MATLAB code under this CIP

## Backward Compatibility

Improves ability to build current sources. Should not change model file formats or default CLI behaviour except where required to compile on modern toolchains. Any CLI or stream format change must be called out explicitly. Branch rename does not affect artefacts; update local clones to track `main`.

## Testing Strategy

- GitHub Actions compile workflow green on `main`
- Successful `make` (or documented target) producing `gp` locally
- Successful run of restored reference tests against `matfiles/`
- Manual smoke: `./gp -h` and one short tutorial command if data/time allow
