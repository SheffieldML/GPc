# CIP-0002: Lift C++14 pin: remove dynamic exceptions, target C++17

## Summary

Replace the temporary `-std=c++14` pin from CIP-0001 with a supported modern language mode (C++17), by removing dynamic exception specifications and fixing any further compile breaks that appear under that mode. Addresses REQ-0004. Builds on CIP-0001’s green compile CI.

## Motivation

CIP-0001 restored compilation on `ubuntu-latest` by pinning C++14 because g++ 15’s default C++17 rejects dynamic exception specifications (`throw(Type&)`) used heavily in `CNdlInterfaces.h` (and related headers). That pin unblocks work but fights the toolchain users get out of the box. We should update the code to match contemporary C++, then let CI and `make.linux` declare C++17 explicitly.

This aligns with **Flexibility Without a Performance Tax** (keep building on current compilers) and **Assert and Verify** (compile CI remains the gate while we change language mode).

## Detailed Description

### Current state (post CIP-0001)

- `make.linux` / `make.inc` set `-std=c++14` with a comment explaining the pin.
- Compile CI builds `gp`, `ivm`, `gplvm` and runs `-h` smoke checks.
- Dynamic exception specifications remain on stream helpers, e.g. `readVersionFromStream(...) throw(ndlexceptions::StreamVersionError&)`.
- One related modern-libstdc++ fix already landed: `operator<<(ostream&, const CKern&)` no longer does `out << kern.display(out)`.

### Approach

1. **Inventory** — List every `) throw(` dynamic exception specification in headers/sources that participate in the core build (and note test-only sites for the same cleanup).
2. **Remove specs** — Two clusters:
   - Stream/MATLAB helpers in `CNdlInterfaces.h`: drop `throw(Type&)` from declarations.
   - `ndlexceptions.h`: replace empty `throw()` on destructors/`what()` with `noexcept` (C++11 `std::exception` contract), matching modern libstdc++.
   Keep `throw expr;` statements for actual exception raising. Exception *types* stay; only the removed *specification* syntax goes.
3. **Raise language mode** — Change `-std=c++14` to `-std=c++17` in `make.linux` (and synced `make.inc` / CI path). Prefer an explicit `-std=c++17` over relying on the compiler default, so the project’s floor is clear.
4. **Fix fallout** — Rebuild under CI; repair any additional C++17 / libstdc++ issues in core tools (similar in spirit to the `display`/`operator<<` fix). Do not broaden into unrelated refactors.
5. **Verify** — Compile workflow green; document the standard in README or make comments.

### Non-goals

- Retiring MATLAB bridges (REQ-0003)
- Full C++20/23 migration or clang-tidy driven style overhaul
- Changing exception *policy* (we are not moving to `noexcept` everywhere in this CIP unless a specific call site requires it for compile)

### Design note

Dynamic exception specifications were deprecated in C++11 and removed in C++17. Removing them does not change runtime behaviour of `throw`/`catch`; it only drops obsolete declarations. Callers that relied on the specs for documentation should rely on comments or ordinary C++ types instead.

## Implementation Plan

1. Grep and catalogue `) throw(` sites; confirm which are in the `gp`/`ivm`/`gplvm` link set
2. Strip dynamic exception specifications from those sites ( mechanised edit + review )
3. Switch make flags to `-std=c++17`
4. Push and fix until Compile CI is green
5. Update CIP-0001 / README notes so the C++14 bridge is marked superseded

## Backward Compatibility

Source-compatible for users building with C++17-capable compilers (any maintained g++/clang from recent years). Anyone still forcing a pre-C++11 compiler is already outside CIP-0001’s contemporary-platform goal. No model-file or CLI format changes.

## Testing Strategy

- Existing Compile GitHub Actions workflow must stay green under `-std=c++17`
- Local `make gp ivm gplvm` after flag change (when macOS make is available)
- No new behavioural tests required solely for removing exception specifications
