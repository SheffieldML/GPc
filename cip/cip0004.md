# CIP-0004: gcov coverage reports and Codecov upload

- [x] Proposed
- [x] Accepted

## Summary

Instrument the matio reference suite with gcov, produce an `lcov` report in CI, and upload it to Codecov (same reporting destination as GPy).

## Motivation

Assert Invariants and Verify Against Reference is stronger when we can see which library paths the restored suite actually exercises. Coverage makes gaps in kernels, noise, and matrix wrappers visible without requiring MATLAB.

## Detailed Description

1. **`COVERAGE=1`** in `make.linux` adds `--coverage -O0` to compile and link flags.
2. **`make run-matio-tests`** runs the matio reference binaries in one place for CI and local use.
3. **Coverage workflow** builds with instrumentation, runs the suite, filters system and `test*.cpp` sources out of the lcov trace, and uploads via `codecov/codecov-action@v7`.
4. Upload uses `secrets.CODECOV_TOKEN` when present; `fail_ci_if_error: false` so a missing Codecov project token does not block merges while the org finishes setup.

## Implementation Plan

1. Extend `make.linux` / `makefile` as above; clean gcov artefacts in `make clean`.
2. Add `.github/workflows/coverage.yml`.
3. Document local and CI steps in the README; note Codecov token setup.

## Testing Strategy

- Coverage workflow green on the PR (build, tests, lcov list).
- Codecov receives a report once `CODECOV_TOKEN` is configured for `SheffieldML/GPc`.
