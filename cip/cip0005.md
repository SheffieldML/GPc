# CIP-0005: Verify transpose, retire dead ACM routines, prefer BLAS flags

## Status

- [x] Proposed
- [x] Accepted
- [x] In Progress
- [x] Implemented
- [x] Closed

## Summary

Make matrix transpose trustworthy and lean: restore a hard-gated transpose test suite, retire the unused ACM Algorithms 467 and 380, document Algorithm 513 (`DTRANSR`) correctly, and remove avoidable physical transposes of Cholesky factors in the model code by using BLAS/LAPACK `trans`/`uplo` flags. Defer any rewrite of the rectangular in-place path until measurement shows it matters.

## Motivation

GPc's in-place transpose stack arrived in the initial SVN import and has barely moved since:

- `ndlfortran.f` still carries three ACM in-situ routines: `DXPOSE` (Alg. 467, Brenner), `DTRANS` (Alg. 380, Laflin & Brebner), and `DTRANSR` (Alg. 513 / revised 380, Cate & Twigg).
- Comments in `ndlfortran.h` and `CMatrix.h` mark 467 as broken. The C wrapper historically passed `bool*` for a Fortran `LOGICAL` work array; that was later changed to `int*`, but 467 was never rehabilitated.
- Labels disagree: Fortran comments call `DTRANSR` "Algorithm 380 – revised"; the C++ headers call it Algorithm 513. The header parameter names for `dtransr_` list `(A, ncols, nrows, …)` while `CMatrix::dtransr` (correctly for Fortran `M,N`) passes `(vals, nrows, ncols, …)`.
- The dedicated rectangular transpose check in `testMatrix.cpp` sits inside a large commented block, so that path is not in the Reference tests hard gate. Square `trans()` is exercised indirectly via `testChol` (lower factor, then `trans()` to match the upper fixture), which is not the same as covering tall/wide/coprime shapes or flag behaviour.

### What is *not* the main problem

`CMatrix::trans()` calls `dtransr` for every non-vector matrix. Almost all model call sites (`CGp::updateAD`, `CGp::_updateInvK`, `CGplvm::_updateK`, `CGplvm::_updateDynK`) transpose **square** Cholesky factors. `DTRANSR` already special-cases `M == N` with a plain triangle swap (`GO TO 130`). Those sites do **not** pay the rectangular cycle-following cost. A blocked C++ square path would be a cache polish, not an algorithmic rescue. The higher-leverage issue is that many of those transposes exist only so later code can treat an upper factor as lower — work BLAS/LAPACK can do with flags.

## Detailed Description

Work proceeds in three layers. Optional modernisation of the rectangular path is explicitly out of the critical path.

### 1. Verify before changing

Restore and extend transpose tests in `testMatrix.cpp` so they run in the Reference tests hard gate:

- Shapes: square, tall, wide, single-row, single-column, and both coprime and non-coprime `(m−1, n−1)` rectangular cases (the cycle structure of 513 depends on this).
- Checks: element-wise reference transpose, double-transpose round-trip, and documented behaviour of `symmetric` / `triangular` flags.
- Keep the existing `testChol` upper-via-`trans()` path; do not treat it as a substitute for the dedicated suite.

Land tests first so today's `dtransr` path is known good before deleting or refactoring anything.

### 2. Retire dead ACM code and fix documentation

- Delete `dxpose_` (Alg. 467) and `CMatrix::dxpose`.
- Delete `dtrans_` (Alg. 380) and `CMatrix::dtrans`.
- Keep `DTRANSR` as the sole in-place rectangular implementation for now. Relabel it consistently as **Algorithm 513 (revised 380)** in `ndlfortran.f`, `ndlfortran.h`, and `CMatrix.h`.
- Fix the `dtransr_` header argument names to match Fortran `M,N` (rows, then columns of the matrix before transpose). Document the recommended `lwork = (m+n)/2` heuristic next to the call site.
- Leave `CMatrix::trans()` behaviour unchanged in this layer except for documentation and the removal of unused wrappers: vectors still swap dimensions only; non-vectors still call `dtransr`.

### 3. Prefer BLAS/LAPACK flags over physical Cholesky flips

One call site at a time in `CGp.cpp` and `CGplvm.cpp`:

- After `jitChol` / `pdinv`, keep the factor upper where possible and pass the appropriate `uplo`/`trans` into consumers (`trsm`, `trmm`, `potrs`, and any helpers that assume lower).
- Run `make run-matio-tests` (and GP/GPLVM gradient checks where those paths are covered) after each site.
- `CIvm.cpp` vector `trans()` calls used only to feed `setMatrix` may stay or gain a row/column overload; they are already free of element movement.
- Where constructors or I/O copy then transpose (`CMatrix(double*, …)` for numpy, `readFromHdf5(..., transpose=true)`), write straight into transposed layout instead of a second pass — small, local fixes once tests exist.

### 4. Optional / later (measurement-gated)

Only if a profiler or memory budget asks for it:

- Blocked in-place square swap in C++ (compare against `DTRANSR`'s existing square path).
- Blocked out-of-place rectangular copy with ownership respected via `memAllocate` / `memDeAllocate`.
- Catanzaro–Keller–Garland C2R/R2C decomposition as a modern in-place rectangular path, after which `ndlfortran.f` could drop transpose code entirely.
- A `make bench-trans` target to record timings in the PR that introduces any of the above.

Until then, do not expand `trans()` into a multi-strategy dispatcher.

## Implementation Plan

1. Restore and extend `testMatrix` transpose cases; confirm Reference tests stay green.
2. Remove `dxpose` / `dtrans` from Fortran, headers, and `CMatrix`; correct `DTRANSR` labels and `dtransr_` argument documentation.
3. Replace avoidable Cholesky `trans()` call sites in `CGp` / `CGplvm` with BLAS flags, one site per commit or similarly small step, re-running the matio suite after each.
4. Fix numpy / HDF5 "copy then transpose" paths if still present.
5. Update header comments; note in the CIP when optional rectangular modernisation is justified.

## Testing Strategy

- New transpose cases run in the hard-gated Reference tests workflow (no `continue-on-error`).
- After each Cholesky call-site change, `make run-matio-tests` passes; likelihoods and gradients stay within existing tolerances where those tests cover the path.
- `checkGradients` on GP / GPLVM examples that exercise the touched approximations is unchanged.
- Coverage (CIP-0004) shows the active `trans()` paths and the new tests exercised.
- Optional benchmarks belong only to PRs that change the rectangular or square implementation strategy.
