# CIP-0008: Make CMatrix ownership safe under copy and assignment

## Status

- [x] Proposed
- [ ] Accepted
- [ ] In Progress
- [ ] Implemented
- [ ] Closed

## Summary

Give `CMatrix` a coherent ownership model for its raw `double* vals` buffer: implement or delete copy/move assignment so `A = B;` cannot compile into a double-free. Prefer the Rule of Five (deep copy assignment plus move) unless a deleted assignment with forced `deepCopy` proves cleaner at call sites.

## Motivation

`CMatrix` owns heap storage and defines a copy constructor and destructor, but no copy or move assignment operator. The compiler-generated `operator=` copies the pointer. After `A = B;`, both objects free the same memory. The codebase avoids this by convention (`deepCopy`), yet the type system does not. That is a latent correctness bug, not a style preference.

This is the highest-priority finding from a post-CIP-0007 structural review of GPc. It aligns with **Assert Invariants and Verify Against Reference** (stop silent memory corruption) and continues the C++17 modernization path of [CIP-0002](cip0002.md) / [REQ-0004](../requirements/req0004_modern-cpp-toolchain.md).

## Detailed Description

### Current state

- `CMatrix` holds `double* vals` and frees it in `~CMatrix()`.
- Copy constructor allocates and copies elements.
- Assignment is the default member-wise copy (pointer aliasing).
- Call sites that need a real copy use `deepCopy`.

### Approach

1. **Inventory** — Grep for `CMatrix` assignment, pass-by-value, and containers of `CMatrix` that rely on assignability. Note test and model code separately.
2. **Choose policy** (decide in this CIP before coding):
   - **Preferred:** Rule of Five — deep copy assignment; move constructor and move assignment that transfer `vals` and leave the source empty/safe.
   - **Alternative:** `= delete` copy/move assignment and require `deepCopy` / explicit construction everywhere assignment appears. Use only if the inventory shows few assign sites and move is rarely needed.
3. **Implement** the chosen policy in `CMatrix.h` / `CMatrix.cpp`. Self-assignment must be safe. Non-owning views (if any constructors wrap external buffers) must remain clearly documented and must not participate in owning assign incorrectly.
4. **Tests** — Add `testMatrix` cases: copy-construct, assign, self-assign, move (if enabled), and a use-after-assign check that the source and destination are independent.
5. **Docs** — One paragraph in [docs/numerics.md](../docs/numerics.md) or [docs/build-and-ci.md](../docs/build-and-ci.md) stating the ownership rule for maintainers.

### Non-goals

- Replacing `double*` with `std::vector` in this CIP (possible follow-on).
- Changing BLAS layout or column-major conventions.
- Fixing `mutable` model caches ([CIP-0009](cip0009.md)) or kernel `new`/`delete` graphs ([CIP-000A](cip000A.md)).

## Implementation Plan

1. Catalogue assignment and pass-by-value sites.
2. Decide Rule of Five vs deleted assignment; record the decision here.
3. Implement operators; fix fallout.
4. Extend `testMatrix`; keep Reference tests green on Ubuntu and macOS.
5. Compress the decision into `docs/` and set `compressed: true` when closed.

## Testing Strategy

- Full `make run-matio-tests` on the blessed platforms.
- Compile CI unchanged aside from any new symbols.
