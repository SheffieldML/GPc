# CIP-0009: Make GP and GPLVM working-state caches explicit

## Status

- [x] Proposed
- [x] Accepted
- [x] In Progress
- [x] Implemented
- [x] Closed

## Summary

Replace the pattern of large `mutable` working matrices updated inside `const` methods on `CGp` and `CGplvm` with an explicit cache/invalidation protocol (or non-`const` update paths) so factorisations and gradients cannot silently go stale and the models are safer to reason about.

## Motivation

`CGp` and `CGplvm` keep most intermediate state (`Am`, `Lm`, `invK`, Cholesky factors, gradient workspaces, and similar) in `mutable` members. `const` methods recompute and write those caches. That design made sense when the API wanted logical constness for likelihood evaluation, but it has three costs:

1. **Reasoning** — readers cannot tell from the signature whether a call mutates cached factors.
2. **Threading** — concurrent likelihood or gradient calls on one model are unsafe by construction.
3. **Staleness** — a missed `KupToDate`-style flag after a parameter or data change is a correctness bug that `checkGradients` only catches when someone runs it.

The post-CIP-0007 review ranked this after [CIP-0008](cip0008.md) (matrix ownership). It supports **Assert Invariants and Verify Against Reference** without changing the mathematical models.

## Detailed Description

### Current state

- Dozens of `mutable CMatrix` (and related) fields in `CGp.h` and `CGplvm.h` (see Appendix A).
- Flags such as `KupToDate` gate some recomputation; coverage of every write path is unclear.
- Public APIs expose `const` log-likelihood / gradient entry points that fill the caches.
- `COptimisable::computeObjectiveVal` / `GradParams` are `const`, so dropping `mutable` entirely requires a follow-on change to the optimiser interface.

### Protocol decision (Accepted)

Prefer **flag helpers + ensure/invalidate API** over a nested cache object for this CIP. Nested `Cache` extraction remains optional follow-on once call sites use the protocol.

On `CGp` / `CGplvm`:

- `invalidateCache()` — mark all working-state flags dirty (K and M on `CGp`; K on `CGplvm`). Cascade rules stay in the existing setters (`setKupToDate(false)` clears Alpha/AD; `setMupToDate(false)` likewise).
- `ensureMUpToDate` / `ensureKUpToDate` / `ensureADUpToDate` / `ensureAlphaUpToDate` — thin wrappers over `updateM` / `updateK` / `updateAD` / `updateAlpha`.
- Mutators (`setOptParams`, `updateX`, `setApproximationType`, scale/bias/beta/active-set setters) call `invalidateCache` or the specific flag clear.
- Const evaluators (`logLikelihood`, `logLikelihoodGradient` / `updateG`) call `ensure*` before reading factors.

Document: a single model instance remains **single-threaded**.

### Non-goals

- Multi-threaded training in this CIP.
- Rewriting sparse approximations (DTC/FITC/PITC) algorithms ([CIP-000E](cip000E.md) / [CIP-000F](cip000F.md)).
- Kernel ownership modernization ([CIP-000A](cip000A.md)).
- Removing `const` from `COptimisable` objectives (keeps `mutable` necessary for now).

## Implementation Plan

1. Complete the mutable-field / invalidation inventory (Appendix A).
2. Agree the protocol shape — **done**: ensure/invalidate over nested Cache for this CIP.
3. Implement for `CGp`, then `CGplvm`, with Reference tests green after each.
4. Document the protocol in `docs/numerics.md`; compress when closed.

## Appendix A — Mutable inventory (2026-11-15)

### `CGp` flags

| Flag | Cleared by | Cascades |
|------|------------|----------|
| `KupToDate` | kernel / X / inducing / approx / `invalidateCache` | clears Alpha, AD |
| `MupToDate` | scale / bias / y path / `invalidateCache` | clears Alpha, AD |
| `ADupToDate` | beta / cascade from K or M | — |
| `AlphaUpToDate` | cascade from K or M | — |

### `CGp` mutable working matrices (groups)

- Targets / alphas: `m`, `Alpha`
- Sparse AD path: `Am`, `Lm`, `invLmV`, `bet`, `diagD`, `sqrtDiagD`, `scaledM`, `V`, `E`, `EET`, `AinvE`, `AinvEET`, `AinvEETAinv`, `AinvK_uf`, `EMT`, `AinvEMT`, `invK_uuK_uf`, `invK_uuK_ufDinv`, `invK_uuK_ufDinvQ`, diag/work matrices through `diagK_ufAinvEMT`
- Gradients: `inducingIndices`, `gDiagX`, `gK_uf`, `gK_uu`, `gK_star`, `gLambda`, `gBeta`, `g_scaleBias`, `g_param`, `gX_u`, `gXorW`, `tempgX`
- Full / inducing K: `K`, `invK`, `diagK`, `LcholK`, `logDetK`, `covGrad`, `K_uu`, `invK_uu`, `logDetK_uu`, `StorekN`, `K_uf`, `A`, `Ainv`, `LcholA`, `logDetA`
- Kernel grads vs X: `dgKX`, `gKX`, `gKX_uf`, `gKX_uf2`

### `CGplvm` mutable working matrices

- `K`, `dynK`, `gX`, `gDiagX`, `invK`, `invDynK`, `LcholK`, `LcholDynK`, `logDetK`, `logDetDynK`, `covGrad`, `tempgX`
- Flag: `KupToDate` only

### Out of scope for this CIP (still `mutable` elsewhere)

- `CKern` distance / inner-product scratch, `CIvm` / `CPpa` cov caches, `CMltools` activations, `COptimisable` verbosity/optimiser ints.
