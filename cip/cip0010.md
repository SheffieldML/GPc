# CIP-0010: Add a dedicated testOptimisable suite for COptimisable.cpp

> CIPs describe HOW to achieve requirements (WHAT). This CIP strengthens [REQ-0002](../requirements/req0002_runnable-verification.md) for the shared optimiser surface.

## Summary

Add a first-class `testOptimisable` binary (and makefile / CI wiring) that exercises `COptimisable.cpp` directly: gradient checks, SCG / CG / GD / L-BFGS drivers, default-optimiser string mapping (including the `lbfgs` ↔ `quasinew` synonym), and basic termination behaviour — using a tiny analytic toy objective rather than a full GP.

**Which requirements does this CIP address?** REQ-0002 (runnable verification). It also improves Codecov visibility for the optimiser translation unit, which today is only hit indirectly via model tests.

## Motivation

`COptimisable` is the shared training surface for GP, GPLVM, IVM, and mltools. Recent work (L-BFGS buffer lifetime / `iflag` success path, `lbfgs` synonym) showed that optimiser bugs can sit behind CLI and model layers with no unit gate.

Today:

- `checkGradients` is called from some model tests (`testIvm`, `testMltools`), but there is **no** `testOptimisable` target.
- SCG / CG / GD / L-BFGS live in `COptimisable.cpp` and are not systematically driven under a known objective.
- Coverage of that file depends on whichever model fixture happens to call `runDefaultOptimiser`.

Assert Invariants and Verify Against Reference wants an early, shape-stable check: a quadratic (or similar) toy `COptimisable` with analytic gradients, then driver smoke that the objective decreases and parameters move sensibly.

## Detailed Description

### Design

1. **Toy model** — A small concrete subclass (e.g. `CQuadOptimisable`) of `COptimisable` (or `CProbabilisticOptimisable` if that keeps the likelihood polarity consistent) implementing:
   - `getOptNumParams` / `getOptParams` / `setOptParams`
   - `computeObjectiveVal` / `computeObjectiveGradParams` for a convex quadratic \(f(x)=\tfrac12 x^\top A x - b^\top x\) (or diagonal \(A\) for simplicity)
   - Known unique minimiser for pass/fail assertions

2. **`testOptimisable.cpp`** — Fail-count style like `testMatrix`:
   - `checkGradients` analytic vs finite-difference within `ndlutil::MATCHTOL` (or a documented looser tol for FD)
   - Each of `scgOptimise`, `cgOptimise`, `gdOptimise`, `lbfgsOptimise` from a fixed start: objective decreases; final params near the known minimiser within a documented tolerance
   - `setDefaultOptimiserStr` / `runDefaultOptimiser` for `scg`, `conjgrad`, `graddesc`, `quasinew`, and **`lbfgs`**
   - Optional: iteration / function-eval terminate flags behave without hanging (bounded `maxIters`)

3. **Build / CI**
   - `makefile`: `testOptimisable` target; add to `matio-tests` **or** a non-matio unit subset if no `.mat` fixtures are required (preferred: no matio dependency for this binary)
   - Reference tests / Compile workflows: build and run `./testOptimisable` on Ubuntu and macOS
   - Exclude the test driver from Codecov patch per existing `codecov.yml` / CIP-0004 practice if needed; library `COptimisable.cpp` should gain hit coverage

4. **Docs** — One short paragraph in [docs/build-and-ci.md](../docs/build-and-ci.md) (or [docs/numerics.md](../docs/numerics.md)) listing `testOptimisable` and how to run it.

### Non-goals

- Replacing SCG/L-BFGS with a new optimiser library
- Full Netlab numerical parity fixtures for every driver (unless a cheap fixture falls out)
- Testing GPLVM/IVM/GP likelihoods here — those stay in `testGp` / `testIvm` / …
- Line-search internals of Nocedal Fortran beyond “L-BFGS terminates and improves the toy objective”

### Alternatives considered

- **Only rely on `testGp -O lbfgs`** — Rejected; too heavy and couples optimiser regressions to GP numerics / fixtures.
- **GoogleTest / Catch2** — Rejected for this CIP; stay with existing fail-count binaries for REQ-0002 consistency.

## Implementation Plan

1. Sketch toy quadratic API and tolerances in this CIP (update if review changes them).
2. Implement `testOptimisable.cpp` + makefile target (no matio unless unavoidable).
3. Wire CI run step; confirm coverage of `COptimisable.cpp` rises on the PR.
4. Document the command in maintainer docs; close CIP after green CI.

## Backward Compatibility

- Additive only: new test binary and CI steps.
- No change to optimiser algorithms or public model APIs required.

## Testing Strategy

- Local: `make testOptimisable && ./testOptimisable` (and `make gp` smoke unchanged).
- CI: Compile builds the binary; Reference (or Compile) runs it on both OSes.
- Manually confirm Codecov / lcov lists hits in `COptimisable.cpp` for the new paths (SCG + L-BFGS at minimum).
