# CIP-0011: Drive near-complete line coverage of `CGp.cpp`

> CIPs describe HOW to achieve requirements (WHAT). This CIP strengthens [REQ-0002](../requirements/req0002_runnable-verification.md) for the central GP model translation unit, building on the Codecov pipeline from [CIP-0004](cip0004.md).

## Summary

Make `CGp.cpp` a first-class coverage target: measure which lines the matio / diagnostic suite still misses, then add focused drivers (and trim unreachable stubs where appropriate) until **executable** lines in that file are covered under the existing `COVERAGE=1` + Codecov workflow — with an explicit policy for `NotImplementedError` branches and `_NDLMATLAB`-only code.

**Which requirements does this CIP address?** REQ-0002 (runnable verification). It does not change GP mathematics; it makes gaps in the shared model surface visible and closable, the same role [CIP-0010](cip0010.md) played for `COptimisable.cpp`.

## Motivation

`CGp` is the hub for FTC / DTC / DTCVAR / FITC / PITC, inducing-point I/O, likelihood / gradients, prediction, and stream round-trips. Recent CIPs ([0009](cip0009.md) caches, [000E](cip000E.md) StableFactor, [000F](cip000F.md) PITC) all touch this file. Project Codecov can look healthy while large arms of `CGp.cpp` remain cold — especially GP-LVM `optimiseX`, non-spherical throws, prediction helpers, and MATLAB bridges.

Without a file-level gate:

- Regressions in rarely exercised switches land without a red CI signal.
- `NotImplementedError` tails and empty stubs inflate “missed” coverage and hide real gaps ([CIP-000B](cip000B.md)).
- Authors of sparse / cache / factorisation work cannot tell whether their new lines are in the measured set.

## Detailed Description

### Definition of “full coverage”

For this CIP, **full coverage of `CGp.cpp` means**:

1. **Line coverage** of every statement that can run in the default Ubuntu Coverage build (`USE_MATIO=1`, no `_NDLMATLAB` unless we deliberately enable it).
2. **Throw-site coverage** for intentional `NotImplementedError` / `Error` branches that we keep (call them and assert the throw) — they count as covered once executed.
3. **Out of scope for 100%** unless a follow-on CIP says otherwise:
   - Bodies behind `#ifdef _NDLMATLAB` / mex-only constructors when the Coverage job does not define those macros.
   - Code deleted under [CIP-000B](cip000B.md) as unreachable after a throw.

Branch coverage is a stretch goal; the hard gate is **lcov line rate for `CGp.cpp` ≥ a documented threshold** (propose **95%** initially, then **98%** once throw stubs are either covered or removed).

### Current surface (inventory sketch, 2026-11-15)

Already exercised in practice by `testGp` / diagnostics (after CIP-000E/000F):

- Spherical FTC, DTC, DTCVAR, FITC, PITC likelihood and gradient paths via matio fixtures.
- Cache invalidation / `ensure*` ([CIP-0009](cip0009.md)).
- StableFactor dual-path on DTC/DTCVAR (`diagDtcvar`, [CIP-000E](cip000E.md)).
- Stream read/write round-trip in `testGp`.

Likely cold or thinly hit (confirm with lcov in step 1):

| Area | Notes |
|------|--------|
| `optimiseX` / latent-X gradient assembly | GP-LVM-style path inside `CGp`; may need a tiny synthetic driver |
| `posteriorMean` / `posteriorMeanVar` / `_posteriorVar` sparse arms | Prediction not asserted in matio `testGp` today |
| `out` / `outGradParams` / `outGradX` | MapModel API; grads throw `NotImplementedError` |
| Non-spherical `else` branches | Throw only — cover with expect-throw or delete per 000B |
| Back-constraint branches | Throw only |
| `pointLogLikelihood` | Empty body |
| `optimise()` wrapper | May only run via CLI `gp`, not `testGp` |
| Output-scale learning gradient terms | Needs `setOutputScaleLearnt(true)` scenario |
| Inducing-not-fixed (`!isInducingFixed`) `gX_u` path | Fixture often fixes inducing |
| `_NDLMATLAB` ctor / `fromMxArray` | Not in default Coverage flags |

### Approach

1. **Baseline** — On Coverage CI (or locally): `COVERAGE=1` build, `run-matio-tests` plus `diagDtcvar` / `diagPitc` / `testOptimisable` as needed; produce `lcov` filtered to `CGp.cpp` and check the miss list into this CIP (appendix update) or `cip/cip0011/`.
2. **Policy** — For each miss: **cover**, **expect-throw**, or **delete** (link 000B). Record the decision in the appendix so Codecov misses are intentional.
3. **Drivers** — Prefer extending `testGp` / small `diag*` / a dedicated `testCGp` fail-count binary (CIP-0010 style) over heavy new `.mat` fixtures. Synthetic N≈10 models are enough for prediction, `optimiseX`, scale-learning, and throw tests.
4. **Gate** — Add a Coverage-workflow step (or script) that fails if `CGp.cpp` line rate &lt; threshold. Keep project Codecov thresholds unchanged; this is a **file-specific** assert.
5. **Docs** — Note the threshold and how to regenerate the miss list in [docs/build-and-ci.md](../docs/build-and-ci.md).

### Non-goals

- Implementing non-spherical or back-constrained GPs in this CIP (unless a one-line throw test is all that is needed).
- 100% of `_NDLMATLAB` without enabling that define in CI.
- GPLVM file coverage (`CGplvm.cpp`) — separate CIP if desired.
- Raising global Codecov project target beyond current auto/threshold settings.

### Alternatives considered

- **Only rely on Codecov patch** — Rejected; patch can stay green while `CGp.cpp` overall remains holey.
- **Require 100% including MATLAB ifdef** — Rejected for this CIP; too coupled to bridge retirement ([REQ-0003](../requirements/req0003_matlab-bridge-retirement.md)).

## Implementation Plan

1. Capture baseline `lcov` for `CGp.cpp` on `main` (post–000E/000F merges); paste miss summary into Appendix A.
2. Classify each miss: cover / expect-throw / delete (000B).
3. Implement drivers (`testCGp` and/or `testGp` extensions; wire into `matio-tests` / Coverage run list as appropriate).
4. Add CI assert on `CGp.cpp` line rate; document threshold.
5. Close when Coverage job enforces the threshold and Appendix A shows no unexplained misses.

## Backward Compatibility

- Additive tests and CI asserts only.
- Optional dead-code deletion coordinated with CIP-000B (behaviour unchanged for supported paths).

## Testing Strategy

- Local: `make USE_MATIO=1 COVERAGE=1 matio-tests && make run-matio-tests` then lcov extract for `CGp.cpp`.
- CI: Coverage workflow green; new file-rate check red if `CGp.cpp` drops below threshold.
- Manual: open Codecov file view for `CGp.cpp` on the implementing PR.
