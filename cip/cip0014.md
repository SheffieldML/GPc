# CIP-0014: GPy-like path façade for parameter get/set and constraints

> CIPs describe HOW to achieve requirements (WHAT). This CIP implements [REQ-0008](../requirements/req0008_gpy-like-parameter-access.md). It unblocks the deferred “fixing parameters” note in [CIP-000D](./cip000D.md) once Phase B lands.

**Naming decision (2026-11-16):** façade paths and leaf names match GPy/`paramz` as closely as sensible. Internal `setParamName` strings and storage may stay GPc-native; the path layer is the compatibility surface.

## Summary

Add a thin, GPy-inspired **path string façade** over the existing indexed parameter and transform machinery. Callers write `kern.setByPath("rbf.lengthscale", 0.2)` (GPy name and units) instead of `setParam(1/ℓ², 0)`. Constraints become runtime `constrainPositive("rbf.variance")` rather than constructor-only `addTransform`. Indexed APIs stay authoritative; the façade never sits in the SCG inner loop.

Delivery is phased: **A** path get/set + runtime constrain; **B** per-parameter fix masks on `CGp` (and siblings as needed); **C** optional model-level paths and CLI. Regex, tied params, and a full `Parameterized` tree stay out of scope.

## Motivation

Today every demo and CLI maps human meaning to magic indices:

```cpp
kernels[i]->setParam(rbfInvWidths[i], 0);
kernels[i]->setParam(variances[i], 1);
```

Compound kernels concatenate type and name without a separator (`rbfinverseWidth`), so even the labels are hard to reuse. GPy users set `m.kern.rbf.variance` and call `constrain_positive()` / `fix()`. We already have the numerical pieces (`CTransform`, `getTransParam` / `setTransParam`, flat `getOptParams`). What is missing is a stable naming and mutation layer at the model boundary.

## Detailed Description

### Design principles

1. **Indexed storage remains source of truth.** Paths resolve to indices; all values still go through `setParam` / `getParam` (natural space) or transform replacement on `CTransformable`.
2. **Façade stays outside the hot path.** Path maps are built once (or on structure change); optimisation continues to use integer vectors.
3. **Fail loudly.** Unknown path, ambiguous match, or arity mismatch → `Error` / `BOUNDCHECK`, never a default.
4. **GPy alignment of names and units, not of the object graph.** Canonical paths match GPy/`paramz`; no Python-style `__setattr__` tree.

### Path grammar (GPy-shaped)

| Form | Meaning | Example |
|------|---------|---------|
| `leaf` | Leaf on a single-component object | `variance` on white/bias |
| `component.leaf` | Child of compound/tensor by **GPy component name** | `rbf.lengthscale` |
| `component_N.leaf` | Duplicates: first keeps bare name; second is `_1`, then `_2`, … (paramz style) | `rbf.variance`, `rbf_1.variance` |
| ARD vector leaves | Only where conversion is defined; see mapping table | not `inputScale` → fake `lengthscale_i` |

**Canonical names are GPy’s.** Paths accept GPy spellings first. Legacy GPc leaf strings (`inverseWidth`, `lengthScale`, `weightVariance`, …) remain **aliases**. `paramPaths()` returns GPy canonical forms only.

**Compound display names.** `CCmpndKern::getParamName` / tensor equivalents become dotted GPy-style paths. Stream values stay positional.

**Component name aliases** (path segment ↔ `getType()`):

| GPy / façade segment | GPc `getType()` |
|----------------------|-----------------|
| `rbf` | `rbf` |
| `white` | `white` |
| `bias` | `bias` |
| `Exponential` or `exp` | `exp` |
| `Mat32` or `matern32` | `matern32` |
| `Mat52` or `matern52` | `matern52` |
| `RatQuad` or `ratquad` | `ratquad` |
| `mlp` | `mlp` |
| `linear` or `lin` | `lin` |
| `std_periodic` or `stdperiodic` | `stdperiodic` (confirm stream type at implement time) |
| `Cosine` or `cosine` | `cosine` |
| `Brownian` or `brownian` | `brownian` |
| `coregionalize` | `coregionalize` (CIP-000D) |

Accept both GPy’s default `name=` and GPc’s type string. Emit GPy’s default in `paramPaths()` where they differ (`Mat32`, `Exponential`, `std_periodic`).

No required `sum.` / `cmpnd.` prefix when the object *is* the compound (matches `k['rbf.variance']` on a GPy `Add`). Optional `sum.` alias for cmpnd is fine for users copying GP printouts.

**Model-level paths (Phase C, optional in first merge).** On `CGp`:

| Path | Maps to |
|------|---------|
| `kern.…` | Delegate to `pkern` with the suffix |
| `beta` | Sparse approximation noise precision (natural space) until a noise façade exists |
| `scale.j` | Output scale \(j\) when scales are learnt |

Inducing inputs and latent `X` stay out of the string API initially.

### Leaf mapping and value conversions

Façade get/set uses **GPy natural values**. Where GPc stores a different parameterisation, convert at the boundary; indexed `setParam` remains in GPc native units.

| Kernel | GPy leaf (canonical) | GPc storage | Conversion on setByPath / getByPath |
|--------|----------------------|-------------|-------------------------------------|
| RBF (iso) | `variance` | `variance` | identity |
| RBF (iso) | `lengthscale` | `inverseWidth` | \(\ell = 1/\sqrt{w}\), \(w = 1/\ell^2\) (same quantity as GPy `inv_lengthscale`) |
| RBF (iso) | `inv_lengthscale` | `inverseWidth` | identity |
| Exp | `variance` | `variance` | identity |
| Exp | `lengthscale` | `inverseWidth` | \(\ell = 1/w\), \(w = 1/\ell\) |
| Matérn 3/2, 5/2, Cosine, StdPeriodic | `lengthscale` | `lengthScale` | identity (spelling only) |
| StdPeriodic | `period` | `period` | identity |
| RatQuad | `lengthscale` | `lengthScale` | identity |
| RatQuad | `power` | `alpha` | name-aligned; document that GPy vs GPc RQ forms are not always bit-identical for the same numbers |
| MLP | `weight_variance`, `bias_variance`, `variance` | `weightVariance`, `biasVariance`, `variance` | identity |
| Linear | `variances` / `variances_i` | `variance` / ARD | map as exposed |
| White, Bias, Brownian | `variance` | `variance` | identity |
| Coregionalize | `W`, `kappa` | CIP-000D layout | identity; `W` in GPy link order |

**RBF ARD:** GPc’s shared `inverseWidth` + `inputScale_i` is not GPy’s per-dimension `lengthscale` vector. Phase A maps shared width like iso RBF; keeps `inputScale_i` under that name. Do not silently treat `lengthscale_i` as `inputScale_i`.

### Value space

- `getByPath` / `setByPath` → natural space **after** the conversion table (GPy units)
- `getTransByPath` / `setTransByPath` → optimiser space on the **stored** GPc parameter (`lengthscale` has no separate unconstrained coordinate — transform applies to `inverseWidth`)

### Runtime constraints

Expose on `CTransformable` (or a small helper used by kernels/noise):

```text
replaceTransform(index, CTransform*)   // remove existing transform at index if any, then add
clearTransform(index)                  // leave parameter unconstrained
```

Façade wrappers:

```text
constrainPositive(path)   // CTransform::defaultPositive()
constrainZeroOne(path)    // CTransform::defaultZeroOne()
constrainNone(path)       // clearTransform
```

Bounded constraints beyond sigmoid/linear are **not** required for Phase A; document as follow-up if GPy `constrain_bounded` is needed.

`CCmpndKern::addKern` already re-offsets child transforms. Runtime replace must operate on the **compound’s** flat index (after path resolution), not only on the child, so optimiser-facing transforms stay consistent. Prefer: resolve path → flat index on the object that owns `transArray` for optimisation. For compounds that flatten transforms into the parent, mutate the parent; keep children in sync if they retain their own copies (audit `addKern` ownership in implementation).

### Phase B: fix / unfix

GPy `param.fix()` drops the parameter from the optimiser vector while keeping the stored value.

Add a `vector<bool> fixed` (or bit mask) sized to `getOptNumParams()` **or**, cleaner, a mask over each *logical* block:

- Kernel: mask of length `pkern->getNumParams()`
- Beta / scales: one flag each (or per scale)
- Inducing / X: keep existing coarse `isInducingFixed()` / `isOptimiseX()` for now

`CGp::getOptNumParams` / `getOptParams` / `setOptParams` / `computeObjectiveGradParams` gather/scatter only unfixed entries. Allocate the mask once; do not rebuild per SCG step.

Verification: `checkGradients` with one kernel parameter fixed must match FD on the reduced vector; fixing none must match today’s behaviour exactly.

Stream persistence of the fix mask and of non-default transforms needs a **stream version bump** when saved; old files load with “all free” and constructor transforms.

### API sketch (Phase A)

On `CKern` (concrete helpers; compound overrides path walk if needed):

```cpp
unsigned int paramIndex(const std::string& path) const; // throws if missing/ambiguous
double getByPath(const std::string& path) const;
void setByPath(const std::string& path, double val);
void constrainPositive(const std::string& path);
void constrainZeroOne(const std::string& path);
void constrainNone(const std::string& path);
std::vector<std::string> paramPaths() const; // canonical list for docs/tests
```

Same pattern on `CNoise` where `getParamName` exists or can be added.

Illustrative call site (vs today):

```cpp
// before (GPc native index + inverseWidth)
kern->setParam(invWidth, 0);
kern->setParam(variance, 1);

// after (GPy names and lengthscale units)
kern->setByPath("lengthscale", lengthscale);  // stores inverseWidth = 1/ℓ²
kern->setByPath("variance", variance);
// compound:
cmpnd->setByPath("rbf.lengthscale", lengthscale);
cmpnd->setByPath("rbf.variance", variance);
cmpnd->setByPath("white.variance", 1e-6);
cmpnd->constrainPositive("rbf.lengthscale");
// legacy alias still works:
cmpnd->setByPath("rbf.inverseWidth", invWidth);
```

### Alternatives considered

| Alternative | Why not (for now) |
|-------------|-------------------|
| Full GPy `Parameterized` tree with child objects | Heavy; fights C++ ownership; tax in every API |
| Regex `['.*variance']` | Nice later; needs unambiguous multi-match semantics |
| Rename storage / `setParamName` to GPy strings globally | Breaks stream field expectations and every index-based caller’s comments; façade is enough |
| Pretend RBF-ARD `inputScale_i` is `lengthscale_i` | Different maths; would mislead ports from GPy |
| Only document index tables | Does not help compound kernels or CIP-000D fixing |

### Tenet trade-offs

- **Flexibility vs performance:** path resolution and unit conversion never in SCG; only at setup and I/O.
- **Compose through interfaces:** façade methods on existing contracts; no parallel GP class.
- **Assert and verify:** path errors are hard failures; conversion helpers covered by round-trip tests; Phase B requires `checkGradients`.
- **Ecosystem interoperability:** canonical paths match GPy; legacy GPc names stay as aliases.

## Implementation Plan

1. **Path helpers (Phase A)**
   - Per-kernel **name map**: GPy canonical leaf ↔ index (+ optional unit conversion)
   - Legacy GPc leaf aliases
   - Compound/tensor: GPy component names, `_1` / `_2` duplicates; fix `getParamName` to dotted GPy paths
   - `paramPaths()` / `paramIndex()` / `getByPath` / `setByPath`
   - Unit tests: `lengthscale` ↔ `inverseWidth` round-trip on RBF; `rbf+white` paths; duplicate `rbf` / `rbf_1`; alias `inverseWidth` still resolves

2. **Transform replace (Phase A)**
   - `replaceTransform` / `clearTransform` on `CTransformable`
   - `constrainPositive` / `constrainZeroOne` / `constrainNone` by **GPy** path
   - Test: change transform, check `getTransParam`/`gradfact` behaviour; `checkGradients` on a small `CGp`

3. **Fix mask (Phase B)**
   - Kernel (and beta/scale) masks on `CGp`
   - Gather/scatter in opt param methods + gradient
   - `checkGradients` with fixed subset; CIP-000D note becomes actionable for `Private`-style patterns

4. **Polish (Phase C, can defer)**
   - `CGp` paths `kern.*`, `beta`, `scale.*`
   - Optional CLI `--set rbf.variance=1.0`
   - Stream version for masks / non-default transforms

5. **Docs**
   - Short path table in CIP closure / README compression; demos prefer paths over raw indices where touched

## Backward Compatibility

- Indexed `setParam` / streams / matio fixtures unchanged in layout
- Display names for compound params gain `.` (and possibly `_k`); treat as acceptable break for a label-only string
- Default transforms at construction unchanged until the user calls `constrain*`
- Fix masks default to all free → identical optimiser vectors

## Testing Strategy

- **Unit:** `paramPaths()` matches GPy-style names for a hand-built `rbf+white` (and duplicate rbf); ambiguous path throws
- **Conversion:** RBF `setByPath("lengthscale", ℓ)` then `getParam(0)` equals \(1/\ell^2\); inverse getByPath recovers \(\ell\)
- **Aliases:** `inverseWidth` and `lengthScale` still resolve where applicable
- **Transform:** replace positive ↔ none; `checkGradients` still passes
- **Phase B:** fixed param omitted from opt vector; FD on reduced space
- **Regression:** matio `testKern` / `testGp` unchanged (indexed storage)
- **Optional:** dump `parameter_names()` from local GPy for the same kernel combo as a golden string list in `matfiles/` or `tests/`
