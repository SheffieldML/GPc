# CIP-0015: Native GPy-tutorial parity via C++ demos and markdown

> CIPs describe HOW to achieve requirements (WHAT). This CIP implements [REQ-0009](../requirements/req0009_gpy-tutorial-parity-native.md). It consumes kernel, coregionalization, sparse, and parameter work from [CIP-000C](./cip000C.md), [CIP-000D](./cip000D.md), [CIP-000E](./cip000E.md), and [CIP-0014](./cip0014.md), and closes the end-to-end demo gap still open on [REQ-0006](../requirements/req0006_multioutput-covariance.md).

## Summary

Make the **easy and close** GPy tutorial workflows recreatable in GPc without Python: multi-output data helpers, a thin coregionalized GP factory, short compiled demos under `examples/`, and markdown tutorials that drive demos/CLI and gnuplot.

**Sharing environment (locked 2026-11-16):** native first — C++ demos + markdown/CLI. GPy notebooks are the **spec/checklist** only. Python bindings and Jupyter/Colab are a **separate future CIP**, not a phase of this one.

**Which requirements?** Primary: [REQ-0009](../requirements/req0009_gpy-tutorial-parity-native.md). Also advances remaining acceptance on [REQ-0006](../requirements/req0006_multioutput-covariance.md) (end-to-end multi-output path) and showcases [REQ-0005](../requirements/req0005_gpy-aligned-kernel-coverage.md) / [REQ-0008](../requirements/req0008_gpy-like-parameter-access.md).

## Motivation

GPc already has much of the modelling surface GPy tutorials need:

| Capability | Where |
|---|---|
| Stationary / periodic / Brownian kernels | CIP-000C / REQ-0005 |
| ICM / LCM / `indexwhite` | CIP-000D / REQ-0006 (`createIcmKern`, `createLcmKern`) |
| Path get/set, constrain, fix | CIP-0014 / REQ-0008 |
| Sparse VarDTC-style path | CIP-000E (`CGp::DTCVAR`) |
| CLI + gnuplot tutorials | [README.md](../README.md), `examples/*.svml` |

What is missing is the **glue and the share format**: GPy’s `build_XY` / slices, a one-shot “coregionalized regression” assembly, demos that call the API the way tutorials read, and markdown that maps notebook → C++. Without that, coregionalization stays test-only and GPy migrants cannot port `basic_gp` or `coregionalization_toy` in an afternoon.

Notebooks are the wrong lead format for GPc: the authoring language is not the execution language, Cling/Colab stories are fragile with LAPACK/Fortran, and putting a Python façade in the hot path conflicts with Flexibility Without a Performance Tax. Native demos keep interoperability at the boundary.

## Detailed Description

### Sharing environment

```
GPy notebooks ──checklist──► helpers + factories ──► examples/*.cpp
                                      │
                                      └──► docs/tutorials/*.md + CLI + gnuplot
```

| Deliverable | Role |
|---|---|
| C++ helpers / factory | Match GPy `util.multioutput` + thin `GPCoregionalizedRegression` assembly |
| `examples/` demos | Runnable API truth; linked from makefile |
| Markdown tutorials | Narrative parallel to named GPy notebooks; shell recipes; plot stubs |
| CLI polish | Only where it unblocks demos (kernel `-k` strings already in the factory) |

**Rejected for this CIP:** xeus-cling notebooks; pybind11 + Colab; rewriting README into a second design doc outside VibeSafe (tutorials may live under `docs/` as compression of this CIP after close).

### In-scope GPy surface (first delivery)

| GPy reference | GPc target |
|---|---|
| `basic_gp` / `toy_rbf_1d` / olympics-style regression | Demo + markdown: `CGp` FTC + Gaussian + RBF/compound; optional `./gp learn` |
| `basic_kernels` (composition) | Demo: cmpnd/tensor + CIP-000C types + `setByPath` |
| `models_basic` (constrain / fix) | Same demos using CIP-0014 paths |
| `sparse_gp_regression` / `sparse_GP_regression_1D` | Demo: `DTCVAR` + inducing; **not** FITC CLI |
| `coregionalized_regression_tutorial` / `coregionalization_toy` / `multiple outputs` (ICM/LCM) | `build_XY` + factory + demo + markdown; layout per [docs/coregionalize.md](../docs/coregionalize.md) |
| Classification tutorials | **Document IVM** (`./ivm` + probit/ncnm) as the substitute; no EP/Laplace in `CGp` here |
| `gplvm_oil_100` | Point at existing `./gplvm` README path; optional thin markdown cross-link only |

### Out of scope (future CIPs)

EP/Laplace classification in `CGp`; Poisson, Student-t, heteroscedastic, warped GP; mean functions; uncertain inputs; derivative multi-output; Bayesian GPLVM / MRD / SSGPLVM; SVI/SVGP; HMC; integral kernels; state-space; Python bindings / Jupyter share format; FITC resurrection as a tutorial default; GPy `Private` as a separate class (use fix masks from CIP-0014 when needed).

### Helper layer (GPy `util.multioutput` parity)

Place helpers next to the existing ICM/LCM factories in [`CKern.h`](../CKern.h) / [`CKern.cpp`](../CKern.cpp) (or a small dedicated header if linkage clarity demands it — prefer keeping them with coregionalize to avoid a second ownership story).

| GPy | GPc (this CIP) |
|---|---|
| `build_XY(X_list, Y_list)` | Stack blocks; append output index as last column of `X`; stack `y`; same cast rules as CIP-000D |
| `get_slices` / `index_to_slices` | Row-range helpers for plotting/predict by output |
| `ICM` / `LCM` | Already `createIcmKern` / `createLcmKern` |
| `MixedNoise` marginal | Already `CIndexWhiteKern` outside the tensor |
| `GPCoregionalizedRegression(...)` | Thin factory: build design → ICM or LCM → `+ indexwhite` → `CGp` + `CGaussianNoise` on stacked `y` (spherical Gaussian path). No new approximation type. |

`prepare_Xnew` / prediction metadata: document that test points carry the index column; add a small helper to stamp `output_index` onto `X*` if that removes demo boilerplate. Full GPy `Y_metadata` plotting stack is not required while gnuplot drives visuals.

**Ownership:** factories that return `CKern*` / `CGp*` document who owns what (match `createIcmKern` clone semantics). Demos use clear delete/RAII consistent with surrounding code (CIP-000A unique_ptr may apply later; do not block this CIP on it).

### Demo programs

Under `examples/` (source) with makefile targets, e.g.:

1. `demo_regression_1d` — FTC GP, RBF (+ optional white), path init, optimise, write prediction table for gnuplot
2. `demo_sparse_dtcvar` — DTCVAR, fixed or free inducing, path/`fix` where useful
3. `demo_coregionalization_toy` — two outputs, `build_XY`, ICM + `indexwhite`, train, per-output predict slices
4. `demo_compound_paths` — cmpnd kernels, `paramPaths` / `setByPath` / `constrainPositive`

Demos may read `.svml` or synthesise toy data in-process (coreg toy mirrors GPy’s sinusoids). Prefer synthesised data for coreg so the demo is self-contained; keep SVM-light for CLI parity with README.

### Markdown tutorials

Add focused pages under `docs/` (e.g. `docs/tutorials/`) — not a parallel architecture doc during design; these **are** the implementation of the share format once the CIP is accepted. Each page:

- Names the GPy notebook / example it parallels
- Lists build/run commands
- Shows expected plot generation (gnuplot stubs or `gp gnuplot`)
- Links API helpers (`build_XY`, paths) rather than re-deriving CIP-000D maths

A single checklist table (in the CIP until compression, then in `docs/tutorials/README.md`) maps GPy → GPc.

### CLI polish (narrow)

Extend `gp learn -k` (and help text) for stream types demos need that are already implemented (`matern32`, `matern52`, `stdperiodic`, …) where missing. Do **not** enable FITC in the tutorial path while it `exitError`s. Coregionalized demos prefer the C++ factory over forcing multi-output through the current single-output CLI.

### Phasing

| Phase | Content | Depends on |
|---|---|---|
| **A — Helpers** | `build_XY`, slices, coregionalized `CGp` factory; unit tests | CIP-000D types present |
| **B — Demos** | Four demos + makefile targets; smoke run in CI or documented manual gate | Phase A; CIP-0014 paths |
| **C — Markdown** | Tutorial pages + GPy checklist; gnuplot recipes | Phase B |
| **D — CLI polish** | Extra `-k` types for demos; help strings | Phase B (can overlap C) |

Backlog tasks are created **only after** this CIP is Accepted (VibeSafe rule).

### Relation to open REQ-0006 criteria

CIP-000D implemented kernels and `testCoregionalize`. REQ-0006 still wants a documented end-to-end train/eval path. Phase A+B of this CIP are intended to satisfy that criterion without enlarging CIP-000D’s closed design.

## Implementation Plan

1. **Accept this CIP** after review of sharing environment and in-scope list; create backlog tasks for phases A–D.
2. **Phase A:** Implement `build_XY` + slice helpers + coregionalized factory; tests beside `testCoregionalize` (or extension thereof).
3. **Phase B:** Add demos and makefile targets; wire smoke runs.
4. **Phase C:** Write `docs/tutorials/` pages and the GPy↔GPc checklist.
5. **Phase D:** CLI `-k` / help updates for mature kernel types used by demos.
6. **Validate** against REQ-0009 acceptance criteria; close CIP; compress tutorial index into formal docs (`compressed: true`).

## Backward Compatibility

Additive only: new helpers, demos, docs, and CLI kernel aliases. No change to `.model` stream field names or existing matio fixtures. Old SVM-light tutorials keep working. Coregionalize index cast rules remain those of CIP-000D.

## Testing Strategy

- **Helpers:** unit tests for stacking shapes, index column values, slice boundaries; reject non-integer indices per CIP-000D.
- **Factory:** fixed-parameter log-likelihood or `K` compare against GPy (reuse / extend CIP-000D fixture style).
- **Demos:** compile in CI; optional short non-optimising smoke (or capped iterations) so CI stays fast.
- **Paths:** demos use `setByPath` / `fix` where relevant — covered by existing `testParamPaths` / `testCGp` plus demo smoke.
- **Docs:** checklist reviewed so every “in scope” GPy item has a demo or explicit IVM/gplvm pointer.
