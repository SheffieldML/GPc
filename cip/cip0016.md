# CIP-0016: Shared JSON/YAML model interchange with GPy and GPmat

> CIPs describe HOW to achieve requirements (WHAT). This CIP implements [REQ-000A](../requirements/req000A_shared-model-interchange.md). It consumes naming and unit policy from [CIP-0014](./cip0014.md), kernel/stream types from [CIP-000C](./cip000C.md) / [CIP-000D](./cip000D.md), and sparse approximation tags from [CIP-000E](./cip000E.md). It is **orthogonal** to [CIP-0015](./cip0015.md) (tutorial parity): that CIP’s “share format” is demos/docs, not model files.

## Summary

Stand up a **shared SheffieldML schema home** first, then implement adapters so GPc, GPy, and later GPmat exchange a documented model subset via a **versioned, inspectable interchange** (**YAML primary**; JSON as the isomorphic encoding). GPc keeps `.model` streams as the native C++ format; the shared format is an adapter at the boundary.

**Which requirements?** Primary: [REQ-000A](../requirements/req000A_shared-model-interchange.md). Also advances durable non-MATLAB artefacts useful to [REQ-0003](../requirements/req0003_matlab-bridge-retirement.md), and exercises [REQ-0005](../requirements/req0005_gpy-aligned-kernel-coverage.md) / [REQ-0008](../requirements/req0008_gpy-like-parameter-access.md).

## Motivation

Today the three toolboxes do not share model files:

| Toolbox | Persistence | Problem for exchange |
|---|---|---|
| GPc | Versioned text `.model` (`CStreamInterface`) | GPc-native field names (`inverseWidth`); positional compounds |
| GPy | `to_dict` → JSON / gzip; or `param_array` + script | Python `class` paths; natural units |
| GPmat | `gpWriteResult` / `gpDeconstruct` → `.mat` | MATLAB structs; not text-portable |

CIP-0014 already fixed the **semantic** bridge (GPy path names and units at the API). Without a shared **file** schema, users still hand-translate. Ecosystem Interoperability asks for formats the community already uses; GPy’s JSON is the only portable, inspectable candidate among the three. Assert Invariants needs golden round-trips. Flexibility Without a Performance Tax forbids putting parsers in SCG.

## Detailed Description

### Design decisions (locked 2026-11-16)

1. **Shared SheffieldML home first.** Schema, type registry, and golden fixtures live in a dedicated org repo (working name: **`SheffieldML/gp-scuderia`**), not under GPc `docs/`. GPc/GPy/GPmat consume that repo (submodule, pin, or release tarball). GPc implementation phases wait on a usable 0.1 schema there.
2. **YAML is primary; JSON is isomorphic.** One abstract tree; two encodings. No YAML-only or JSON-only semantic fields. Authoring, goldens, and human review prefer `.yaml`; tools may emit `.json` for stacks that prefer it. GPc may parse YAML directly or via a convert-at-boundary step — decide at Phase A without putting either parser in SCG.
3. **Portable type tags, inspired by GPy class strings.** Wire `type` values are language-neutral dotted paths derived from GPy’s `class` strings by stripping the `GPy.` prefix and lowercasing: e.g. `GPy.kern.RBF` → `kern.rbf`, `GPy.models.GPRegression` → `models.gp_regression`, `GPy.likelihoods.Gaussian` → `likelihoods.gaussian`. Compounds follow GPy’s additive/multiplicative layout with tags such as `kern.add` / `kern.prod` (names finalised in the registry). Full `GPy.*` class strings are **read aliases** only; writers emit portable tags. Registry file in `gp-scuderia` maps portable tag ↔ GPy class ↔ GPc stream type ↔ GPmat kern type.
4. **Natural units on the wire.** Wire parameters use GPy-natural values; GPc converts with the CIP-0014 table on import/export. Indexed/`setParam` storage stays GPc-native inside the process.
5. **`.model` unchanged.** No stream field renames in this CIP. Shared format is additive, not a replacement for `writeParamsToStream`.
6. **Own the subset, not the zoo.** First subset = FTC (and later sparse) Gaussian regression with the kernel catalogue GPc already shares with GPy tutorials. Full GPy zoo is out of scope.
7. **GPmat is a late phase / sibling work.** Adapter after schema + GPc↔GPy fixtures exist; implementation primarily in GPmat against `gp-scuderia`.

### Abstract tree (sketch; YAML authoring form)

```yaml
schema_version: "0.1"
type: models.gp_regression          # portable; GPy.models.GPRegression accepted on read
input_dim: 1
output_dim: 1
approximation: ftc                  # ftc | dtc | dtcvar | fitc | pitc
kernel:
  type: kern.add
  parts:
    - type: kern.rbf
      variance: 1.0
      lengthscale: 1.0
      ARD: false
    - type: kern.white
      variance: 0.1
likelihood:
  type: likelihoods.gaussian
  variance: 0.1
# X / Y optional; omit when caller supplies data
```

Kernel nodes carry `type`, natural-valued parameters, and children for compounds/tensors. Coregionalize uses CIP-000D layout (`W`, `kappa`, `outputDim`, `rank`) in natural/GPy link order. Sparse models add inducing inputs and beta as in GPy sparse dicts / GPc stream fields.

**Rejected alternatives:**
- Pickle / MATLAB-only `.mat` as the shared format (not inspectable cross-language).
- Keeping the schema only inside GPc (blocks GPy/GPmat ownership and review).
- Requiring live Python imports of `GPy.kern.RBF` as the wire type key (non-portable).
- Renaming `.model` fields to GPy strings (breaks existing files; CIP-0015 already froze stream names).
- Embedding YAML/JSON parsers in the SCG hot path.
- Requiring a live GPy install to *load* fixtures in GPc tests (fixtures are static files in `gp-scuderia`; GPy generation is a maintainer tool).

### Mapping to GPc

| Interchange | GPc |
|---|---|
| `type: models.gp_regression` | `CGp` (+ Gaussian `CNoise`) |
| `kernel` tree | Factory driven by portable tags via registry → existing stream type strings |
| natural params | CIP-0014 conversion into `setParam` / `setByPath` |
| `approximation` | `CGp::FTC` / `DTC` / `DTCVAR` / … |
| optional `X`,`Y` | caller-owned `CMatrix`; load path mirrors GPy `save_data` |

Export walks the live model and emits portable tags + natural units (not raw `.model` dumps).

### Mapping to GPy

| Interchange | GPy |
|---|---|
| Portable `type` (+ `GPy.*` alias on read) | Map through registry → `from_dict` class dispatch |
| Nested kernel + likelihood | Existing `_save_to_input_dict` / `_build_from_input_dict` |
| Natural params | Identity (already GPy units) |

Preferred path: registry + thin converter so GPy need not change before Phase C; optional later PR teaching GPy to emit portable tags natively.

### Mapping to GPmat (Phase D)

| Interchange | GPmat |
|---|---|
| Same YAML/JSON tree | MATLAB YAML/JSON tooling or a small MEX-free reader |
| Kernel type tags | Registry → `kernCreate` type cells |
| Params | Map through GPmat param vectors (inverse-width native — convert like GPc) |

Deliver as MATLAB functions in GPmat against `gp-scuderia`, not inside GPc C++.

### Phasing

| Phase | Deliverable | Depends |
|---|---|---|
| **0 — Shared home** | Create `SheffieldML/gp-scuderia`: README, `schema_version` 0.1, type registry, JSON Schema (validation), **YAML goldens** (FTC RBF±white±bias, with/without data), license | CIP-0014 closed ✓ |
| **A — GPc I/O** | GPc consumes pinned `gp-scuderia`; write/read subset; `.model` untouched | Phase 0 published |
| **B — Expand subset** | Compounds, sparse DTCVAR, coreg ICM toy (schema + GPc) | Phase A; CIP-000D/000E |
| **C — GPy round-trip** | GPy ↔ YAML fixtures via registry; optional CI when GPy available | Phase A (+ B as covered) |
| **D — GPmat** | MATLAB adapter + one demo in GPmat | Phase 0–A stable |

GPc YAML dependency policy (Phase A): prefer reading the primary `.yaml` goldens; avoid a heavy required dependency in the default build — header-only, optional linked lib, or convert-to-JSON at test/fixture ingest are all acceptable if load stays off the SCG path.

### Tenet balance

- **Ecosystem interoperability:** shared org schema; GPy-inspired portable tags; YAML/JSON; keep `.model` and SVM-light.
- **Compose through interfaces:** interchange adapters call `CKern` / `CNoise` / `CGp` factories; no parallel model core.
- **Assert and verify:** golden YAML fixtures in `gp-scuderia` + prediction/LL tolerances.
- **Flexibility without a performance tax:** parse once at load; never in SCG.
- **LAPACK owns linear algebra:** unchanged.

## Implementation Plan

1. **Accept locks** (done in draft): shared home first; YAML primary; portable tags from GPy class paths; natural units; `.model` frozen.
2. **Phase 0:** Create and publish `gp-scuderia` (local scaffold → GitHub when `gh` auth works); schema 0.1 + registry + YAML goldens.
3. **Phase A:** GPc adapter against pinned `gp-scuderia`; unit tests on those goldens.
4. **Phase B:** Sparse + coregionalize in schema and GPc; reject FITC if runtime still `exitError`s (document).
5. **Phase C:** GPy round-trip scripts; optional CI.
6. **Phase D:** GPmat adapter in GPmat repo.
7. **Compression (after Closed):** point GPc README at `gp-scuderia`; update ecosystem-interoperability examples.

## Backward Compatibility

Additive only. Old `.model` files load. No stream version bump required unless we later persist new flags (out of scope here). GPy/GPmat users opt in by using the shared files; existing pickle / `.mat` workflows unchanged.

## Testing Strategy

- Golden **YAML** fixtures in `gp-scuderia` (no MATLAB required); JSON twins optional for validators.
- GPc: load → `logLikelihood` / `posteriorMean` vs stored reference values; export → canonical YAML/JSON equality.
- Cross-toolbox: GPy-generated fixtures (Phase C); tolerances documented per quantity.
- Negative tests: unknown type, truncated param vector, dim mismatch → hard fail.
- Schema validation against the published JSON Schema for both encodings.
