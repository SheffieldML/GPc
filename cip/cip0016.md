# CIP-0016: Shared JSON/YAML model interchange across GP toolboxes

> CIPs describe HOW to achieve requirements (WHAT). This CIP implements [REQ-000A](../requirements/req000A_shared-model-interchange.md). It consumes naming and unit policy from [CIP-0014](./cip0014.md), kernel/stream types from [CIP-000C](./cip000C.md) / [CIP-000D](./cip000D.md), and sparse approximation tags from [CIP-000E](./cip000E.md). It is **orthogonal** to [CIP-0015](./cip0015.md) (tutorial parity): that CIP’s “share format” is demos/docs, not model files.

## Summary

Stand up a **shared SheffieldML schema home** first, then implement adapters so GPc, GPy, and later GPmat exchange a documented model subset via a **versioned, inspectable interchange** (**YAML primary**; JSON as the isomorphic encoding). GPc keeps `.model` streams as the native C++ format; the shared format is an adapter at the boundary.

**Which requirements?** Primary: [REQ-000A](../requirements/req000A_shared-model-interchange.md). Also advances durable non-MATLAB artefacts useful to [REQ-0003](../requirements/req0003_matlab-bridge-retirement.md), and exercises [REQ-0005](../requirements/req0005_gpy-aligned-kernel-coverage.md) / [REQ-0008](../requirements/req0008_gpy-like-parameter-access.md).

## Motivation

Today the three toolboxes do not share model files:

| Toolbox | Persistence | Problem for exchange |
|---|---|---|
| GPc | Versioned text `.model` (`CStreamInterface`) | GPc-native field names (`inverseWidth`); positional compounds |
| GPy | `to_dict` → JSON / gzip; or `param_array` + script | Python `class` paths; natural units |
| GPmat | `gpWriteResult` / `gpDeconstruct` → `.mat` | MATLAB structs; not text-portable |

CIP-0014 already fixed the **semantic** bridge (GPy path names and units at the API). Without a shared **file** schema, users still hand-translate. Ecosystem Interoperability asks for formats the community already uses; GPy’s JSON is the only portable, inspectable candidate among the three. Assert Invariants needs golden round-trips. Flexibility Without a Performance Tax forbids putting parsers in SCG.

## Detailed Description

### Design decisions (locked 2026-11-16)

1. **Shared SheffieldML home first.** Schema, type registry, and golden fixtures live in a dedicated org repo (working name: **`SheffieldML/gp-scuderia`**), not under GPc `docs/`. GPc/GPy/GPmat consume that repo (submodule, pin, or release tarball). GPc implementation phases wait on a usable 0.1 schema there.
2. **YAML is primary; JSON is isomorphic.** One abstract tree; two encodings. No YAML-only or JSON-only semantic fields. Authoring, goldens, and human review prefer `.yaml`; tools may emit `.json` for stacks that prefer it. GPc may parse YAML directly or via a convert-at-boundary step — decide at Phase A without putting either parser in SCG.
3. **Portable type tags, inspired by GPy class strings.** Wire `type` values are language-neutral dotted paths derived from GPy’s `class` strings by stripping the `GPy.` prefix and lowercasing: e.g. `GPy.kern.RBF` → `kern.rbf`, `GPy.models.GPRegression` → `models.gp_regression`, `GPy.likelihoods.Gaussian` → `likelihoods.gaussian`. Compounds follow GPy’s additive/multiplicative layout with tags such as `kern.add` / `kern.prod` (names finalised in the registry). Full `GPy.*` class strings are **read aliases** only; writers emit portable tags. Registry file in `gp-scuderia` maps portable tag ↔ GPy class ↔ GPc stream type ↔ GPmat kern type.
4. **Natural units on the wire.** Wire parameters use GPy-natural values; GPc converts with the CIP-0014 table on import/export. Indexed/`setParam` storage stays GPc-native inside the process.
5. **`.model` unchanged.** No stream field renames in this CIP. Shared format is additive, not a replacement for `writeParamsToStream`.
6. **Own the subset, not the zoo.** First subset = FTC (and later sparse) Gaussian regression with the kernel catalogue GPc already shares with GPy tutorials. Full GPy zoo is out of scope.
7. **GPmat is a late phase / sibling work.** Adapter after schema + GPc↔GPy fixtures exist; implementation primarily in GPmat against `gp-scuderia`.
8. **Framework-neutral registry (added 2026-11-25).** The wire tag is the contract; GPy is not normative. Portable tags keep GPy-derived names only because that vocabulary is widely recognised. The registry carries, for every tag, a native entry for each of GPy, GPc, GPmat, GPyTorch, GPflow and GPJax, with explicit `null` where a framework has no equivalent (adapters must fail loudly). Per-parameter transforms are recorded in the registry. Known mismatches: GPyTorch has no white kernel and no variance on `RBFKernel` (use `ScaleKernel`); GPJax parameterises Gaussian noise by standard deviation; GPflow stores softplus-transformed values; GPc stores inverse width and noise precision. Approximation support per framework is tabulated; unsupported tags raise. Class and parameter names for GPyTorch, GPflow and GPJax were read from upstream source on 2026-11-25 (`api_checked`); entries stay `verified: false` until a round-trip fixture exists.
9. **Strict schema (added 2026-11-25).** Unknown top-level fields are rejected; experimental fields use an `x-` prefix. Training data lives under `data: {X, Y}`. Non-FTC approximations require `inducing_inputs`; `sparse_linalg` applies only to sparse approximations.

### Abstract tree (sketch; YAML authoring form)

```yaml
schema_version: "0.1"
type: models.gp_regression          # portable; GPy.models.GPRegression accepted on read
input_dim: 1
output_dim: 1
approximation: ftc                  # ftc | dtc | dtcvar | fitc | pitc
# sparse_linalg: lq                 # sparse only; omit or lq | stable | legacy (default lq)
kernel:
  type: kern.add
  parts:
    - type: kern.rbf
      variance: 1.0
      lengthscale: 1.0
      ARD: false
    - type: kern.white
      variance: 0.1
likelihood:
  type: likelihoods.gaussian
  variance: 0.1
# X / Y optional; omit when caller supplies data
```

Kernel nodes carry `type`, natural-valued parameters, and children for compounds/tensors. Coregionalize uses CIP-000D layout (`W`, `kappa`, `outputDim`, `rank`) in natural/GPy link order. Sparse models add inducing inputs and beta as in GPy sparse dicts / GPc stream fields, plus the orthogonal `sparse_linalg` token (below).

### Approximation vs sparse linear algebra (shared with GPy)

Two orthogonal axes — do **not** encode LQ as a fourth approximation name:

| Axis | Wire field | Tokens | Meaning |
|---|---|---|---|
| Approximation (model / bound) | `approximation` | `ftc` \| `dtc` \| `dtcvar` \| `fitc` \| `pitc` | Which sparse GP |
| Inducing-side factor | `sparse_linalg` | **`lq` (default)** \| `stable` \| `legacy` | How \(C\) / \(A\) is factored |

- **`lq`**: whitened features + LQ of \([I,\sqrt{\beta}B]\) (Seeger BLR; CIP-001B). Shipped default in GPc.
- **`stable`**: whitened \(C=I+\beta BB^\top\) + Cholesky / Murray adjoints (CIP-0012). Matches GPy 1.x VarDTC/FITC arithmetic today.
- **`legacy`**: explicit \(A=K_{uf}K_{uf}^\top+\beta^{-1}K_{uu}\) + `pdinv` (pre-0012).

Read aliases (write canonical only): `stablefactor`/`chol` → `stable`; `gram` → `legacy`. Case-insensitive on read. FTC ignores `sparse_linalg` (omit, or reject non-default).

**GPc surfaces (already aligned):** CLI `--sparse-linalg`; C++ `setSparseLinalgMode`; Python `gpc.SparseGPRegression(..., sparse_linalg="lq")` and `.sparse_linalg` (read/write).

**GPy surfaces (to implement in GPy):** keep `inference_method` as the *approximation* (`VarDTC`, `FITC`, …). Add the orthogonal knob on those classes — do **not** invent `VarDTC_LQ` subclasses:

```python
m = GPy.models.SparseGPRegression(X, Y, Z=Z)  # inference_method = VarDTC()
m.inference_method.sparse_linalg = "lq"       # default once ported
# or: VarDTC(sparse_linalg="stable")
```

Interchange emits/reads the same `sparse_linalg` string. Bench artifacts record the column; REQ-0007 gates the **default `lq`** row.

**Rejected alternatives:**
- Pickle / MATLAB-only `.mat` as the shared format (not inspectable cross-language).
- Keeping the schema only inside GPc (blocks GPy/GPmat ownership and review).
- Requiring live Python imports of `GPy.kern.RBF` as the wire type key (non-portable).
- Renaming `.model` fields to GPy strings (breaks existing files; CIP-0015 already froze stream names).
- Embedding YAML/JSON parsers in the SCG hot path.
- Requiring a live GPy install to *load* fixtures in GPc tests (fixtures are static files in `gp-scuderia`; GPy generation is a maintainer tool).

### Mapping to GPc

| Interchange | GPc |
|---|---|
| `type: models.gp_regression` | `CGp` (+ Gaussian `CNoise`) |
| `kernel` tree | Factory driven by portable tags via registry → existing stream type strings |
| natural params | CIP-0014 conversion into `setParam` / `setByPath` |
| `approximation` | `CGp::FTC` / `DTC` / `DTCVAR` / … |
| `sparse_linalg` | `CGp::setSparseLinalgMode` (`lq` / `stable` / `legacy`) |
| optional `X`,`Y` | caller-owned `CMatrix`; load path mirrors GPy `save_data` |

Export walks the live model and emits portable tags + natural units (not raw `.model` dumps).

### Mapping to GPy

| Interchange | GPy |
|---|---|
| Portable `type` (+ `GPy.*` alias on read) | Map through registry → `from_dict` class dispatch |
| Nested kernel + likelihood | Existing `_save_to_input_dict` / `_build_from_input_dict` |
| Natural params | Identity (already GPy units) |
| `approximation` | Choice of `inference_method` class (`VarDTC` ↔ `dtcvar`, `FITC` ↔ `fitc`, …) |
| `sparse_linalg` | `inference_method.sparse_linalg` (new; default `lq` once LQ lands in GPy) |

Preferred path: registry + thin converter so GPy need not change before Phase C; optional later PR teaching GPy to emit portable tags natively. The `sparse_linalg` field is specified here so GPy can grow LQ without forking inference classes; GPc’s façade already speaks the same tokens.

### Mapping to GPmat (Phase D)

| Interchange | GPmat |
|---|---|
| Same YAML/JSON tree | MATLAB YAML/JSON tooling or a small MEX-free reader |
| Kernel type tags | Registry → `kernCreate` type cells |
| Params | Map through GPmat param vectors (inverse-width native — convert like GPc) |

Deliver as MATLAB functions in GPmat against `gp-scuderia`, not inside GPc C++.

### Phasing

| Phase | Deliverable | Depends |
|---|---|---|
| **0 — Shared home** | Create `SheffieldML/gp-scuderia`: README, `schema_version` 0.1, type registry, JSON Schema (validation), **YAML goldens** (FTC RBF±white±bias, with/without data), license | CIP-0014 closed ✓ |
| **A — GPc I/O** | GPc consumes pinned `gp-scuderia`; write/read subset; `.model` untouched | Phase 0 published |
| **B — Expand subset** | Compounds, sparse DTCVAR, coreg ICM toy (schema + GPc) | Phase A; CIP-000D/000E |
| **C — GPy round-trip** | GPy ↔ YAML fixtures via registry; optional CI when GPy available | Phase A (+ B as covered) |
| **D — GPmat** | MATLAB adapter + one demo in GPmat | Phase 0–A stable |
| **E — Python ML stacks** | Adapters for GPyTorch, GPflow, GPJax (in `gp-scuderia` or each project), verified against goldens; confirm registry entries and supported approximations | Phase C; schema tagged stable |

GPc YAML dependency policy (Phase A): prefer reading the primary `.yaml` goldens; avoid a heavy required dependency in the default build — header-only, optional linked lib, or convert-to-JSON at test/fixture ingest are all acceptable if load stays off the SCG path.

### Tenet balance

- **Ecosystem interoperability:** shared org schema; GPy-inspired portable tags; YAML/JSON; keep `.model` and SVM-light.
- **Compose through interfaces:** interchange adapters call `CKern` / `CNoise` / `CGp` factories; no parallel model core.
- **Assert and verify:** golden YAML fixtures in `gp-scuderia` + prediction/LL tolerances.
- **Flexibility without a performance tax:** parse once at load; never in SCG.
- **LAPACK owns linear algebra:** unchanged.

10. **C++ is the canonical GPc implementation.** Interchange must work without Python (`gp` CLI, clusters). The mapping logic lives once, in C++; the Python façade delegates once A1 passes conformance. Load and save stay off the SCG path. Vendored parser choice (nlohmann/json versus a minimal in-house reader) is settled in A1 against the dependency policy above.

## Implementation Plan

1. **Accept locks** (done in draft): shared home first; YAML primary; portable tags from GPy class paths; natural units; `.model` frozen.
2. **Phase 0:** Create and publish `gp-scuderia` (local scaffold → GitHub when `gh` auth works); schema 0.1 + registry + YAML goldens.
3. **Phase A:** GPc adapter against pinned `gp-scuderia`; unit tests on those goldens. Split (decision 10):
   - **A0 (done 2026-11-25):** Python adapter `gpc.interchange`, conformant on both goldens. Interim reference for the mapping rules.
   - **A1:** C++ reader/writer (`CInterchange`) as the canonical implementation: JSON twin via a vendored header-only parser (no new required dependency; YAML via optional yaml-cpp build flag or convert-at-boundary). Owns the unit mappings (ARD split, `1/beta`, white plus likelihood both adding, zero mean) and the refusal rules. A `testInterchange` binary loads the goldens and checks `x-reference` and negative fixtures.
   - **A2:** CLI: `gp learn --from model.json`, `gp export model.model model.json`, `gp import`. `.model` unchanged.
   - **A3:** Python binds A1 and `gpc.interchange` drops its own mapping logic; the A0 tests and `conformance.sh` then guard parity.
4. **Phase B:** Sparse + coregionalize in schema and GPc; reject FITC if runtime still `exitError`s (document).
5. **Phase C:** GPy round-trip scripts; optional CI.
6. **Phase D:** GPmat adapter in GPmat repo.
7. **Compression (after Closed):** point GPc README at `gp-scuderia`; update ecosystem-interoperability examples.

## Backward Compatibility

Additive only. Old `.model` files load. No stream version bump required unless we later persist new flags (out of scope here). GPy/GPmat users opt in by using the shared files; existing pickle / `.mat` workflows unchanged.

## Testing Strategy

- Golden **YAML** fixtures in `gp-scuderia` (no MATLAB required); JSON twins optional for validators.
- GPc: load → `logLikelihood` / `posteriorMean` vs stored reference values; export → canonical YAML/JSON equality.
- Cross-toolbox: GPy-generated fixtures (Phase C); tolerances documented per quantity.
- Negative tests: unknown type, truncated param vector, dim mismatch → hard fail.
- Schema validation against the published JSON Schema for both encodings.

### 2026-11-25 (adapters)
GPy, GPc and GPmat adapters landed together. GPy generates the `x-reference` block (log likelihood, predictive mean and variance) in each golden; GPc and GPmat reproduce it (`scripts/conformance.sh`, run from `gp-scuderia`). An independent numpy implementation of the exact marginal likelihood and the Titsias bound agrees with GPy to 4e-8, so the oracle is not just GPy agreeing with itself.

Findings that changed the specification or code:

- **Noise semantics.** The wire means K + white + sigma^2 I. GPy, GPmat, GPflow and GPJax all add both. GPc did not: under CIP-0027 a trainable White owned the Gram noise and `likelihood.variance` was ignored (log likelihood off by 0.28 on the FTC golden). Decision: GPc matches the wire. `allowWhiteAndLikelihoodNoise` now makes both add (previously it only suppressed the error), is exposed as `set_allow_white_and_noise`, and `gpc.interchange` turns it on for documents with `kern.white`. The CIP-0027 default is unchanged and covered by a test; flipping the default needs a CIP-0027 amendment.
- **ARD parameterisation.** GPc `rbfard` stores one `inverseWidth` and per-dimension `inputScale_j` in [0,1] with `1/l_j^2 = inverseWidth * inputScale_j`. The adapter writes the canonical split `inputScale_j = (min l / l_j)^2`; the round trip is exact. GPmat `rbfard2` stores `inputScales = 1/l^2`.
- **Mean.** The wire is zero mean. GPmat subtracts `mean(y)` (`model.bias`) by default, so its adapter sets bias to zero and scale to one.
- **Jitter.** GPmat adds 1e-6 to K_uu on sparse models without a white term; this moves the DTCVar bound by about 4e-5, hence the golden log-likelihood tolerance of 1e-4 (predictions agree to 1e-9).
- **GPmat complex log likelihood.** Under Octave the sparse bound has imaginary part k*pi (sign flips in a factor passed to `logdet`). The real part is correct; the adapter checks the imaginary part is k*pi and fails otherwise.

Not yet done: GPy `to_wire`, `kern.prod`, `matern52`, coregionalisation, YAML I/O in GPc and GPmat entry points, CI, publishing `gp-scuderia`.

### 2026-11-26 (A2)
Added `gp learn --from model.json [-o out.json] [-m out.model] [-# iters]`, `gp import in.json model_file [data_file]` and `gp export example_file model_file out.json`. A `.model` stream holds no data, so import writes a companion CSV (default `model_file.csv`) and export reads data from a CSV. Export refuses models the wire format cannot carry: centred or scaled targets (use `-C 0 -S 0`), `white` kernels in exact GPs (`.model` does not store the allow-white flag), PITC, multi-output, non-Gaussian likelihoods and unsupported kernels. Each export is verified by rebuilding the document and comparing log likelihoods. Import then export reproduces the dtcvar golden exactly.
Found and fixed a pre-existing bug: `CMatrix::readParamsFromStream` read tokens without a `.` with `atoi`, so hex floats such as `0x1p-1` (0.5) loaded as 0, silently corrupting saved models (for example a bias variance of 0.5). It now uses `strtod`; `testInterchange` has a regression test. Note: `learn --from` on an FTC+White document trains White and the likelihood variance together, which are unidentifiable. Remaining: A3.

### 2026-11-26 (A3)
`gpc.interchange` now delegates to C++: new `_gpc.InterchangeModel` (`python/src/wrap_interchange.*`) wraps `CInterchange` and takes the document as JSON. `from_wire`, `to_wire` and `reference` keep their signatures; the Python mapping code (ARD split, noise opt-in, refusals) is deleted. `to_wire` ignores its template argument, since the C++ model keeps the source document. `gp-scuderia/scripts/conformance.sh` now also runs `conformance_gpc_cli.sh` (import/export round trip and refusals). All three toolboxes' conformance, `testInterchange` and the existing interchange/regression pytest files pass. Phase A is complete.

### 2026-11-26: allow-white flag in the `.model` stream

`CGp::writeParamsToStream` now writes an optional trailing `allowWhiteAndLikelihoodNoise=true` key when the CIP-0027 opt-in is set; `readParamsFromStream` reads it if present (absent means false, so older streams load unchanged, and default models write byte-identical streams). Exact GPs with `kern.white` therefore round trip through `.model`, `gp import` and `gp export`. A White kernel without the flag, and sparse models with White, are still refused on export: their noise semantics differ from the wire's additive rule. This is an additive stream change, not a change to the CIP-0027 default.
