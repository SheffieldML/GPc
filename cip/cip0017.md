# CIP-0017: Psi statistics and Bayesian GP-LVM (GPy-parity subset)

> CIPs describe HOW to achieve requirements (WHAT). This CIP implements [REQ-000B](../requirements/req000B_bayesian-gplvm-psi.md).

## Summary

Add GPy-style **psi statistics** on the `CKern` contract and a **Bayesian GP-LVM** model class that trains a diagonal Gaussian \(q(\mathbf{X})\) under the collapsed Titsias bound plus a standard-normal KL term — the same modelling target as GPy’s `BayesianGPLVM` for RBF/ARD (and Linear / Bias / White compounds).

This is **not** a small patch on MAP [`CGplvm`](../CGplvm.h). Today GPc has point-estimate latent \(\mathbf{X}\), no uncertain-input expectations, and sparse approximation stubs inside `CGplvm` that never enter the likelihood. The reusable base is DTCVAR / inducing algebra in [`CGp`](../CGp.h) (and the whitened StableFactor path from [CIP-0012](./cip0012.md)), plus MAP GPLVM’s PCA init, optimiser packing, and stream patterns.

**Which requirements?** Primary: [REQ-000B](../requirements/req000B_bayesian-gplvm-psi.md). Also advances verification culture from [REQ-0002](../requirements/req0002_runnable-verification.md) and exercises kernel catalogue depth from [REQ-0005](../requirements/req0005_gpy-aligned-kernel-coverage.md).

## Motivation

GPy’s Bayesian GP-LVM is the practical default for latent visualisation when MAP overfits or when regularising \(q(\mathbf{X})\) matters. GPc already ships a MAP GPLVM CLI and oil tutorial, and CIP-0015 / REQ-0009 explicitly listed Bayesian GPLVM as a non-goal for tutorial parity. Closing that gap keeps Interoperate With the GP Ecosystem honest once demos claim GPy-subset coverage.

Technically, the missing piece is **psi statistics**: expectations of the kernel under Gaussian inputs,

\[
\psi_0 = \sum_n \mathbb{E}_{q(\mathbf{x}_n)}[k(\mathbf{x}_n,\mathbf{x}_n)],\quad
\Psi_1 = \mathbb{E}_{q(\mathbf{X})}[K_{\mathbf{f}\mathbf{u}}],\quad
\Psi_2 = \sum_n \mathbb{E}_{q(\mathbf{x}_n)}[k(\mathbf{x}_n,\mathbf{Z})k(\mathbf{Z},\mathbf{x}_n)^\top].
\]

Those replace \(K_{\mathbf{uf}}\) and the DTCVAR trace term in the sparse bound. Without a `CKern` contract for them, every uncertain-input model would reimplement RBF integrals.

## Detailed Description

### Feasibility (codebase facts)

| Area | Today | Gap |
|---|---|---|
| MAP `CGplvm` | Dense FTC ML over point \(\mathbf{X}\); PCA init; optional GPDM / back-constraints | No \(q(\mathbf{X})\); sparse approx flags are stubs |
| `CGp` sparse | DTC / DTCVAR / FITC / PITC; learnable \(Z=\mathbf{X}_u\); CIP-0012 whitened \(C=I+\beta BB^\top\) | Deterministic \(K_{uf}\) only |
| `CKern` | `compute`, `getGradX`, `updateX`, compounds/tensors | No `psi0` / `psi1` / `psi2` or gradients |
| Verification | `matfiles/` MATLAB-era; `checkGradients`; CIP-0012 mpmath gates | Need text fixtures (GPy script) and/or MC for psi |

**Verdict:** Feasible as a **new feature CIP**, not an incremental GPLVM tweak. Rough size: about **2–3× CIP-0012** (~15–25 person-days across phases), with the main risk in **psi2 gradients** for RBF-ARD.

### Design principles (tenets)

1. **Compose Through Interfaces** — virtual psi API on `CKern`; default throws `NotImplementedError`. Model code never special-cases RBF.
2. **Assert and Verify** — `DIMENSIONMATCH` on \((\boldsymbol{\mu},\mathbf{S},Z)\); `checkGradients` on the full ELBO; fixture compare with `ndlutil::MATCHTOL` (or documented looser tol for MC).
3. **Flexibility Without a Performance Tax** — prefer accumulating \(\sum_n \Psi_2^{(n)}\) into an \(M\times M\) matrix; avoid storing \(N\times M\times M\) unless a debug path needs it.
4. **LAPACK Owns the Linear Algebra** — reuse StableFactor / Cholesky of \(K_{uu}\) and the DTCVAR slots (`gK_uu`, `gK_uf`→`gPsi1`/`gPsi2`, `gBeta`); do not invent a second inducing solver.
5. **Ecosystem Interoperability** — match GPy’s diagonal \(q(\mathbf{X})\) parameterisation and natural kernel params; verify against GPy-generated fixtures, not against MATLAB mex.

### Phase 1 — Psi contract and closed forms

Add to `CKern` (names indicative):

- `psi0(mu, S)`, `psi1(Psi1, mu, S, Z)`, `psi2(Psi2sum, mu, S, Z)`  
- Gradient entry points wrt kernel hyperparameters, \(Z\), \(\boldsymbol{\mu}\), and \(\mathbf{S}\) (exact signatures to mirror GPy’s `psicomp` / `psichol` split where helpful).

Implement first for:

- `CRBFKern` / `CRBFARDKern` (Titsias & Lawrence 2010 closed forms)
- `CLinKern`, `CBiasKern`, `CWhiteKern`
- `CCmpndKern`: \(\psi_0,\Psi_1\) additive; \(\Psi_2\) includes cross terms \(\sum_{i,j} \mathbb{E}[k_i k_j]\)

Out of Phase 1: Matérn closed form, general tensor products, non-diagonal \(q(\mathbf{x}_n)\).

**Verification without MATLAB:** (a) finite-difference grads; (b) Monte Carlo \(\mathbb{E}[k]\) under \(q(\mathbf{x})\); (c) optional small text fixture from a pinned GPy script checked into `matfiles/` or `testdata/`.

### Phase 2 — `CBayesGplvm` (or equivalent name)

New model class (prefer **not** overloading MAP `CGplvm` until the ELBO path is proven):

- Parameters: kernel, \(\beta\) (or Gaussian noise), inducing \(Z\), \(\boldsymbol{\mu}\) (\(N\times q\)), \(\mathbf{S}\) (\(N\times q\)) with positive transforms on \(\mathbf{S}\)
- Objective: collapsed sparse variational bound with \(\Psi_0,\Psi_1,\Psi_2\) replacing \(K_{ff}\) diag / \(K_{fu}\) / \(K_{fu}K_{uf}\), minus \(\mathrm{KL}(q\|p)\) for \(p(\mathbf{x})=\mathcal{N}(0,I)\)
- Init: reuse `initXpca` for \(\boldsymbol{\mu}\); small isotropic \(\mathbf{S}\); \(Z\) from subset of \(\boldsymbol{\mu}\) or k-means-style pick
- Wire `COptimisable` / SCG; call `checkGradients` when param count is small or under a test flag
- `.model` stream fields versioned for \(\boldsymbol{\mu}\), \(\mathbf{S}\), \(Z\)
- CLI: flag on `./gplvm` or a dedicated binary — decide at Accept

Reuse CIP-0012 adjoint pattern: forward uses whitened inducing algebra; reverse mode fills kernel / \(Z\) / \(\beta\) grads; psi grads supply \(\partial\Psi/\partial\theta\).

### Phase 3 — GPy parity gates

- Script (documented, not required at CI runtime if fixtures are committed) that dumps psi, ELBO, and a gradient vector for a seeded tiny problem
- `testBayesGplvm` (name TBD) compares C++ to fixtures
- Optional: short oil-100 Bayesian run vs MAP in a markdown tutorial **after** CIP-0015 Stage work — do not block 0015

### Explicit non-goals (this CIP)

MRD, SSGPLVM, SVI/SVGP, HMC, dynamics prior on latents, inferring \(q(\mathbf{x}_*)\) for held-out \(\mathbf{Y}_*\) beyond mean/var prediction, Matérn psi, full tensor psi, Python bindings, changing MAP `CGplvm` defaults.

### Relation to CIP-0015 / REQ-0009

Those documents list Bayesian GPLVM as out of scope. On **Accept** of this CIP (or REQ-000B → Ready), amend those non-goal bullets to point here rather than “future CIP” with no owner.

### Alternatives considered

1. **Extend MAP `CGplvm` in place** — Rejected for first delivery: sparse stubs and MAP likelihood would tangle; a parallel class keeps assert surfaces clear.
2. **Port GPy Cython psicomp via FFI** — Rejected: violates Flexibility Without a Performance Tax (host round-trip) and Compose Through Interfaces (kernel contract in C++).
3. **Uncertain inputs inside `CGp` only** — Deferred: useful later for regression with noisy \(\mathbf{X}\); Bayesian GPLVM is the motivating end-to-end user path and forces the full KL + init story.

## Implementation Plan

1. **Accept gate** — Confirm REQ-000B Ready; amend CIP-0015 / REQ-0009 non-goal pointers; create backlog tasks per phase.
2. **Phase 1** — Psi API + RBF/ARD/Lin/Bias/White + compound; FD + MC tests.

4. **Phase 3** — GPy text fixtures + compare test; optional tutorial note.
5. **Close** — Update README / `docs/tutorials/` only after verification (compression stage).

## Backward Compatibility

- MAP `CGplvm` and `./gplvm` default behaviour unchanged.
- New stream keys are additive; old GPLVM `.model` files remain loadable.
- `CKern` gains virtual methods with safe defaults (throw / no-op documented); existing kernels compile without implementing psi until needed.

## Testing Strategy

- Unit: psi vs MC and FD for each implemented kernel; compound cross-term sanity.
- Model: `checkGradients` on \(N,M,q\) small enough for FD; ELBO vs GPy fixture.
- Asserts: size mismatches on \(\boldsymbol{\mu}\)/\(\mathbf{S}\)/\(Z\) abort; positive \(\mathbf{S}\) via transforms.
- CI: fixture-based tests without MATLAB; optional GPy script is maintainer tooling, not a CI dependency.
