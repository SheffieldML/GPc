# CIP-0018: Manifold Relevance Determination (GPy-parity subset)

## Summary

Add a **multi-view** variational model comparable to GPy’s `MRD`: one shared diagonal Gaussian \(q(\mathbf{X})\) and shared inducing set \(Z\) across \(V \ge 2\) aligned views \(\{\mathbf{Y}^{(v)}\}\), each with its own RBF-ARD (or other psi-capable) kernel and homoscedastic noise. The objective is

\[
\sum_{v=1}^{V} \mathcal{L}_{\mathrm{VarDTC}}^{(v)}(\mathbf{Y}^{(v)},\theta_v,\beta_v;\,q(\mathbf{X}),Z)
- \mathrm{KL}\bigl(q(\mathbf{X})\,\|\,\mathcal{N}(0,I)\bigr),
\]

with the KL counted **once**. Soft private/shared latent structure is read off by comparing per-view ARD input scales (GPy `factorize_space` / `plot_scales`).

This is **composition on top of** [CIP-0017](./cip0017.md) / [`CBayesGplvm`](../CBayesGplvm.h). Do **not** fork a second VarDTC or reimplement psi.

**Which requirements?** Primary: [REQ-000C](../requirements/req000C_manifold-relevance-determination.md). Relies on [REQ-000B](../requirements/req000B_bayesian-gplvm-psi.md). Verification culture from [REQ-0002](../requirements/req0002_runnable-verification.md).

## Motivation

CIP-0017 closed the single-view Bayesian GP-LVM gap. GPy tutorials and Damianou et al. (ICML 2012) treat MRD as the natural multi-view next step: same uncertain latents and inducing algebra, separate ARD kernels per view so dimensions that stay active in several views are “shared” and those active in one view are “private.”

An assessment of GPc vs GPy (2026-11-16) concluded the blocking work is multi-view wiring — shared \(\boldsymbol{\mu},\mathbf{S},Z\), summed view bounds, single KL — not more RBF-ARD psi. Shipping MRD keeps Interoperate With the GP Ecosystem honest for multi-view demos without waiting on missing-data or non-Gaussian SparseGP features.

## Detailed Description

### Feasibility (codebase facts)

| Area | Today (post CIP-0017) | Gap for MRD |
|---|---|---|
| Psi + RBF-ARD | On `CKern`; CLI default `rbfard` | Reuse |
| Single-view VarDTC + KL | `CBayesGplvm` | Need per-view bound with **shared** \(q(X),Z\) |
| Parameter packing | One kern, one \(\beta\), one \(Y\) | Sum grads for \(Z,\mu,S\); pack \(V\) kernels and \(\beta_v\) |
| Init | PCA of one \(Y\) | Concat / single-block PCA over views |
| CLI | `./bgplvm` | Multi-file learn + ARD factorise helper |

**Verdict:** Feasible as a **new feature CIP** (~0.5–1× CIP-0017 effort). Main risk is correct joint packing and avoiding double-counted KL; prefer an explicit joint objective over GPy’s `kl_factr = 1/V` child hack.

### Design principles

1. **Compose Through Interfaces** — reuse `CKern` psi and the existing VarDTC cache/grad algebra; views pass local \(Y,\beta,D,\mathrm{kern}\).
2. **Assert and Verify** — `DIMENSIONMATCH` on equal \(N\) across views; `checkGradients` on a tiny \(V=2\) problem; GPy MRD text fixture.
3. **LAPACK Owns the Linear Algebra** — one inducing factorisation path per view update; no second solver.
4. **Ecosystem Interoperability** — match GPy’s shared-\(X\) / per-view-ARD story; document intentional deviations (single KL, init defaults).

### Preferred architecture

Do **not** fork VarDTC. Prefer one of:

1. Extract a thin **view bound** helper (VarDTC ELBO + grads given fixed \(q(\mathbf{X}),Z\)) from `CBayesGplvm`, then `CMrd` owns shared latents and a vector of `{Y, kern, beta}`; **or**
2. `CMrd` holds shared \(\mu,S,Z\) and internally drives \(V\) view structs that call the same cache routines with view-local \(D,\beta,Y\).

Either way:

- Objective: \(\sum_v L_{\mathrm{var}}^{(v)} - \mathrm{KL}\) (central KL).
- Shared grads: \(\partial/\partial Z,\mu,S = \sum_v (\partial L_{\mathrm{var}}^{(v)}/\partial\cdot) - \partial\mathrm{KL}/\partial\cdot\).
- Per-view grads: kernel params and \(\beta_v\) only from view \(v\).
- Single-view `CBayesGplvm` remains the \(V=1\) API; MRD does not replace it.

### Init

- Default: concat-PCA on \(\mathrm{hstack}(Y^{(1)},\ldots,Y^{(V)})\) into \(\boldsymbol{\mu}\) (GPy `PCA_concat` spirit); \(\mathbf{S}\) small positive; \(Z\) subset/permute of \(\boldsymbol{\mu}\) rows.
- Document `PCA_single`-style block init as optional if useful for demos.

### UX

- Library API first; optional `./mrd` or `bgplvm`-style CLI taking multiple SVM-light paths.
- Dump/display per-view ARD `inputScale_*`; helper akin to `factorize_space(threshold)` returning shared vs private index sets.
- Gnuplot: reuse plane select (`-d`) on the shared \(\boldsymbol{\mu}\); variance map from a chosen view’s posterior.

### Explicit non-goals (this CIP)

Missing-data VarDTC, non-Gaussian views, minibatch/SVI/MPI, Linear-ARD psi, SSGPLVM, dynamics / GPDM priors, Matérn/tensor psi, inferring \(q(x_*)\) from new multi-view \(Y_*\), Python bindings, changing `./bgplvm` single-view defaults.

### Alternatives considered

1. **GPy-style child models with `kl_factr`** — Works in paramz; in C++ an explicit joint objective is clearer and equivalent if KL is counted once. Prefer joint objective.
2. **Hard private/shared subspaces** — Rejected for v1; soft ARD matching GPy MRD is the target.
3. **Extend `CBayesGplvm` in place with optional view list** — Risk of muddying the single-view stream and CLI; prefer a sibling `CMrd` (or clearly named multi-view class).

## Backward Compatibility

- `CBayesGplvm` and `./bgplvm` unchanged in defaults and stream format.
- New stream type for MRD models; old Bayes GPLVM `.model` files remain loadable.

## Testing Strategy

- Unit: \(V=2\) tiny synthetic with known shared/private dims; ELBO finite; FD grads on joint param vector.
- Fixture: GPy `MRD` dump of ELBO and per-view ARD scales (ranking / threshold factorisation), committed under `testdata/`.
- Asserts: mismatched \(N\) across views abort; \(V < 2\) rejected or redirected to `CBayesGplvm`.
- CI: fixture tests without MATLAB; GPy generator is maintainer tooling.
