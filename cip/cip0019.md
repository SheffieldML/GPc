# CIP-0019: Integrate numerical stability suite (separate from matio reference tests)

> CIPs describe HOW to achieve requirements (WHAT). ## Summary

Land a **first-class, separate** numerical stability suite under `numerical_stability/`, modelled on GPy's `test_numerical_stability.py` contracts (finiteness, accuracy, invariance). Keep it out of `make run-matio-tests` so the MATLAB-era reference gate stays quiet. Wire an optional CI job and a cross-branch outcome comparer.

Known defects use **strict expected-fail** (`xfail` → unexpected pass fails the job) until a follow-up CIP removes them.

## Motivation

`testMatrix` / `testKern` / `testGp` check API shape and fixture parity. They do not systematically probe overflow, cancellation, extreme conditioning, or translation invariance. GPy's suite found real defects that unit tests never hit. GPc needs the same behavioural numerics gate, adapted to C++ APIs (`CMatrix`, `ndlutil`, `CKern`, `CNoise`, `CGp`).

If we fold these checks into `matio-tests`:

1. The reference gate grows with expected failures — noisy and easy to misread.
2. Fix PRs and regression PRs share one green/red signal.
3. There is no way to ask whether a branch clears more expected fails than `main` without new failures.

## Detailed Description

### Goals

1. **Separate suite location** — `numerical_stability/` sibling to `bench/`, not mixed into default `run-matio-tests`.
2. **Stable contracts** — finiteness; accuracy vs analytic / self-consistency tolerances; invariance (translation / input rescaling).
3. **Strict expected-fail** — known bugs report `xfailed`; unexpected pass (`xpassed`) fails the job.
4. **Cross-branch comparison** — same suite binary / outcome stream against two trees; report improvements vs regressions.
5. **Optional CI** — dedicated workflow; does not block the Compile / Reference matio jobs on the full expected-fail catalogue.

### Non-goals

- Fixing catalogued defects (follow-up CIP).
- Replacing matio golden fixtures (CIP-0001 / CIP-0003).
- Porting GPy-only layers GPc does not have (SVGP/`climin`, EP moment matching, Python link-function stack, AST breakpoint scan).

### Layer map (GPy → GPc)

| GPy layer | GPc counterpart |
|-----------|-----------------|
| `GPy.util.linalg` (`jitchol`, `pdinv`, …) | `CMatrix::jitChol`, `pdinv`, `logDet`, `chol`, `trsm` |
| Special functions | `ndlutil::{ngaussian,cumGaussian,lnCumGaussian,gradLnCumGaussian,gamma,gammaln}` |
| Link functions | Skip / fold into noise where relevant (`CProbitNoise`) |
| Likelihoods / EP | `CGaussianNoise`, `CProbitNoise` (no EP / Poisson / Gamma / Student-t stack) |
| Kernels | `CRbfKern`, `CExpKern`, `CMatern32/52Kern`, `CLinKern`, `CWhiteKern`, `CBiasKern`, compounds |
| Models | `CGp` FTC / DTC / FITC / PITC / DTCVAR |
| Source hygiene (`ipdb`) | N/A in C++; skip |

### Pytest-equivalent outcome policy

| Outcome | Meaning |
|---------|---------|
| `passed` | Contract holds |
| `xfailed` | Known defect; expected |
| `xpassed` | Known defect fixed — **fail** until marker removed |
| `failed` | Unexpected regression — fail |

Machine-readable lines: `OUTCOME name=<id> result=<outcome>`.

### Layout

```text
numerical_stability/
  README.md
  testNumericalStability.cpp   # suite driver
  compare.py                    # baseline vs candidate outcome diff
  test_compare.py               # classify() unit tests (Python)
```

### How to run (local)

```bash
# Reference / unit track (unchanged)
make USE_MATIO=1 matio-tests && make run-matio-tests

# Numerical suite only
make testNumericalStability && ./testNumericalStability

# Or
make run-numerical-stability
```

### CI

Dedicated workflow `.github/workflows/numerical-stability.yml`:

- Path filter: library sources, `numerical_stability/**`, makefile, that workflow.
- Ubuntu + OpenBLAS (one cell — numerics are not an OS matrix drama).
- Build and run `./testNumericalStability`; fail on `failed` / `xpassed`.

### Cross-branch comparer

`numerical_stability/compare.py` runs the suite binary (or parses saved outcome JSON) for baseline vs candidate and classifies nodeids like GPy CIP-0011. Exit non-zero on regressions.

## Implementation Plan

1. House the suite under `numerical_stability/` + README.
2. Implement C++ driver with outcome reporting and strict xfail helpers.
3. Makefile targets; leave `matio-tests` / `run-matio-tests` untouched.
4. CI workflow with path filters.
5. `compare.py` + `test_compare.py` for the outcome matrix.
6. Smoke-run locally; freeze any xfails with cause strings.

## Backward Compatibility

- Contributors who only run matio reference tests see no difference.
