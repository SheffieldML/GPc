# CIP-0021: Resuscitate Probabilistic Point Assimilation (PPA) from Nat King MATLAB

> CIPs describe HOW to achieve requirements (WHAT). This CIP extends verification and contemporary C++ hygiene for a dormant model path ([REQ-0002](../requirements/req0002_runnable-verification.md), [REQ-0004](../requirements/req0004_modern-cpp-toolchain.md)).

## Summary

Bring **Probabilistic Point Assimilation (PPA)** back to a buildable, tested GPc path by porting the finished algorithm from Nathaniel King’s MATLAB toolbox ([lawrennd/ppa](https://github.com/lawrennd/ppa), local clone `~/lawrennd/ppa`) into the modern `CIvm`-style C++ contracts — not by polishing the unfinished `CPpa` stubs in isolation.

PPA is a full-data variational EM method for GPs with interchangeable noise models (King & Lawrence, TR CS-05-06 / ECML material). GPc already ships CLI-shaped sources (`CPpa.{h,cpp}`, `ppa.cpp`) that never linked into the makefile, inherit a deleted base class, and leave `mStep` / \(q(\bar f)\) unimplemented. The MATLAB tree supplies the missing E/M steps, demos, and data for assert-and-verify fixtures.

**Which requirements?** [REQ-0002](../requirements/req0002_runnable-verification.md) (runnable verification for a restored model), [REQ-0004](../requirements/req0004_modern-cpp-toolchain.md) (C++17-era interfaces, no orphan targets). Orthogonal to sparse/`CGp` work (CIP-0012/001B/001C): PPA is dense \(N\times N\), not an inducing approximation.

## Motivation

Maintainers and users meeting `ppa.cpp` / `CPpa` in the tree cannot build or test them. README and CI advertise `gp` / `ivm` / `gplvm` / `bgplvm` only. Leaving a half-port in-tree violates Assert and Verify: shapes and gradients cannot be checked if the model never runs.

Nat King’s MATLAB release 0.1 is complete enough to act as the reference of record (`ppaEStep`, `ppaMStep`, `ppaExpectfBar`, `ppaExpectfBarfBar`, `ppaInit`, `ppaOptimisePPA`, `demPpa1`–`4`). The C++ under `ppa/src/` in that repo is the same unfinished port as GPc — **do not treat `ppa/src` as the algorithm source.**

Without this CIP the honest alternatives are archive/delete PPA or leave silent rot. Revival is chosen because the reference toolbox and paper still exist locally and on GitHub.

## Detailed Description

### Feasibility (codebase facts)

| Area | Today (GPc) | MATLAB reference (`lawrennd/ppa`) |
|---|---|---|
| Algorithm | `mStep()` empty; `updateExpectationsfBar` throws; `init` / `updateK` / `updateInvK` declared but not defined | Full EM: E-step expectations under \(q(f)\), \(q(\bar f)\); M-step kernel (+ optional β) via SCG |
| Model shape | Mixes IVM active-set vocabulary (`activeX`, `activeSet`) with PPA EM | **Full-data** GP: `kern.Kstore` / `invKstore` are \(N\times N\) |
| Base class | `COptimisableKernelModel` (gone) | N/A (struct model + noise/kern toolboxes) |
| CLI | `ppa.cpp` includes missing `ppa.h` | `demPpa*.m` |
| Build / CI | No makefile target; not in `compile.yml` | Depends on KERN/NOISE/NDLUTIL/OPTIMI/PRIOR/MLTOOLS/NETLAB |
| Tests | None; no `matfiles/*ppa*` | `demPpa1` + `matlab/testFunctions/` calibration scripts |

**Verdict:** Feasible as a **revive CIP** of roughly IVM size once Phase 0 proves MATLAB/Octave can emit fixtures. Main risks: old MATLAB stack bit-rot; \(O(N^3)\) dense algebra (by design); confused active-set leftovers in C++ that must be removed or clearly demoted to stream-only history.

### Design principles (tenets)

1. **Assert and Verify** — every restored EM piece compared to MATLAB/Octave dumps (or frozen numeric fixtures) with `equals` / `ndlutil::MATCHTOL`; `checkGradients` on kernel (and β when enabled) objectives.
2. **Compose Through Interfaces** — `CPpa` mirrors `CIvm`: `CMapModel` + `CProbabilisticOptimisable` + `CStreamInterface` (+ optional `CMatInterface` only if matio path is kept). Noise via `CNoise`; kernel via `CKern`.
3. **LAPACK Owns the Linear Algebra** — replace MATLAB `pdinv` with Cholesky / triangular solves already used by IVM/`CMatrix`; no hand-rolled dense inverse in the hot path.
4. **Flexibility Without a Performance Tax** — keep PPA dense and honest; do not pretend FITC-scale. Prefer one \(N\times N\) factorisation path with clear storage ownership (no leaking `vector<CMatrix*>` without RAII cleanup).
5. **Ecosystem Interoperability** — CLI parity with IVM where sensible (`learn`, `test`, `predict`, `display`, `gnuplot`); stream version `ppaVersion` bumped if field layout changes; document that old unreleased `.model` files are unsupported if none exist in the wild.

### Algorithm target (from MATLAB)

Outer loop (`ppaOptimisePPA`): init → repeat M-step then E-step until Δ log-likelihood &lt; tol or max outer iters.

**E-step** (`ppaEStep`):

1. Update \(\langle \bar f\rangle\), \(\langle \bar f\bar f^\top\rangle\) under \(q(\bar f)\):
   - \(\mathrm{Cov}_i = (\mathrm{diag}(B_{\cdot i}) + K^{-1})^{-1}\)
   - \(\langle \bar f_{\cdot i}\rangle = \mathrm{Cov}_i\,\mathrm{diag}(B_{\cdot i})\,\langle f_{\cdot i}\rangle\)
   - \(\langle \bar f\bar f^\top\rangle_i = \mathrm{Cov}_i + \langle\bar f\rangle\langle\bar f\rangle^\top\)
2. `noiseUpdateNuG` → `g`, `nu`; `gamma = (g.^2 - nu)/2`
3. \(\langle f\rangle = \langle\bar f\rangle + g \oslash B\); second moment via `ppaExpectff`

**M-step** (`ppaMStep`): optimise kernel params (`ppaUpdateKernel` / variational or KL forms); optional β update (`ppaScgUpdateBeta`, scalar or matrix per `options.scalarB`).

C++ Phase 1 may ship **scalar β** and **non-variational kernel M-step** first (MATLAB `options.varKern = false` path), matching the simplest demos.

### Non-goals

- Sparse / inducing PPA, or merging PPA into `CGp` approximations
- Gunnar / Raetsch full benchmark reproduction in CI
- Mex / `_NDLMATLAB` as the primary verification path (fixtures may be generated once offline)
- Claiming performance parity with IVM on large \(N\)

### Go / cut criteria

- **Continue** after Phase 0 if `demPpa1` (or equivalent) runs and we can dump \(K\), expectations, and log-likelihood for a fixed seed/params.
- **Defer/Reject** if the MATLAB stack cannot be made to run and no trustworthy frozen fixtures can be recovered — then archive `CPpa` / `ppa.cpp` out of the default tree rather than ship stubs.

## Implementation Plan

1. **Phase 0 — Reference spike** (this worktree first):
   - Map MATLAB → C++ symbols; document scalar-β / full-\(N\) choice.
   - Run `demPpa1` (Octave or MATLAB) with local `kern`/`noise`/… deps; dump reference tensors.
   - Exit note: revive continues vs archive.

2. **Phase 1 — Compile skeleton**:
   - Restore `ppa.h` (`CClppa` like `CClivm`).
   - Rebase `CPpa` onto IVM-like bases; fix members (`K` / `invK` / expectations; drop bogus active-set API for the live path).
   - Implement `init` / `updateK` / `updateInvK` enough to link.
   - `make ppa`; CI smoke `./ppa -h` only.

3. **Phase 2 — E-step + M-step port**:
   - Port expectations and empty `mStep` from MATLAB; wire kernel (+ optional β) through `COptimisable`.
   - LAPACK factorisations; `DIMENSIONMATCH` / symmetry flags.

4. **Phase 3 — Verification**:
   - `testPpa` vs Phase 0 fixtures; `checkGradients` on approx LL / kernel objective.
   - CLI smoke: learn on `rand_*` or `examples/` toy; `display` / `predict`.

5. **Phase 4 — Docs and close**:
   - README binary list + short tutorial after Closed; mark `compressed` when formal docs absorb the CIP.

## Backward Compatibility

- No released GPc binary currently builds `ppa`; breaking stream field renames are acceptable with a version bump.
- IVM / GP / GPLVM paths unchanged.
- Dense \(N\times N\) memory use is inherent; document practical \(N\) guidance in the tutorial.

## Testing Strategy

- **Reference**: MATLAB/Octave dumps from `demPpa1` (and a probit classification toy) compared in `testPpa`.
- **Gradients**: `checkGradients` on kernel parameters after a few EM iterations at fixed noise sites.
- **Build**: `make ppa` in Compile workflow; optional inclusion in `matio-tests` only if matio fixtures are added.
- **Non-regression**: existing `testIvm` / `tests` targets must stay green.
