# CIP-0021: CMake CI soak then hard-gate cutover

> CIPs describe HOW to achieve requirements (WHAT). This CIP revisits the CI cutover that [CIP-0020](./cip0020.md) explicitly deferred. It implements the verification posture of [REQ-0001](../requirements/req0001_contemporary-build.md) / [REQ-0002](../requirements/req0002_runnable-verification.md) under CMake on Actions, without regressing [REQ-0007](../requirements/req0007_competitive-default-build.md) OpenBLAS / release semantics. Local day-to-day `make` stays documented and supported.

## Summary

Bring GitHub Actions onto the thin CMake path from CIP-0020 in **two phases**: (1) parallel non-blocking (or `continue-on-error`) CMake compile + `ctest` jobs that must match makefile results during a soak; (2) only after soak evidence, flip Compile and Reference hard gates to CMake. Coverage and numerical-stability stay on make until a later follow-up unless soak shows an easy gcov path. Do **not** delete makefile CI or local `make.linux` / `make.osx` in this CIP.

**Which requirements?** [REQ-0001](../requirements/req0001_contemporary-build.md), [REQ-0002](../requirements/req0002_runnable-verification.md), [REQ-0007](../requirements/req0007_competitive-default-build.md).

## Motivation

CIP-0020 shipped living CMake (`libgp`, CLIs, `GPC_BUILD_TESTS` / CTest, scikit-build) but locked Actions on make. That was correct for packaging-first delivery. The cost of staying there forever:

1. **Drift** — `cmake/GpcSources.cmake` and makefile object lists can diverge; CI only exercises one.
2. **Packaging confidence** — wheels use CMake; merges are gated on make. Failures that only appear under CMake land after release packaging.
3. **Contributor path** — macOS Homebrew GCC / OpenBLAS discovery is already encoded in CMake; duplicating it only in make fragments is ongoing tax.

Tenets: **Assert and Verify** (soak before flipping the gate); **Interoperate** (CI matches the packaging generator); **Flexibility Without a Performance Tax** (build system stays outside the SCG loop).

## Detailed Description

### Locked decisions (for Proposed review)

1. **New CIP, not amend CIP-0020.** CIP-0020’s cutover deferral stays historically true; this CIP owns the CI change.
2. **Soak before hard fail.** Phase 1 adds Ubuntu + macOS CMake jobs that build CLIs (Compile parity) and run `ctest` with `GPC_USE_MATIO=ON` (Reference parity). Prefer a dedicated workflow (e.g. `cmake-ci.yml`) with `continue-on-error: true` **or** a required check that is introduced only after soak — do not flip existing hard jobs on day one.
3. **Parity bar.** CMake Reference job must exercise the same binary set as `make run-matio-tests` (already listed in `cmake/GpcTests.cmake`). Compile smoke must cover `gp` / `ivm` / `gplvm` / `bgplvm` help (same as `compile.yml`).
4. **Toolchain matrix matches today.** Ubuntu: apt `g++` / `gfortran` / `libopenblas-dev` / `libmatio-dev` / `cmake` / `ninja-build` (or Unix Makefiles). macOS: Homebrew `gcc` / `openblas` / `libmatio` / `cmake`; pass `CXX`/`FC` to Homebrew `g++-N` / `gfortran-N` or rely on `GPC_PREFER_HOMEBREW_GCC`.
5. **Flags.** Checking builds use Debug (makefile default / `GPC_CHECKS=1`). Do not silently switch CI to `Release` / `GPC_CHECKS=0`.
6. **Coverage stays on make in this CIP** unless Phase 1 discovers a low-risk gcov story. Numerical-stability workflow stays on make. Optional follow-up CIP for Coverage-on-CMake.
7. **Python façade CI** is optional Phase 3: `pip install -e python/[test]` + pytest on Ubuntu only (scikit-build). Not required to flip Compile/Reference hard gates.
8. **Local make remains blessed for humans.** README / `docs/build-and-ci.md` continue to lead with `make`; document CMake CI as the Actions path after cutover. Do not remove `makefile` / `make.linux` / `make.osx`.
9. **Rejected:** big-bang replacement of all four workflows on one PR; Windows CI (still needs its own fragment/CIP); retiring make in-tree.

### Soak exit criteria (Phase 1 → Phase 2)

- At least one full week on `main` (or ≥N merged PRs — pick at Accept) where parallel CMake Compile + CTest are green whenever makefile gates are green.
- No unresolved CMake-only flakes on macOS (RPATH / gfortran) or Ubuntu (OpenBLAS discoverability).
- Short note in the PR / CIP Progress Updates listing any intentional differences (none expected).

### Cutover (Phase 2)

- Convert parallel jobs to hard-fail **or** replace steps inside existing `compile.yml` / `reference-tests.yml` with CMake/`ctest`.
- Keep makefile workflows temporarily as `continue-on-error` for one further soak **or** drop them once Phase 2 is trusted — decide at Phase 2 Accept with evidence; default proposal: **keep make as a non-required shadow for one release**, then remove shadow jobs in a tiny follow-up commit.

## Implementation Plan

1. **Phase 0 — Docs + CIP-0020 close**  
   - Mark [CIP-0020](./cip0020.md) Closed (merged via #74).  
   - Point `docs/build-and-ci.md` at this CIP for “CI cutover”.

2. **Phase 1 — Parallel CMake CI (non-blocking)**  
   - Add `.github/workflows/cmake-ci.yml` (matrix Ubuntu + macOS).  
   - Jobs: configure (`-DGPC_BUILD_TESTS=ON -DGPC_USE_MATIO=ON -DGPC_BUILD_PYTHON=OFF`), build, CLI help smoke, `ctest --output-on-failure`.  
   - `continue-on-error: true` (or equivalent) until soak exit criteria met.  
   - Install `cmake` (+ `ninja` optional) on both OSes.

3. **Phase 2 — Hard-gate cutover**  
   - Flip Compile + Reference to CMake (hard fail).  
   - Update `docs/build-and-ci.md` Actions table.  
   - Optional makefile shadow jobs as above.

4. **Phase 3 — Optional packaging smoke (can ship with Phase 1 or later)**  
   - Ubuntu-only: editable `pip install -e python/[test]` + `pytest -q python/tests`.  
   - Does not block Phase 2.

## Backward Compatibility

- Local `make gp` / `make USE_MATIO=1 run-matio-tests` unchanged.  
- No model / matfile / CLI changes.  
- Contributors who only use make keep working; Actions may require CMake on runners after Phase 2 (already true for packaging).

## Testing Strategy

- Phase 1: compare parallel job logs to makefile Reference on the same commit; investigate any CMake-only failure before treating soak as green.  
- Phase 2: PR must show hard CMake gates green on Ubuntu + macOS; makefile shadow green if retained.  
- Assert-and-Verify: fixture-backed tests still load `matfiles/` via `_NDLMATIO`.
