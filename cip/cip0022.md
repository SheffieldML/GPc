# CIP-0022: CSV and pods as preferred data path; SVM-light as legacy

## Summary

Move tutorial and CLI **data** I/O onto dense **CSV/TSV** for C++, and **`pods.datasets`** for Python examples, matching GPy / mlatcl practice. Keep SVM-light (`.svml`) as a supported legacy reader. Do not invent a new SheffieldML data schema; do not conflate this with model interchange ([CIP-0016](./cip0016.md) / [REQ-000A](../requirements/req000A_shared-model-interchange.md)).

**Which requirements does this CIP address?** [REQ-0011](../requirements/req0011_csv-pods-data-access.md).

## Motivation

GPc’s README and CLIs still centre on Thorsten Joachims’ SVM-light format for interoperability with older SheffieldML tools and Anton Schwaighofer’s MATLAB SVML toolbox. That path is dated:

- GPy examples load oil, olympic marathon, swiss roll, etc. via **`pods`**, not `.svml`.
- GP tutorial matrices are dense; sparse `label idx:value` encoding adds friction for pandas / NumPy / simple editors.
- CIP-001D Phase E already plans optional `pods` notebooks; native CLI still has only SVML + optional MATLAB in `CClctrl::readData`.

Aligning the preferred path with CSV + pods restores “speak the formats the community already uses” without waiting on model YAML.

## Detailed Description

### Layering

| Layer | Preferred | Legacy / optional |
|--------|-----------|-------------------|
| C++ CLI / demos | Dense CSV/TSV via `CClctrl` | `.svml` (format 0); MATLAB `.mat` when `_NDLMATLAB` |
| Python examples | `pods.datasets.*` → NumPy → `gpc` | Hand-written CSV; no SVML required |
| Large arrays | Existing `_HDF5` on `CMatrix` (later, not first cut) | — |
| Model files | Unchanged `.model`; future YAML per CIP-0016 | — |

`pods` stays an **optional** Python extra (same as GPy examples / CIP-001D Phase E). Core C++ never depends on Python or network download.

### CSV layout (first cut)

Document and implement one primary convention so tutorials stay boring:

1. **Single file** `name.csv`: whitespace- or comma-separated dense matrix; **last column is `y`**, preceding columns are `X`. Lines starting with `#` are comments. Optional first line of non-numeric tokens = header (skipped).
2. **Paired files** (optional second mode): `name.X.csv` and `name.y.csv` with matching row counts — useful for multi-output `y` or when labels are separate.

Fail loudly if row counts disagree, files are empty, or tokens are non-numeric after header skip (`FileFormatError` / `DIMENSIONMATCH`-style checks into `X`/`y` sizes).

### `CClctrl` integration

Today (`CClctrl.cpp`):

- `fileFormat == 0` → `readSvmlDataFile`
- `fileFormat == 1` → MATLAB `X`/`y` variables

Add:

- `fileFormat == 2` → `readCsvDataFile` (new)
- **Auto-detect** in `readData` when format is unset / default: `.svml` → 0, `.mat` → 1, `.csv`/`.tsv`/`.txt` → 2 (txt as dense CSV with whitespace)

CLI flags (if any already select format) gain a CSV value; demos that hard-call `readSvmlDataFile` can switch to `readData` or `readCsvDataFile` once examples exist.

### Example artefacts

- Export or hand-author dense CSV for **sinc** (and preferably **spgp1d** or oil100 subset) under `examples/`, generated once from existing `.svml` or from `pods` so C++ demos stay offline.
- Prefer CSV in new/updated CIP-0015 tutorial pages; leave `.svml` in-tree and note compatibility.
- Python: Phase E notebooks use `pods` (olympic marathon / oil_100); no new SVML writers.

### Explicit non-goals

- OpenML or Parquet as a C++ dependency
- Replacing `.model` or implementing CIP-0016 here
- Bundling `pods` into core `gpc`
- Silent migration that deletes `.svml` examples in the first delivery
- Putting parsers on the SCG hot path

### Tenet note

[ecosystem-interoperability](../tenets/gpc/ecosystem-interoperability.md) examples currently lead with SVM-light. Soft-update those examples to prefer CSV/`pods`, with SVM-light as legacy — same durable idea (shared inspectable data at the boundary), updated community formats.

## Implementation Plan

1. **Spec lock**: Confirm CSV conventions above (single-file last-column-`y` as default; paired files optional).
2. **C++ reader**: Implement `CClctrl::readCsvDataFile`; wire `fileFormat == 2` and extension auto-detect in `readData`; keep SVML path unchanged.
3. **Examples**: Add `examples/sinc.csv` (and at least one second set); update one demo + one tutorial page to prefer CSV; retain `.svml`.
4. **Python**: Cross-link CIP-001D Phase E — document `pods` as the interesting-data path; optional tiny script to dump `pods` → CSV for offline CLI (script under `scripts/` or `python/examples/`, not a core dep).
5. **Docs / tenet**: Update README data-format paragraph; soft-update ecosystem-interoperability examples; CIP-0015 tutorial index note.
6. **Tests**: Round-trip or golden compare: load `sinc.svml` and `sinc.csv` → `X`/`y` agree within `ndlutil::MATCHTOL`; malformed CSV throws.

## Backward Compatibility

- All existing `.svml` loads continue to work.
- Default CLI behaviour: if users pass `.svml` paths, behaviour unchanged; if they pass `.csv`, new path applies.
- No change to `.model` streams or optimiser internals.
- MATLAB format path unchanged when compiled with `_NDLMATLAB`.

## Testing Strategy

- Unit / CLI test: CSV loader dimension and value checks against a tiny fixture.
- Parity: `sinc.svml` vs `sinc.csv` matrices equal within tolerance.
- Smoke: `./gp learn` (or demo binary) on CSV example completes.
- Python: optional — notebook or script import `pods` only under `gpc[examples]` / documented extra (covered primarily by CIP-001D Phase E).
