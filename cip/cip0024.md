# CIP-0024: EQ / ExpQuad — GPy lengthscale-first SE surface on shared RBF engine

## Summary

Make GPy’s **ExpQuad parameterisation** (lengthscale \(\ell\) + variance, \(k(r)=\sigma^2\exp(-\frac12 r^2)\) with lengthscale-scaled \(r\)) a first-class GPc surface under type/name **`eq` / `ExpQuad`**, implemented as a thin type on the existing `CRbfKern` numerical engine. Naming is secondary to parameterisation parity. [CIP-000C](./cip000C.md) deferred ExpQuad as duplicate maths; this CIP is the GPy-facing SE contract, not a second formula.

**Which requirements?** [REQ-0012](../requirements/req0012_eq-expquad-parameterisation.md). Builds on path/unit policy from [REQ-0008](../requirements/req0008_gpy-like-parameter-access.md) / [CIP-0014](./cip0014.md). Foreshadows portable tags in [REQ-000A](../requirements/req000A_shared-model-interchange.md) / [CIP-0016](./cip0016.md).

**Numbering note**: CIP-0022 is CSV/pods; CIP-0023 is PPA revive on its branch. This EQ delivery is **CIP-0024**.

## Motivation

GPy’s clean squared-exponential teaching form is **lengthscale-first** (`ExpQuad` / default `RBF` mode). GPc’s historical SE is MATLAB-style **`inverseWidth`** on `CRbfKern`. CIP-0014 already converts `rbf.lengthscale` ↔ `inverseWidth` at the path boundary, but there is no explicit GPc type whose GPy identity is ExpQuad, and docs/CLI still present `inverseWidth` as the native story.

Users matching GPy care that setting \(\ell\) means the same thing as in ExpQuad—not that we reimplement \(K_of_r\). RBF in GPy is a sibling with extras (psi, optional `inv_lengthscale`), not a parent wrapper around ExpQuad; GPc can keep one engine and still expose ExpQuad’s parameterisation as the GPy-compat primary.

## Detailed Description

### Parameterisation contract (primary)

| Layer | EQ / ExpQuad (this CIP) | Existing `rbf` |
| --- | --- | --- |
| GPy-facing primary params | `lengthscale` \(\ell\), `variance` | same via CIP-0014 paths; indexed API still `inverseWidth` |
| Formula | \(r=\sqrt{\sum (x_q-x'_q)^2/\ell_q^2}\), \(k=\sigma^2 e^{-r^2/2}\) | identical maths |
| Storage (allowed) | May keep `inverseWidth` internally via `CRbfKern` | `inverseWidth` |
| Path component | `ExpQuad` (also accept `eq` / `expquad`) | `rbf` |
| Stream type | write `eq`; read `eq` / `ExpQuad` / `expquad` | `rbf` |
| Optional alias leaves | `inv_lengthscale` / `inverseWidth` (identity on storage), as for RBF | same |

Indexed `setParam` / stream field layout for the shared engine may remain `inverseWidth` + `variance` so `.model` layout for the numeric payload stays consistent with RBF; the **GPy surface** (paths, CLI help, Python façade, docs) must present lengthscale-first for `eq`.

### Design

1. **`CEqKern` public subclass of `CRbfKern`**  
   - Constructors: `CRbfKern` then `setType("eq")`, `setName("ExpQuad")`.  
   - `clone()` → `CEqKern*`; `gpyComponentName()` → `"ExpQuad"`.  
   - Inherit compute / grads / psi / WN inducing. Document: GPc `eq` may expose RBF extras (psi) as a **feature super-set** of GPy ExpQuad; formula and lengthscale meaning match ExpQuad.  
   - Path conversion: same `LEAF_RBF_LENGTHSCALE` rules as RBF (`lengthscale` ↔ `inverseWidth`); ensure `typesCompatible` covers `eq` / `ExpQuad` / `expquad`.

2. **Stream / factory**  
   | Wire / CLI | Action |
   | --- | --- |
   | write | `type: eq` |
   | read | `eq`, `ExpQuad`, `expquad` → `CEqKern` |
   | param payload | same fields as RBF (`inverseWidth`, `variance`) unless a stream version bump is justified; document mapping to \(\ell\) in docs |

3. **Paths**  
   - Canonical: `ExpQuad.lengthscale`, `ExpQuad.variance`.  
   - Do **not** path-alias `eq` ↔ `rbf` components (GPy keeps distinct names).  
   - `paramPaths()` for an `eq` leaf lists GPy lengthscale/variance forms first.

4. **CLI**  
   - `-k eq` constructs `CEqKern`.  
   - Prefer documenting / accepting lengthscale-oriented flags where the tool already has them; where only `-g` inverse-width exists today, either accept the same for `eq` with a help note that GPy units are lengthscale via `-P ExpQuad.lengthscale=…`, or add a lengthscale flag in the same PR if cheap. Do not invent `eqard`; ARD stays `rbfard`.

5. **Python façade (CIP-001D)**  
   - Prefer examples that set `ExpQuad.lengthscale` / construct EQ when showing GPy→GPc. Optional; must not block C++ close.

6. **Verification**  
   - Set \(\ell\) via path on `CEqKern`; compare \(K\) to `CRbfKern` with `inverseWidth=1/\ell^2` and to the ExpQuad formula.  
   - Stream round-trip keeps `type == "eq"`.  
   - Path smoke for `ExpQuad.lengthscale`.  
   - No new matio fixture required if EQ↔RBF + path tests cover Assert and Verify.

### Alternatives considered

- **Naming-only alias without stressing lengthscale** — Rejected as the primary story; user intent is GPy parameterisation.  
- **Change `CRbfKern` indexed storage to lengthscale** — Out of scope for this CIP (breaks streams / MATLAB fixtures); keep conversion at boundary.  
- **Duplicate `K_of_r`** — Rejected.  
- **Rename `rbf` → `eq`** — Rejected.  
- **`eqard`** — Deferred.

### Tenet notes

- **Interoperate With the GP Ecosystem** — ExpQuad lengthscale-first at the boundary.  
- **Compose Through Interfaces** — `CEqKern` fulfils `CKern` via inheritance.  
- **Flexibility Without a Performance Tax** — shared engine; conversion off the SCG hot path (paths only).  
- **Assert and Verify** — \(\ell\)→\(K\) vs RBF-equivalent width; stream/path checks.

## Implementation Plan

1. **Core** — `CEqKern`; `typesCompatible` / `gpyComponentName`; factory read aliases; confirm lengthscale path conversion applies to `eq`.  
2. **CLI** — `-k eq`; help text states GPy lengthscale via `-P ExpQuad.lengthscale=…` (and any flag polish).  
3. **Tests** — lengthscale set → \(K\) matches RBF at \(w=1/\ell^2\); stream type preserved; `ExpQuad.*` paths.  
4. **Docs** — `docs/param-paths.md`: ExpQuad row; note EQ = lengthscale-primary SE, RBF engine + MATLAB storage.  
5. **Python (optional same PR)** — façade example with ExpQuad paths.

## Backward Compatibility

- Additive. `rbf` streams, indexed APIs, and paths unchanged.  
- `equals(eq, rbf)` false by type even when params match.

## Testing Strategy

- `testParamPaths` (or equivalent): `ExpQuad.lengthscale` get/set.  
- `testKern` (or small unit): EQ vs RBF matrix equality at equivalent \(\ell\) / \(w\).  
- Manual: `gp learn -k eq -P ExpQuad.lengthscale=…` and confirm saved `type: eq`.
