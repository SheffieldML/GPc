# CIP-0025: BLAS-owned distances and OpenMP bulk K(r) — parallelism without a GPc thread pool

> CIPs describe HOW to achieve requirements (WHAT). This CIP implements [REQ-0013](../requirements/req0013_intra-eval-kernel-parallelism.md) and continues the competitive-kernel work of [REQ-0007](../requirements/req0007_competitive-default-build.md) / [CIP-0013](./cip0013.md). It **takes ownership of CIP-0013 P7** (threading study) and finishes the P4 GEMM distance form that the stationary base still lacks. The L2/L3 safety contract stays in [CIP-001F](./cip001F.md) / [REQ-0010](../requirements/req0010_documented-concurrency-contract.md); this CIP is L4 only.

## Summary

Parallelise **inside one evaluation** of stationary covariance without GPc managing threads:

1. **BLAS-owned work** — express bulk squared distances as GEMM (\(-2XX_2^\top\) + row norms), so multi-threaded OpenBLAS can parallelise them; keep linear kernels on `gemm` / `syrk`.
2. **OpenMP over radial maps** — optional `#pragma omp parallel for` on disjoint rows of `fillSymWorkspace` / `fillRectWorkspace` (and related \(K(r)\) / gradient shells), with the OpenMP runtime owning the pool.

Default builds and the published one-thread bench protocol remain correct. Same-instance concurrent model APIs stay rejected.

**Which requirements?** [REQ-0013](../requirements/req0013_intra-eval-kernel-parallelism.md) (primary); [REQ-0007](../requirements/req0007_competitive-default-build.md) (performance posture / harness).

## Motivation

[CIP-0013](./cip0013.md) landed OpenBLAS defaults, `CStationaryKern`, and a per-evaluation \(r^2\)/\(K\) workspace. The hot path for isotropic stationary kernels is still a **serial double loop** in `fillSymWorkspace` / `fillRectWorkspace` (`CKern.cpp`). CIP-0013 P4 already named the GPy-shaped fix — `dgemm` for distances when \(q\) or the block is large — but the implementation kept the scalar `dist2Active` loop. P7 (multi-threaded OpenBLAS + OpenMP over bulk kernel loops) was left as an optional study and never owned by a follow-on CIP.

Users who do not want to manage threading still have two library-owned levers:

| Lever | Who owns threads | What it speeds |
|-------|------------------|----------------|
| Raise `OPENBLAS_NUM_THREADS` (or vendor equiv.) | OpenBLAS / vendor BLAS | GEMM distances, `syrk`/`gemm` linear kernels, Cholesky / TRSM after \(K\) |
| Build with OpenMP (`-fopenmp`) | OpenMP runtime | Element-wise \(K(r)\), `sqrt`/`exp`, and residual scalar distance loops |

Hand-rolled `std::thread` pools, mutexes around `logLikelihood`, or sharing one `CKern` workspace across app threads would fight [CIP-0009](./cip0009.md) caches and Flexibility Without a Performance Tax. This CIP deliberately avoids those.

## Detailed Description

### Standards ladder placement

| Level | Meaning | Owner |
|-------|---------|-------|
| L1 | One instance, one owning thread | CIP-0009 (done) |
| L2–L3 | Multi-instance + RNG + BLAS nesting docs | CIP-001F / REQ-0010 |
| **L4** | Parallelism **inside** one evaluation | **This CIP** |
| L5 | Same-instance concurrent / mutexed API | Rejected |

Workers under OpenMP are **not** a second “owning” thread for the model graph: they only write **disjoint rows** of evaluation scratch that the owning thread allocated and will read after the parallel region. The CIP-0009 cache protocol is unchanged.

### Track 1 — BLAS-owned distances (and existing BLAS kernels)

**Target.** For default full-width stationary blocks (no `activeDims` ICM slice), compute unscaled

\[
R_{ij}^2 = \|x_i\|^2 + \|x'_j\|^2 - 2\, x_i^\top x'_j
\]

via row-norm vectors + one `gemm` (`CMatrix::gemm` / underlying `dgemm`), then clamp \(R_{ij}^2 \ge 0\) and set the symmetric diagonal to exactly 0 (GPy / CIP-0013 numerics). Apply `scaleFactor()` and `K_of_r` to fill `m_workK*`.

**When to use GEMM vs scalar.** Keep the small-\(q\) scalar loop (CIP-0013 P3) when profiled GEMM overhead loses — typically \(q = 2\) on the published protocol. Threshold is a compile-time or runtime cutoff documented beside the bench table (e.g. switch at \(q \ge 8\) or \(n\cdot q\) above a measured knee). ICM / non-default `activeDims` may stay on `dist2Active` until a sliced GEMM is worth it.

**Linear kernels.** No change to `CLinKern::compute` (`syrk` / `gemm`); document that raising BLAS threads already parallelises those paths and post-\(K\) LAPACK.

**Nesting.** If OpenMP Track 2 is enabled for the same evaluation, set BLAS to **one** thread for that process (or document a measured override). Matches CIP-001F nesting intent and current `OPENBLAS_NUM_THREADS=1` bench practice when the “application” (here: OpenMP) is already multi-threaded.

### Track 2 — OpenMP over bulk \(K(r)\) / workspace rows

**Target.** Behind an explicit build flag (e.g. `GPC_OPENMP=1` → `-fopenmp` in `make.linux` / `make.osx` and optional CMake option), parallelise the **outer** index of:

- `CStationaryKern::fillSymWorkspace` / `fillRectWorkspace` (after or instead of GEMM for the distance stage, depending on track-1 choice)
- Copy-out loops in `compute` if they remain hot
- Gradient shells that stream the workspace row-wise, **only** where each thread writes disjoint outputs (no shared reductions without a correct OpenMP reduction or post-region combine)

**Constraints.**

- No OpenMP inside `CGp` cache ensure paths beyond what the kernel already does; one evaluation still looks single-threaded from the optimiser’s point of view.
- Debug builds may assert the owning thread around model entry; worker threads must not call `invalidateCache` / mutators.
- Default CI / matio / `OPENBLAS_NUM_THREADS=1` q=2 protocol builds **without** requiring OpenMP, so contributors without libomp stay green.

**Study matrix (was CIP-0013 P7).** Record wall times for FTC / VarDTC / FITC at 1, 2, and “all” threads for: (a) BLAS-only, (b) OpenMP-only with BLAS=1, (c) both only if measured safe. Publish beside the existing harness docs; do not change REQ-0007’s one-thread acceptance bar.

### Rejected alternatives

- Custom GPc thread pool or task queue for kernel tiles
- `std::mutex` on `CKern` / `CGp` hot paths
- Making one `CGp` free-threaded or releasing the Python GIL for this CIP
- Replacing OpenBLAS with a second dense stack to get parallelism
- Forcing OpenMP on in every default release build without a documented switch

### Tenet trade-offs

- **LAPACK Owns the Linear Algebra**: distance GEMM is the default large-\(q\) path; we do not hand-roll a threaded GEMM.
- **Flexibility Without a Performance Tax**: OpenMP stays optional; no mutex tax on the single-thread path.
- **Assert and Verify**: element-wise oracle + matio; threaded configs must not ship without agreement checks.
- **Compose Through Interfaces**: changes live in `CStationaryKern` (and build flags); `CGp` keeps calling `pkern->compute`.

## Implementation Plan

1. **Track 1 — GEMM distances**
   - Add helpers on `CStationaryKern` (or thin `CMatrix` helpers) for row squared-norms + `gemm` rectangular/symmetric \(R^2\).
   - Wire `fillSymWorkspace` / `fillRectWorkspace` to choose GEMM vs scalar by \(q\) / size; clamp and zero diagonal.
   - Keep `computeElement` as oracle; extend `testKern` coverage for near-duplicates and both branches.

2. **Track 2 — OpenMP build + pragmas**
   - Add `GPC_OPENMP` (make + thin CMake mirror); document in README / `docs/build-and-ci.md`.
   - Parallelise disjoint-row fills; verify no data races on workspace members (rows only; epoch flags set after the parallel region).
   - Force / document `OPENBLAS_NUM_THREADS=1` when OpenMP is on for the same process.

3. **Measurement and docs**
   - Extend bench notes with thread-count columns for Track 1 / Track 2.
   - Update [docs/numerics.md](../docs/numerics.md) L4 pointer from “CIP-0013 P7” to this CIP; keep L1–L3 in CIP-001F.
   - Mark CIP-0013 P7 as superseded by this CIP (study delivered or abandoned with numbers).

4. **Close gate**
   - Matio + `testKern` green; REQ-0013 acceptance criteria checked; REQ-0007 one-thread protocol not regressed.

## Backward Compatibility

- Binary / API: no public `CKern` signature changes required.
- Behaviour: numerical agreement within `MATCHTOL`; GEMM cancellation handled by clamp (same as GPy intent).
- Build: OpenMP off by default unless `GPC_OPENMP=1`; existing `make` / CI unchanged until explicitly enabled.
- Env: users who already set `OPENBLAS_NUM_THREADS` keep that lever for Track 1; nested-thread guidance is documentation, not a silent process-wide `omp_set_num_threads` in library init (prefer documented env / bench wrappers).

## Testing Strategy

- **Correctness**: `testKern` bulk vs `computeElement`; matio reference suite; near-duplicate \(X\) rows.
- **Threading**: build with `GPC_OPENMP=1`; run kernel tests under 1 and \(N\) OpenMP threads; optional TSAN job is nice-to-have, not a close blocker.
- **Performance**: `make RELEASE=1 bench` + `bench/run_bench.py` with recorded `OPENBLAS_NUM_THREADS` / `OMP_NUM_THREADS`; one-thread numbers remain the REQ-0007 gate.
- **Nesting smoke**: one documented run with OpenMP>1 and OpenBLAS>1 only to record whether it helps or hurts — not a CI gate.
