## Summary

Extend Probabilistic Point Assimilation beyond dense \(N\times N\) by driving the EM M-step and E-step **mean** updates through [`CGp`](../CGp.h) sparse approximations (DTC first; FITC/PITC optional; DTCVAR for a principled bound). CIP-0023 explicitly listed sparse/inducing PPA as a non-goal; this CIP opens that work with evidence from a parallel `CSparsePpa` prototype.

**Which requirements?** [REQ-0002](../requirements/req0002_runnable-verification.md) (runnable verification for a new approximation path). Builds on CIP-0023 (dense PPA), CIP-0012/001B/001C (sparse factorisation / inducing).

## Motivation

Dense PPA is \(O(N^3)\) and allocates several \(N\times N\) matrices. The EM structure already isolates a Gaussian regression on pseudo-targets \(\langle f\rangle\) with noise \(1/\beta\). That is exactly what `CGp` implements for DTC/FITC/PITC/DTCVAR. Reusing `CGp` avoids a second sparse-GP stack and inherits inducing optimisation and white-noise inducing features.

Without a CIP, merging the prototype into `./ppa` would silently violate CIP-0023’s non-goals and ship without a sparse objective.

## Detailed Description

### Algorithm mapping

PPA places Gaussian sites between the GP latent \(\bar f\) and the non-Gaussian likelihood: \(f = \bar f + \varepsilon\), \(\varepsilon\sim\mathcal{N}(0,\beta^{-1})\).

| Step | Dense today (`CPpa`) | Sparse via `CGp` |
|------|----------------------|------------------|
| M-step | `kernelLogLikelihood` = LML of \(K+\beta^{-1}I\) on \(\langle f\rangle\) | `CGp::logLikelihood` / optimiser with targets \(\langle f\rangle\), fixed \(\beta\) |
| E-step mean | \(\langle\bar f\rangle = K(K+\beta^{-1}I)^{-1}\langle f\rangle\) | `CGp::posteriorMean` at training \(X\) |
| Sites | `noise` with `varSigma = 1/\beta` | unchanged (outer `CNoise`) |
| Monitor | `approxLogLikelihood` uses \(K^{-1}\), \(\mathrm{tr}(K^{-1}\langle\bar f\bar f^\top\rangle)\) | **undefined** for rank-\(M\) priors; need new bound (DTCVAR-shaped) |

### Prototype evidence (`prototype-sparse-ppa`)

See [`prototype_notes.md`](cip0026/prototype_notes.md). Hard results:

1. DTC with \(M=N\), \(X_u=X\), **RBF+Bias only**, matches dense `CPpa` through multiple E-steps.
2. Requested `CGp::FTC` must remap to DTC(\(M=N\)): FTC never adds \(\beta^{-1}I\).
3. **`CWhiteKern` cross-covariance is zero**, so DTC \(M=N\) does **not** recover dense when white is in the compound kernel. Phase-0 fixtures use white → not a valid M=N oracle. Keep observation noise in \(\beta\) for sparse PPA (or teach white cross terms later). **[CIP-0027](cip0027.md)** proposes moving FTC measurement noise into `CNoise`/\(\beta\) and deprecating default White — that removes this carve-out once defaults flip.
4. Init match with \(\langle f\rangle=0\) is vacuous for the GP mean; assert after ≥2 E-steps.

### Design (productionise)

- Keep dense `CPpa` as the CIP-0023 path.
- Promote `CSparsePpa` (or fold a sparse mode into `CPpa` behind an approx enum) with owned mutable \(X\), \(\langle f\rangle\); shared or synced `CKern`; outer `CNoise`; inner Gaussian for `CGp` only.
- Scalar \(\beta\) only (matches CIP-0023 Phase 1 and `CGp`).
- Approximation order: DTC → FITC/PITC smoke → **DTCVAR bound** for monitoring / convergence.
- Do not allocate dense `invK` / `fBarfBar` on the sparse path.
- Stream: new `ppaVersion` fields for approx type + inducing; bump when CLI merges.
- Prediction: `CGp::posteriorMeanVar` then outer `noise.out`.

### Tenets

- **Compose through interfaces** — reuse `CGp` / `CKern` / `CNoise`.
- **Assert and verify** — DTC \(M=N\) vs dense; gradient checks via `CGp::checkGradients`; no fake monotone check until the bound exists.
- **Flexibility without a performance tax** — sparse path must drop \(N\times N\) stores.
- **Ecosystem** — dense `.model` unchanged; version-bump for sparse.

## Implementation Plan

1. **Accept this CIP** after review of prototype notes.
2. **Phase A — Production DTC loop**: land `CSparsePpa` (or equivalent) on main; `testSparsePpa` as a matio-free gate; document no-white / \(\beta\) convention.
3. **Phase B — Sparse storage & CLI**: optional `./ppa learn --approx dtc -a M`; stream version bump; quiet `CGp` logging.
4. **Phase C — DTCVAR PPA bound**: re-derive monitor over \(q(u)\); replace dense `approxLogLikelihood` on the sparse path; convergence check.
5. **Phase D (optional)**: FITC/PITC; inducing optimisation; white-noise inducing (CIP-001C) with PPA sites.

## Backward Compatibility

- Dense `./ppa` / `CPpa` / Phase-0 fixtures unchanged.
- Sparse is opt-in (new type or CLI flags).
- Old dense `.model` files remain loadable; sparse models need a higher `ppaVersion`.

## Testing Strategy

- `testSparsePpa`: DTC \(M=N\) vs dense (no white); FTC remap; \(M<N\) smoke; white-kernel drift document.
- `checkGradients` on inner `CGp` M-step.
- After Phase C: bound finite for \(M<N\); optional monotonicity on controlled problems.
- Do **not** require Nat King MATLAB sparse fixtures (none exist).
