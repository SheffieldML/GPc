# CIP-0027: GPy-aligned defaults — noise in `Gaussian_noise.variance`; drop auto White/Bias

## Summary

Align GPc’s default Gaussian regression (and related CLI/demo/Python builds) with GPy: **observation noise lives at `Gaussian_noise.variance`**; **do not auto-append White or Bias**. Deprecate the old defaults with warnings. **IVM keeps trained White** as the softener (B′ documents the exception; see [`ivm_softener.md`](cip0027/ivm_softener.md)). Trainable probit scale and EP/`CGp` classification defer to a later **non-linear likelihoods** CIP.

**Which requirements?** [REQ-0014](../requirements/req0014_observation-noise-in-likelihood.md). Also supports GPy path/tutorial/façade parity ([REQ-0008](../requirements/req0008_gpy-like-parameter-access.md), [REQ-0009](../requirements/req0009_gpy-tutorial-parity-native.md), [REQ-000E](../requirements/req000E_gpy-facing-python-facade.md)).

## Motivation

Three stacks currently disagree:

| Path | Where measurement noise lives today |
|------|-------------------------------------|
| FTC `CGp` | Diagonal of \(K\) via auto-added **White** (`gp.cpp`, demos, Python `GPRegression`) |
| Sparse `CGp` | **\(\beta\)** on sites / likelihood; White in \(K\) is optional and breaks \(K_{uf}\) consistency |
| Dense / sparse PPA | **\(\beta^{-1}I\)** on the Gram + outer `CNoise`; CIP-0026 says “keep noise in \(\beta\)”, strip White for M=N gates |

GPy defaults are RBF-only for both `GPRegression` and `GPClassification` (Bernoulli + probit link); Bias and White are opt-in. GPy’s advice for Gaussian noise is `likelihood.variance`, not White ([GPy #506](https://github.com/SheffieldML/GPy/issues/506)). Matching that removes double-counting, makes CIP-0026’s DTC \(M=N\) oracle the normal case, and stops teaching a GPc-only noise story.

## Detailed Description

### Locked design choices (2026-11-18)

1. **Canonical storage / path for Gaussian observation noise:** `Gaussian_noise.variance` (GPy/`paramz` spelling). Sparse \(\beta\) remains the internal precision where the sparse algebra needs it; expose `Gaussian_noise.variance` as the user-facing get/set (with \(\beta = 1/\sigma^2\) sync). Do **not** teach `beta` as the primary FTC regression path.
2. **IVM softener = trained White (preferred exception).** IVM uses `CProbitNoise` (not Heaviside+White as the likelihood). Probit \(\sigma^2\) is fixed at \(10^{-6}\); trainable noise params are bias only. Softness that is **trained** enters via **White in \(K\)**, and `CIvm::updateM` must call `getWhite()` because `CWhiteKern::computeElement` is always zero. **CIP-0027 prefers to keep trained White on the IVM path** after Phase B′ confirms it is load-bearing (expected). Dropping IVM White, training probit \(\sigma^2\), or GPy-style Bernoulli+EP on `CGp` are **not** delivery goals here — they belong to a larger **non-linear likelihoods** CIP (see below and [`ivm_softener.md`](cip0027/ivm_softener.md)).
3. **Bias auto-append (regression / PPA / Python):** stop it with White — GPy does not auto-add Bias. For **IVM**, Bias auto-append is decided in B′ (probit already has bias offsets; kernel Bias may be redundant). Explicit `+ Bias` / `+ White` remain supported everywhere.

### Target model (end state)

For spherical Gaussian observation noise:

\[
p(y \mid f) = \mathcal{N}(y; f, \sigma^2 I), \qquad \beta = 1/\sigma^2.
\]

- **FTC**: factor \(K_{\text{signal}} + \sigma^2 I\) after `pkern->compute`, with \(\sigma^2\) from `CGaussianNoise` / path `Gaussian_noise.variance` (same Gram pattern as `CPpa::kernelLogLikelihood`).
- **Sparse**: algebra stays on \(\beta\); path alias `Gaussian_noise.variance` ↔ \(1/\beta\).
- **PPA**: unchanged maths (\(\beta\) + outer `CNoise`); CLI stops auto-appending White and Bias.
- **`CWhiteKern` / `CBiasKern`**: remain real kernels for explicit prior structure; **not** appended by default for Gaussian regression / PPA / Python FTC.
- **IVM**: keep trained White as the softener unless B′ overturns that (unlikely); document the exception next to GPy-aligned regression defaults.
- **CIP-001C** white-noise **inducing** (`--inducing whitenoise`) is orthogonal — do not rename or fold into this CIP.

### Deprecation strategy

| Phase | Behaviour |
|-------|-----------|
| **A — Dual-path + warn** | FTC takes \(\sigma^2\) from `Gaussian_noise.variance` and adds it on the Gram. Warn (verbosity ≥ 1) if a trainable White is also present while Gaussian variance is free. Warn if constructors/CLI still auto-append Bias/White (once dual path exists). Legacy White-only noise models keep working under a documented fallback rule. |
| **B — Defaults flip (regression / PPA / demos / Python)** | `gp.cpp`, `ppa.cpp`, `demo_regression_1d`, Python `GPRegression`: stop auto-`addKern` of White **and** Bias. Default compound = user-requested kernels only (CLI default remains RBF if none given). Tutorials and CIP-001D match GPy. **`ivm.cpp` is not flipped here.** |
| **B′ — IVM evidence + document exception** | Run composition tests ([`ivm_softener.md`](cip0027/ivm_softener.md) matrix). **Expected outcome:** keep auto White for IVM; optionally drop auto Bias; write the exception into `docs/tutorials/ivm_*.md` and CLI help. Optional spike: trainable probit \(\sigma^2\) — evidence only for the future non-linear-likelihoods CIP. |
| **C — Tighten** | Optional `--allow-white-and-noise` for **Gaussian regression** (White + `Gaussian_noise.variance`). Soak; then drop dual interpretation if any. |

### FTC implementation sketch

1. Own \(\sigma^2\) on `CGaussianNoise`; include it in FTC `CGp` optimisable params; path `Gaussian_noise.variance` (and legacy alias `sigma2` if useful).
2. Sync sparse \(\beta \leftrightarrow \sigma^2\) when approximation is sparse and noise is Gaussian.
3. After `pkern->compute(K, *pX)`, add \(\sigma^2\) on the diagonal before `jitChol`.
4. Gradients w.r.t. \(\sigma^2\); kernel grads on the noise-augmented inverse.
5. Equivalence gate: FTC RBF + `Gaussian_noise.variance=σ²` (no White) ≡ legacy FTC RBF+White(\(σ²\)) with noise variance fixed out of the way, within `ndlutil::MATCHTOL`.

### PPA / sparse consistency

After Phase A–B: FTC, sparse `CGp`, and PPA share \(K_{\text{signal}} + \sigma^2 I\) (via \(\beta\) internally where needed). CIP-0026’s “FTC never adds \(\beta^{-1}I\)” / “strip White for M=N” notes become obsolete for the Gaussian path — update when this lands.

### IVM softener (summary; full write-up in [`ivm_softener.md`](cip0027/ivm_softener.md))

- **Not** “threshold + White” as the likelihood — it is **probit** with fixed tiny \(\sigma^2\), plus **trained White in \(K\)** consumed via `getWhite()`.
- White-in-\(K\) ≢ scaled probit ≢ Heaviside+latent noise when \(K\) is correlated.
- Training probit \(\sigma^2\) can plug into the existing `noiseIters` M-step (site approx already depends on \(\sigma^2\)) — that is **not** the same as full EP, and is **deferred**.
- GPy `GPClassification` (Bernoulli + EP + RBF) is the long-term ecosystem target for a **non-linear likelihoods** CIP, not a silent IVM default flip in 0027.

### Deferred: non-linear likelihoods CIP (placeholder)

Out of scope for 0027; spawn when ready (next free CIP id at Accept time or later):

- Trainable likelihood scales / temperatures (`CProbitNoise` \(\sigma^2\), ordered, ncnm, …) with verified grads under IVM and/or PPA sites.
- EP / Laplace / other non-conjugate inference on `CGp` (GPy classification parity).
- Clear story for when softness lives in \(K\) (White) vs in the likelihood vs in site \(\beta\).

CIP-0027 only documents the IVM White exception and leaves hooks (B′ spike, tutorial notes) for that work.

### Tenets

- **Ecosystem interoperability** — GPy paths and defaults.
- **Compose through interfaces** — noise via `CNoise`; kernels opt-in.
- **Assert and verify** — legacy↔new FTC equivalence; IVM composition gates; sparse M=N without White carve-out.

## Implementation Plan

1. **Accept REQ-0014 + this CIP.**
2. **Phase A**: FTC + `Gaussian_noise.variance` on Gram; path façade; deprecation warnings; equivalence test.
3. **Phase B**: Flip regression/PPA/demo/Python defaults (no auto White, no auto Bias); docs; CIP-0026 note update.
4. **Phase B′**: IVM composition tests; **document keep-White exception** (and Bias decision); optional trainable-probit spike as evidence only.
5. **Phase C**: Optional harden + soak for Gaussian regression dual noise.
6. **Later (separate CIP):** non-linear likelihoods / EP-style classification integration.

## Backward Compatibility

- White-/Bias-bearing `.model` files still load; warnings point at `Gaussian_noise.variance`.
- Default compound change for regression/PPA/Python is the user-visible break — Phase B release notes.
- IVM keeps White by design under this CIP; no surprise classification default flip.

## Testing Strategy

- Path tests: `Gaussian_noise.variance` get/set; sparse alias to \(\beta\).
- `testSparsePpa`: M=N without White carve-out once FTC noise-on-Gram exists.
- **IVM (B′)**: matrix in [`ivm_softener.md`](cip0027/ivm_softener.md); results → `cip/cip0027/ivm_kernel_composition.md`.
