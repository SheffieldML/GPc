## Summary

Put observation noise on the **likelihood**, with a **canonical parameter** `likelihood.variance` and GPy1 spelling `Gaussian_noise.variance` as an **alias** ([target architecture](../docs/target-architecture.md) rule 7). Stop auto-appending White or Bias for Gaussian regression / PPA / Python FTC. Deprecate the old defaults with warnings. **IVM keeps trained White** as the softener (B′ documents the exception; see [`ivm_softener.md`](cip0027/ivm_softener.md)).

**Amendment (2026-11-20):** retarget from “match GPy1 defaults” to “conform to the shared GPc / GPy2 target architecture, with GPy1 names as aliases.” Add **Phase 0** (likelihood naming + batched likelihood API sketch; no new state on likelihoods — rule 2). Expand **Phase A** so every model that carries Gaussian observation noise owns it on the likelihood (not only FTC). Stripping targets / sites out of `CNoise` remains a **follow-on CIP** (rules 1, 3, 4).

Trainable probit scale and EP/`CGp` classification stay deferred to that follow-on / non-linear likelihoods work.

**Which requirements?** [REQ-0014](../requirements/req0014_observation-noise-in-likelihood.md). Also supports GPy path/tutorial/façade parity ([REQ-0008](../requirements/req0008_gpy-like-parameter-access.md), [REQ-0009](../requirements/req0009_gpy-tutorial-parity-native.md), [REQ-000E](../requirements/req000E_gpy-facing-python-facade.md)).

## Motivation

Three stacks currently disagree:

| Path | Where measurement noise lives today |
|------|-------------------------------------|
| FTC `CGp` | Diagonal of \(K\) via auto-added **White** (`gp.cpp`, demos, Python `GPRegression`) |
| Sparse `CGp` | **\(\beta\)** on sites / likelihood; White in \(K\) is optional and breaks \(K_{uf}\) consistency |
| Dense / sparse PPA | **\(\beta^{-1}I\)** on the Gram + outer `CNoise`; CIP-0026 says “keep noise in \(\beta\)”, strip White for M=N gates |

GPy1 defaults are RBF-only for both `GPRegression` and `GPClassification`; Bias and White are opt-in; advice for Gaussian noise is `likelihood.variance`, not White ([GPy #506](https://github.com/SheffieldML/GPy/issues/506)). That still matters for ecosystem familiarity — but the durable target is the [shared architecture](../docs/target-architecture.md): likelihoods are parameters plus batched functions; one canonical parameterisation (variance) with \(\beta\) derived where the algebra wants it; GPy1 path spellings as aliases. Matching that removes double-counting, makes CIP-0026’s DTC \(M=N\) oracle the normal case, and stops teaching a GPc-only noise story that a JAX GPy2 would not copy.

## Detailed Description

### Relation to the target architecture

| Architecture rule | What CIP-0027 does | What it deliberately does **not** do |
|---|---|---|
| **2** — Likelihoods are parameters + batched functions; no data / mutable inference state | **Phase 0:** name the batched surface (`log_density`, `variational_expectations`, …); ensure new work adds **no** state to likelihoods | Move `py` / `mu` / `varSigma` / sites out of `CNoise` (follow-on CIP) |
| **7** — Canonical tree; GPy1 names as aliases | **Phase A:** `likelihood.variance` canonical; `Gaussian_noise.variance` alias; \(\beta = 1/\sigma^2\) internal | Teach `beta` as the primary user-facing FTC path |
| **4** — Inference state belongs to inference | Document IVM White softener as inference/kernel exception; keep sites where they are for now | Relocate EP/ADF/PPA sites (follow-on) |

Reviewer checklist items from the architecture note that apply to every 0027 PR: no new per-point storage on the likelihood; no new per-element virtuals on hot paths; new noise params on the canonical tree with one parameterisation.

### Locked design choices (2026-11-18; amended 2026-11-20)

1. **Canonical storage / path for Gaussian observation noise:** `likelihood.variance`. Alias: `Gaussian_noise.variance` (GPy1/`paramz` spelling via [CIP-0014](cip0014.md)). Sparse \(\beta\) remains the internal precision where the sparse algebra needs it (\(\beta = 1/\sigma^2\) sync). Do **not** teach `beta` as the primary user-facing FTC regression path.
2. **IVM softener = trained White (preferred exception).** IVM uses `CProbitNoise` (not Heaviside+White as the likelihood). Probit \(\sigma^2\) is fixed at \(10^{-6}\); trainable noise params are bias only. Softness that is **trained** enters via **White in \(K\)**, and `CIvm::updateM` must call `getWhite()` because `CWhiteKern::computeElement` is always zero. **CIP-0027 prefers to keep trained White on the IVM path** after Phase B′ confirms it is load-bearing (expected). Dropping IVM White, training probit \(\sigma^2\), or GPy-style Bernoulli+EP on `CGp` are **not** delivery goals here — they belong to the follow-on likelihood / inference CIP (see below and [`ivm_softener.md`](cip0027/ivm_softener.md)).
3. **Bias auto-append (regression / PPA / Python):** stop it with White — neither GPy1 nor the target architecture auto-add Bias. For **IVM**, Bias auto-append is decided in B′ (probit already has bias offsets; kernel Bias may be redundant). Explicit `+ Bias` / `+ White` remain supported everywhere.
4. **No new likelihood state in this CIP.** Phase 0/A/B may add parameters and batched entry points, but must not grow `CNoise`’s per-point data or site storage. Existing copies stay until the follow-on CIP removes them.

### Phase 0 — Likelihood surface (architecture rule 2)

Before flipping defaults, fix the contract this CIP and GPy2 will share:

1. **Naming.** Prefer architecture / GPy2-canonical names for new APIs (`log_density`, `variational_expectations`, `log_predictive_density`, EP moments, predictive moments). Keep existing C++ method names as wrappers or oracles where renaming would be churn without a consumer.
2. **Batched shape.** Working interface takes contiguous blocks \((Y_B,\mu_B,v_B)\) (or \(f_B\) where exact) and writes into caller-provided buffers. Per-element virtuals remain for tests only; do not add new hot-path per-element methods.
3. **Scope of Phase 0 code.** Minimal: document the API on `CNoise` / Gaussian path; add or sketch batched Gaussian helpers used by Phase A FTC Gram noise; **zero** new fields for data or sites.
4. **Out of Phase 0.** Full migration of IVM/PPA/ADF callers onto batched primitives; stripping `py`/`mu`/`varSigma` — follow-on CIP.

### Target model (end state for this CIP)

For spherical Gaussian observation noise:

\[
p(y \mid f) = \mathcal{N}(y; f, \sigma^2 I), \qquad \beta = 1/\sigma^2.
\]

- **FTC**: factor \(K_{\text{signal}} + \sigma^2 I\) after `pkern->compute`, with \(\sigma^2\) from the likelihood (`likelihood.variance` / alias `Gaussian_noise.variance`) — same Gram pattern as `CPpa::kernelLogLikelihood`.
- **Sparse `CGp` / SVGP / related:** algebra stays on \(\beta\); path alias ↔ \(1/\beta\); observation noise is likelihood-owned (Phase A covers every such model that already has a noise/precision knob).
- **PPA**: unchanged maths (\(\beta\) + outer `CNoise`); CLI stops auto-appending White and Bias. PPA’s augmentation \(\beta\) that is **not** observation noise stays as today (architecture note).
- **`CWhiteKern` / `CBiasKern`**: remain real kernels for explicit prior structure; **not** appended by default for Gaussian regression / PPA / Python FTC.
- **IVM**: keep trained White as the softener unless B′ overturns that (unlikely); document the exception next to architecture-aligned regression defaults.
- **CIP-001C** white-noise **inducing** (`--inducing whitenoise`) is orthogonal — do not rename or fold into this CIP.

### Deprecation strategy

| Phase | Behaviour |
|-------|-----------|
| **0 — Likelihood surface** | Batched naming + API sketch; no default flip; no new likelihood state. |
| **A — Dual-path + warn** | Every Gaussian-observation model takes \(\sigma^2\) from the likelihood (`likelihood.variance`, alias `Gaussian_noise.variance`). FTC adds it on the Gram. Warn (verbosity ≥ 1) if a trainable White is also present while Gaussian variance is free. Warn if constructors/CLI still auto-append Bias/White (once dual path exists). Legacy White-only noise models keep working under a documented fallback rule. |
| **B — Defaults flip (regression / PPA / demos / Python)** | `gp.cpp`, `ppa.cpp`, `demo_regression_1d`, Python `GPRegression`: stop auto-`addKern` of White **and** Bias. Default compound = user-requested kernels only (CLI default remains RBF if none given). Tutorials and CIP-001D match GPy1 *names* and the architecture *structure*. **`ivm.cpp` is not flipped here.** |
| **B′ — IVM evidence + document exception** | Run composition tests ([`ivm_softener.md`](cip0027/ivm_softener.md) matrix). **Expected outcome:** keep auto White for IVM; optionally drop auto Bias; write the exception into `docs/tutorials/ivm_*.md` and CLI help. Optional spike: trainable probit \(\sigma^2\) — evidence only for the follow-on CIP. |
| **C — Tighten** | Optional `--allow-white-and-noise` for **Gaussian regression** (White + likelihood variance). Soak; then drop dual interpretation if any. |

### FTC implementation sketch

1. Own \(\sigma^2\) on `CGaussianNoise` / likelihood params; include it in FTC `CGp` optimisable params; path `likelihood.variance` with alias `Gaussian_noise.variance` (and legacy `sigma2` if useful).
2. Sync sparse \(\beta \leftrightarrow \sigma^2\) when approximation is sparse and noise is Gaussian.
3. After `pkern->compute(K, *pX)`, add \(\sigma^2\) on the diagonal before `jitChol`.
4. Gradients w.r.t. \(\sigma^2\); kernel grads on the noise-augmented inverse.
5. Equivalence gate: FTC RBF + `likelihood.variance=σ²` (no White) ≡ legacy FTC RBF+White(\(σ²\)) with noise variance fixed out of the way, within `ndlutil::MATCHTOL`.

### PPA / sparse consistency

After Phase A–B: FTC, sparse `CGp`, and PPA share \(K_{\text{signal}} + \sigma^2 I\) (via \(\beta\) internally where needed). CIP-0026’s “FTC never adds \(\beta^{-1}I\)” / “strip White for M=N” notes become obsolete for the Gaussian path — update when this lands.

### IVM softener (summary; full write-up in [`ivm_softener.md`](cip0027/ivm_softener.md))

- **Not** “threshold + White” as the likelihood — it is **probit** with fixed tiny \(\sigma^2\), plus **trained White in \(K\)** consumed via `getWhite()`.
- White-in-\(K\) ≢ scaled probit ≢ Heaviside+latent noise when \(K\) is correlated.
- Training probit \(\sigma^2\) can plug into the existing `noiseIters` M-step (site approx already depends on \(\sigma^2\)) — that is **not** the same as full EP, and is **deferred**.
- GPy `GPClassification` (Bernoulli + EP + RBF) is the long-term ecosystem target for the **follow-on likelihood / inference CIP**, not a silent IVM default flip in 0027.

### Deferred: follow-on likelihood / inference CIP (placeholder)

Out of scope for 0027; spawn when ready (next free CIP id at Accept time or later). Maps to architecture rules 1, 3, 4:

- Targets, missing mask and normaliser: one data owner; models read batches (rule 1).
- Contiguous blocks only on hot paths (rule 3).
- EP / ADF / PPA sites become inference workspaces over likelihood primitives (rule 4); `CNoise` loses `py`, `mu`, `varSigma`.
- Trainable likelihood scales / temperatures (`CProbitNoise` \(\sigma^2\), ordered, ncnm, …) with verified grads under IVM and/or PPA sites.
- EP / Laplace / other non-conjugate inference on `CGp` (GPy classification parity); new likelihoods via Gauss–Hermite where appropriate.
- Clear story for when softness lives in \(K\) (White) vs in the likelihood vs in site \(\beta\).

CIP-0027 only documents the IVM White exception and leaves hooks (B′ spike, tutorial notes, Phase 0 API names) for that work.

### Tenets

- **Ecosystem interoperability** — GPy1 path aliases; shared GPc / GPy2 decomposition.
- **Compose through interfaces** — noise via likelihood/`CNoise`; kernels opt-in.
- **Assert and verify** — legacy↔new FTC equivalence; IVM composition gates; sparse M=N without White carve-out.
- **Flexibility without a performance tax** — batched contiguous APIs; no new per-element hot paths.

## Backward Compatibility

- White-/Bias-bearing `.model` files still load; warnings point at `likelihood.variance` / `Gaussian_noise.variance`.
- Default compound change for regression/PPA/Python is the user-visible break — Phase B release notes.
- IVM keeps White by design under this CIP; no surprise classification default flip.
- Existing `CNoise` data copies remain until the follow-on CIP (no silent behaviour change from Phase 0 alone).
