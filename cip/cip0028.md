# CIP-0028: Weight-space inducing features for MLP and arc-cosine kernels

> CIPs describe HOW to achieve requirements (WHAT). This CIP extends [REQ-000D](../requirements/req000D_jitter-free-sparse-conditioning.md) beyond the stationary white-noise path of [CIP-001C](./cip001C.md).

## Summary

Add a third inducing-variable family, **weight-space features**, so sparse GPs with **dot-product** kernels (`CMlpKern` / `CMlpardKern`, and a new arc-cosine kernel) get kernel-free \(K_{uu}\) the same way CIP-001C did for stationary kernels.

Inducing variables live on the **weight** measure of the infinite-network representation, not on the input domain. Then \(K_{uu}\) depends only on the weight-space windows; all kernel dependence sits in \(K_{fu}\). Downstream whitened StableFactor / LQ algebra ([CIP-0012](./cip0012.md), [CIP-001B](./cip001B.md)) is unchanged.

This is the CIP-001C “Future CIP” pointer for MLP / network features. Green’s-function / causal features are [CIP-0029](./cip0029.md).

## Motivation

### Gap left by CIP-001C

White-noise inducing with Gaussian windows (and the Hankel spectral path) covers isotropic stationary kernels and RBF-ARD. Explicit non-goals in CIP-001C:

- weight-space features for **dot-product** kernels (`CMlpKern` erf units; arc-cosine / ReLU units);
- anything that needs `domainDim() != inputDim`.

MLP is already a first-class CLI kernel (`-k mlp`) and appears in IVM/GP/PPA help text, but sparse DTCVAR with `--inducing whitenoise` correctly refuses it: there is no L² square-root convolution on the input domain. Point inducing still works, and still inherits the usual \(K_{uu}=k(Z,Z)\) conditioning problems as weight/bias variances grow or inducing inputs cluster in angle.

### Structural fix (same REQ-000D outcome)

Write the MLP (arcsin) kernel as an expectation over Gaussian weights with erf nonlinearities (Williams 1996 / Neal). Place inducing variables on that weight measure:

\[
u_m = \int \psi_m(\mathbf{w})\, w(\mathbf{w})\,\mathrm{d}\mathbf{w},
\]

with fixed windows \(\psi_m\) on \(\mathbf{w}\). Then \(K_{uu}[m,n]=\langle\psi_m,\psi_n\rangle\) is independent of `weightVariance` / `biasVariance` / `variance`. Cross-covariance \(K_{fu}\) becomes a finite network of smoothed erf (or ReLU) units — the finite-width counterpart of the infinite MLP GP.

| Arc-cosine | Absent | New `CArcCosineKern` (order 0/1) as `CKern`; order 1 matches ReLU / Cho & Saul |

**Verdict:** Phase 1 is API + MLP closed form (CIP-001C Phase 2 sized). Arc-cosine is Phase 2. No new linear algebra.

### Design principles (tenets)

1. **Compose Through Interfaces** — third `CInducing` implementation; `CGp` dispatches only through the contract.
2. **Assert and Verify** — FD on all new grads; Monte Carlo check of \(K_{fu}\) vs erf features; optional infinite-width limit check (large isotropic Gaussian windows → MLP \(k(\mathbf{x},\mathbf{z})\) up to scale — document the exact limit used as a gate).
3. **LAPACK Owns the Linear Algebra** — reuse StableFactor / LQ; skip nothing special beyond `kuuDependsOnKernel()==false` caching already used by WN.
4. **Flexibility Without a Performance Tax** — closed-form erf / Gaussian integrals for isotropic Gaussian windows; no MC in the hot path.
5. **Ecosystem Interoperability** — naming follows GPflow-style inter-domain / weight-space inducing; arc-cosine type string stable for streams.

### Mathematics (MLP / erf)

Augment inputs \(\tilde{\mathbf{x}}=(\mathbf{x},1)\). The Williams MLP kernel with parameters \((w,b,\sigma^2)\) corresponds to

\[
\mathbf{w}\sim\mathcal N(\mathbf{0},\Sigma),\quad
\Sigma=\mathrm{diag}(w I_d,\, b),\quad
\phi(\mathbf{w},\mathbf{x})=\operatorname{erf}\big(\mathbf{w}^\top\tilde{\mathbf{x}}\big)
\]

(up to the conventional scale that yields `asin` after the Gaussian expectation — match GPc’s existing `CMlpKern::computeElement` exactly).

Take L²-normalised Gaussian windows on weight space centred at \(\hat{\mathbf{w}}_m\) with covariance \(\tilde S\) (scalar width \(s\) times a fixed metric, or diagonal for ARD). The inducing feature for data \(\mathbf{x}\) is the Gaussian expectation of \(\phi\) under \(\mathcal N(\hat{\mathbf{w}}_m,\tilde S)\):

\[
K_{fu}(\mathbf{x},m)
  = c_m\,\sigma\,
    \operatorname{erf}\!\left(
      \frac{\hat{\mathbf{w}}_m^\top\tilde{\mathbf{x}}}
           {\sqrt{1+2\,\tilde{\mathbf{x}}^\top\tilde S\,\tilde{\mathbf{x}}}}
    \right)
\]

(with \(c_m\) the normalisation that makes \(K_{uu}\) the Gram of the windows). This is the formula already sketched in CIP-001C. Implement and pin constants by matching:

1. direct 1-D / low-d MC integration of \(\mathbb E[\phi(\mathbf{w})\psi_m(\mathbf{w})]\) for \(K_{fu}\);
2. analytic \(K_{uu}=\int\psi_m\psi_n\) (same Gaussian-window formula as CIP-001C, now in weight dimension \(d+1\)).

**ARD (`CMlpardKern`):** product / diagonal \(\Sigma=\mathrm{diag}(w_1,\ldots,w_d,b)\) and optional per-coordinate window widths — Phase 1b after isotropic MLP is green.

### Arc-cosine (Phase 2)

Cho & Saul arc-cosine kernels of order \(n\) arise from ReLU\(^n\) features. Order 1:

\[
k_1(\mathbf{x},\mathbf{x}')
  \propto \|\tilde{\mathbf{x}}\|\,\|\tilde{\mathbf{x}}'\|\,
  \big(\sin\theta+(\pi-\theta)\cos\theta\big)/\pi,
\]

with \(\theta=\angle(\tilde{\mathbf{x}},\tilde{\mathbf{x}}')\). Weight-space windows yield **smoothed ReLU** ridge units (Dutordoir et al. 2021 style). New `CArcCosineKern` with `order` in \(\{0,1\}\) (order 0 = angular / erf-adjacent; order 1 = ReLU). Stream type `arccos` / `arccosine`.

### Phase plan

#### Phase 0 — Contract hygiene for `domainDim != inputDim`

CIP-001C reserved `domainDim()` for this follow-on; today both implementations still mirror input dim and `CGp` keeps `X_u` at `inputDim` columns.

- Clarify ownership: weight-space centres are **not** rows of input-space `X_u`. Options (pick one in implementation; prefer A):
  - **A (preferred):** `CInducingWeightSpace` owns `W` (`M × (d+1)`); `centres()` returns `W`; `CGp::X_u` unused / left empty for this type; `isOptimiseX` packs via `getNumParams` on the inducing object only.
  - **B:** Resize `X_u` to `M × domainDim()` and relax stream asserts when `inducingType=weightspace`.
- Update stream I/O: `inducingType=weightspace`, `weightCentres=` (or matio field), `windowWidth=`; absent keys keep points default.
- CLI: `--inducing points|whitenoise|weightspace` and reuse `--window-width` for weight-space \(s\).

Gate: existing point and WN tests unchanged.

#### Phase 1 — MLP isotropic weight-space

- `CInducingWeightSpace` implementing `CInducing` with `kuuDependsOnKernel()==false`, `typeName()=="weightspace"`.
- `CMlpKern::{wsCrossCompute, wsGradParams, wsGradW, wsGradX, wsGradS}` closed form.
- Equivalence / sanity gates:
  - FD grads (`diagWeightSpace` or extend `testCGp`);
  - MC convolution vs closed form (1-D and small \(d\));
  - DTC/DTCVAR finite under StableFactor and LQ with MLP + weight-space;
  - \(\kappa(K_{uu})\) independent of `weightVariance` on a sweep (stability cell `ws_wv_sweep_*`).
- Default \(s\) from median spacing of weight centres; \(s\) fixed unless explicitly learnable (same caution as CIP-001C: learning \(s\) can reintroduce ill-conditioning).

#### Phase 1b — MLP ARD

- `CMlpardKern` ws\* overrides; diagonal window metric optional (start with isotropic \(s\) in weight space even for ARD \(\Sigma\)).

#### Phase 2 — Arc-cosine kernel + weight-space

- Implement `CArcCosineKern` (orders 0 and 1) with `testKern`-style checks / FD; stream factory.
- ws\* path for order 1 (smoothed ReLU); order 0 if the same integral is cheap.
- CLI `-k arccos` (or `arccosine`) with `--arccos-order`.

#### Phase 3 — Polish

- Compound rules documented and enforced with clear errors.
- Meff already exists; ensure weight-space appears in stability suite alongside WN.
- README / `docs/numerics.md` sparse section: when to use points vs whitenoise vs weightspace.
- Compression after Close.

### Explicit non-goals

- Green’s-function / causal Matérn features on the input line ([CIP-0029](./cip0029.md)).
- Deep GP layer stacks / Dutordoir full deep inducing nets (citation only; single-layer MLP/arccos first).
- Psi / Bayesian GP-LVM with weight-space inducing.
- Polynomial kernel weight-space (different feature map; out of scope unless a later CIP).
- Replacing point inducing as default.

### Alternatives considered

1. **Force MLP through Hankel / spectralDensity.** Rejected: MLP is not stationary on \(\mathbf{x}\); Bochner does not apply.
2. **Finite random features as inducing (Rahimi–Recht / sparse spectrum).** Related but different: that approximates \(k\) with random \(\mathbf{w}_m\), whereas here \(\mathbf{w}_m\) (window centres) are variational parameters with kernel-free \(K_{uu}\). Random features can initialise centres.
3. **Hard-code MLP branch in `CGp`.** Rejected (Compose Through Interfaces).
4. **Only ship arc-cosine, treat MLP as legacy.** Rejected: MLP is already in the tree and CLI; users ask for it first.
