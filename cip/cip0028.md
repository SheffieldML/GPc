# CIP-0028: Weight-space inducing features for MLP and arc-cosine kernels

> CIPs describe HOW to achieve requirements (WHAT). This CIP extends [REQ-000D](../requirements/req000D_jitter-free-sparse-conditioning.md) beyond the stationary white-noise path of [CIP-001C](./cip001C.md).

## Summary

Add another inducing-variable family, **weight-space features**, alongside points, white-noise ([CIP-001C](./cip001C.md)), and Green’s ([CIP-0029](./cip0029.md)), so sparse GPs with **dot-product** kernels (`CMlpKern` / `CMlpardKern`, and a new arc-cosine kernel) get kernel-free \(K_{uu}\).

Inducing variables are defined on **unit white noise in weight space**, with the weight prior \(p(\mathbf{w})\) entering only through \(\sqrt{p}\) in \(K_{fu}\) (same REQ-000D pattern as CIP-001C’s \(\sqrt{S}\) factor). Downstream whitened StableFactor / LQ algebra ([CIP-0012](./cip0012.md), [CIP-001B](./cip001B.md)) is unchanged.

This is the CIP-001C “Future CIP” pointer for MLP / network features. The early CIP-001C sketch of the MLP \(K_{fu}\) omitted the \(\sqrt{p}\) factor; the Mathematics section below is authoritative.

## Motivation

### Gap left by CIP-001C

White-noise inducing with Gaussian windows (and the Hankel spectral path) covers isotropic stationary kernels and RBF-ARD. Explicit non-goals in CIP-001C:

- weight-space features for **dot-product** kernels (`CMlpKern` erf units; arc-cosine / ReLU units);
- anything that needs `domainDim() != inputDim`.

MLP is already a first-class CLI kernel (`-k mlp`) and appears in IVM/GP/PPA help text, but sparse DTCVAR with `--inducing whitenoise` correctly refuses it: there is no L² square-root convolution on the input domain. Point inducing still works, and still inherits the usual \(K_{uu}=k(Z,Z)\) conditioning problems as weight/bias variances grow or inducing inputs cluster in angle.

### Structural fix (same REQ-000D outcome)

Write the MLP (arcsin) kernel as a feature expansion over Gaussian weights with erf nonlinearities (Williams 1996 / Neal). Match CIP-001C’s white-noise construction on that weight space: the process is driven by **unit** white noise \(\xi\), and the prior density \(p\) appears under a square root so the covariance recovers \(\int\phi\phi'\,p\):

\[
f(\mathbf{x})
  = \int \phi(\mathbf{w},\mathbf{x})\,\sqrt{p(\mathbf{w})}\,\xi(\mathbf{w})\,\mathrm{d}\mathbf{w},
\qquad
u_m = \int \psi_m(\mathbf{w})\,\xi(\mathbf{w})\,\mathrm{d}\mathbf{w}.
\]

Then \(K_{uu}[m,n]=\langle\psi_m,\psi_n\rangle\) is independent of `weightVariance` / `biasVariance` / `variance`, while \(K_{fu}\) carries all kernel dependence (including \(\Sigma\)) through \(\sqrt{p}\,\psi_m\). The finite-\(M\) posterior mean is a network of smoothed erf (or ReLU) units — the finite-width counterpart of the infinite MLP GP.

**Rejected alternative (breaks REQ-000D):** defining \(u_m=\int\psi_m\eta\) with coloured noise \(\mathrm{Cov}(\eta)=p\) would put \(\Sigma\) into \(K_{uu}\).

### Relation to published inter-domain / activated features

The *general* idea — hidden units of a network as inter-domain inducing variables for dot-product kernels — is published. What CIP-0028 specifically does is apply the **VIK / white-noise window** construction ([Álvarez et al. 2010](https://proceedings.mlr.press/v9/alvarez10a.html); already the spine of [CIP-001C](./cip001C.md)) to the **weight-space white noise** behind Williams’ / Neal’s infinite network. That combination is the claim; “not found elsewhere” is not a proof of novelty, and the deep-kernel / infinite-width literature after 2023 remains a place to keep looking.

**Closest published line (activated / RKHS features):**
- Sun, Shi & Grosse (AABI 2020 workshop) — hidden units as inter-domain inducing points for dot-product kernels on \(\mathbb{R}^d\) and \(S^{d-1}\); synthetic checks of the derivations.
- Dutordoir, Durrande & Hensman (ICML 2020) — map data to the unit hypersphere and use spherical harmonics so covariances between inducing variables are diagonal (spectral groundwork).
- Dutordoir et al. (NeurIPS 2021) — fuller theory: activations as inter-domain inducing features, extended to deep GPs; cites Sun et al. as closest prior work.
- Tiao, Dutordoir & Picheny (ICML 2023) — practical issues and an extension via orthogonal decompositions of GPs.

**How that line differs from CIP-0028:**

| | Dutordoir / Sun activated features | CIP-0028 (VIK on weight measure) |
|---|---|---|
| Inducing definition | RKHS inner product of \(f\) with an activation-shaped feature (often via spherical harmonics) | Window on unit white noise \(\xi\) in weight space: \(u_m=\int\psi_m\xi\) |
| \(K_{uu}\) | Depends on the kernel spectrum (e.g. Gegenbauer series in \(\cos\angle(\mathbf{w}_m,\mathbf{w}_{m'})\) weighted by eigenvalues) | \(\langle\psi_m,\psi_n\rangle\) — **kernel-free** (REQ-000D) |
| Domain | Typically sphere / harmonic truncation | Inputs stay in \(\mathbb{R}^d\); weight space is \(\mathbb{R}^{d+1}\) |
| \(K_{fu}\) | Exact activation-shaped features (series) | Closed-form **smoothed** erf / ReLU (Gaussian windows) |
| Network mean match | Forward pass can match the GP mean exactly | Approaches exact activations only as \(s\to 0\); \(s\) must stay \(>0\) or \(\mathrm{Var}(u_m)\) blows up |
| Conditioning | Spectral \(K_{uu}\) can still ill-condition | \(K_{uu}\) cannot be driven singular by kernel hyperparameters |

So: **VIK applied to the weight measure** — a new combination of two published ideas (activated inter-domain features + white-noise windows), not a new idea from scratch. The \(\sqrt{p}\) factor is what links the windows to the kernel’s weight distribution; it has no counterpart in the RKHS / harmonic construction, and it is what makes finite-\(\Sigma\) MLP weight-space inducing able to learn \(w\) and \(b\).

**Optional comparison (Phase 3 / follow-on):** on a shared arc-cosine problem, compare conditioning and bound quality against Dutordoir-style activated features (GPflow reference exists) to show the REQ-000D advantage in practice. Not a Phase 1 gate.

**Verdict:** Phase 1 is MLP closed form with the corrected \(\sqrt{p}\) path (CIP-001C Phase 2 sized). Arc-cosine is Phase 2. No new linear algebra.

### Design principles (tenets)

1. **Compose Through Interfaces** — new `CInducing` implementation; `CGp` dispatches only through the contract.
2. **Assert and Verify** — FD on all new grads; Monte Carlo oracle is \(\int\phi\sqrt{p}\,\psi\) (not \(\int\phi\psi\)); informative sparse-vs-exact gap as `weightVariance` grows; optional infinite-width / wide-window limit check.
3. **LAPACK Owns the Linear Algebra** — reuse StableFactor / LQ; skip nothing special beyond `kuuDependsOnKernel()==false` caching already used by WN.
4. **Flexibility Without a Performance Tax** — closed-form erf / Gaussian integrals for isotropic Gaussian windows; no MC in the hot path.
5. **Ecosystem Interoperability** — naming follows GPflow-style inter-domain / weight-space inducing; arc-cosine type string stable for streams.

### Mathematics (MLP / erf)

Augment inputs \(\tilde{\mathbf{x}}=(\mathbf{x},1)\). The Williams MLP kernel with parameters \((w,b,\sigma^2)\) corresponds to a feature map

\[
p(\mathbf{w})=\mathcal N(\mathbf{w};\mathbf{0},\Sigma),\quad
\Sigma=\mathrm{diag}(w I_d,\, b),\quad
\phi(\mathbf{w},\mathbf{x})=\operatorname{erf}\big(\mathbf{w}^\top\tilde{\mathbf{x}}\big)
\]

(up to the conventional scale that yields `asin` after the Gaussian expectation — match GPc’s existing `CMlpKern::computeElement` exactly), realised as \(f=\int\phi\sqrt{p}\,\xi\) above.

Take L²-normalised Gaussian windows \(\psi_m\) on weight space centred at \(\hat{\mathbf{w}}_m\) with covariance \(\tilde S\) (scalar width \(s\) times a fixed metric, or diagonal for ARD). Then

\[
K_{uu}[m,n]=\langle\psi_m,\psi_n\rangle
\]

(same Gaussian-window Gram as CIP-001C, now in dimension \(d+1\)), and

\[
K_{fu}(\mathbf{x},m)
  = \int \phi(\mathbf{w},\mathbf{x})\,\sqrt{p(\mathbf{w})}\,\psi_m(\mathbf{w})\,\mathrm{d}\mathbf{w}.
\]

**Gaussian product.** \(\sqrt{p(\mathbf{w})}\propto\exp(-\tfrac14\mathbf{w}^\top\Sigma^{-1}\mathbf{w})\) is an unnormalised \(\mathcal N(\mathbf{0},2\Sigma)\). Multiplying by Gaussian \(\psi_m\) yields an effective Gaussian \(\mathcal N(\boldsymbol{\mu}_m,S_m)\) with

\[
S_m^{-1}=\tilde S^{-1}+(2\Sigma)^{-1},
\qquad
\boldsymbol{\mu}_m=S_m\tilde S^{-1}\hat{\mathbf{w}}_m,
\]

plus a \(\Sigma\)-dependent amplitude \(a_m(\Sigma,\tilde S,\hat{\mathbf{w}}_m)\) from the product of normalising constants and the \(\sqrt{p}\) prefactor. The erf expectation under that Gaussian is closed form:

\[
K_{fu}(\mathbf{x},m)
  = c_m\,a_m\,\sigma\,
    \operatorname{erf}\!\left(
      \frac{\boldsymbol{\mu}_m^\top\tilde{\mathbf{x}}}
           {\sqrt{1+2\,\tilde{\mathbf{x}}^\top S_m\,\tilde{\mathbf{x}}}}
    \right),
\]

with \(c_m\) absorbing L² window normalisation so \(K_{uu}\) stays the plain Gram of the \(\psi_m\).

**Finite \(\Sigma\) vs \(w,b\to\infty\).** As \(\Sigma\to\infty\), \((2\Sigma)^{-1}\to 0\), so \(S_m\to\tilde S\) and \(\boldsymbol{\mu}_m\to\hat{\mathbf{w}}_m\): the simple erf formula without \(\sqrt{p}\) is the **infinite weight/bias-variance limit** of the finite-\(\Sigma\) path, not a rival construction. In that limit \(w\) and \(b\) are not learned (angular / scale-free regime; overall scale stays in \(\sigma^2\)). Softness of units is then controlled by window width \(s\) and input normalisation.

**Two kernels, not one mode flag (Compose Through Interfaces).** Keep both ends of the limit, but as **separate kernel types** rather than a topology-changing switch on `CMlpKern`:

| Kernel | Role | Weight-space \(K_{fu}\) |
|---|---|---|
| `CMlpKern` / `CMlpardKern` | Finite \(\Sigma\); learn `weightVariance` / `biasVariance` | Full \(\sqrt{p}\) Gaussian product \((\boldsymbol{\mu}_m,S_m,a_m)\) |
| `CArcCosineKern` order 0 | Angular / infinite-\((w,b)\) home (Cho & Saul; Williams MLP limit) | Simple smoothed erf / sign-like units (\(\hat{\mathbf{w}}_m,\tilde S\) only) |
| `CArcCosineKern` order 1 | ReLU / arc-cosine | Smoothed ReLU ridge units |

Do **not** add a third MLP class or an `--mlp-infinite` that removes parameters from `CMlpKern` (stream/`getNumParams` churn). Optional Phase 1 **sanity bridge**: freeze large finite \(w,b\) on `CMlpKern` and check `wsCross*` → simple-erf formula; production “infinite” use goes through `-k arccos --arccos-order 0`.

**Why the early CIP-001C sketch must not be the MLP implementation.** Dropping \(\sqrt{p}\) on `CMlpKern` while still exposing learnable \(w,b\) makes those hyperparameters inert in \(K_{fu}\) (apart from overall \(\sigma\)). Implement the product form for MLP; use arc-cosine order 0 when you want the infinite limit explicitly.

**Monte Carlo oracle (Phase 1 gate).** For `CMlpKern`: estimate \(\int\phi\sqrt{p}\,\psi_m\); matching \(\int\phi\psi_m\) alone is a false green. For the large-\((w,b)\) bridge / arc-cosine order 0: the simple integral without \(\sqrt{p}\) is the right oracle.

**ARD (`CMlpardKern`):** product / diagonal \(\Sigma=\mathrm{diag}(w_1,\ldots,w_d,b)\) and optional per-coordinate window widths — Phase 1b after isotropic MLP is green.

### Arc-cosine (Phase 2)

Cho & Saul arc-cosine kernels of order \(n\) arise from threshold / ReLU\(^n\) features on the sphere (or normalised \(\tilde{\mathbf{x}}\)). Order 1:

\[
k_1(\mathbf{x},\mathbf{x}')
  \propto \|\tilde{\mathbf{x}}\|\,\|\tilde{\mathbf{x}}'\|\,
  \big(\sin\theta+(\pi-\theta)\cos\theta\big)/\pi,
\]

with \(\theta=\angle(\tilde{\mathbf{x}},\tilde{\mathbf{x}}')\). Order 0 is the angular / sign counterpart and is the **public kernel** for the \(w,b\to\infty\) MLP limit above. Weight-space windows yield **smoothed** activations (not exact Dutordoir RKHS features). New `CArcCosineKern` with `order` in \(\{0,1\}\). Stream type `arccos` / `arccosine`.
### Phase plan

#### Phase 0 — Contract hygiene for `domainDim != inputDim` (done)

CIP-001C reserved `domainDim()` for this follow-on. Design **A** landed: `CInducingWeightSpace` owns `W` (`M × (d+1)`); `centres()` returns `W`; `CGp::X_u` unused for this type; CLI/stream `inducingType=weightspace` + `windowWidth` / weight centres; `ws*` hooks throw until Phase 1. Points / WN / greens regression green.

#### Phase 1 — MLP isotropic weight-space

- `CMlpKern::{wsCrossCompute, wsGradParams, wsGradW, wsGradX, wsGradS}` closed form with \(\boldsymbol{\mu}_m,S_m,a_m\) as above (not the \(\hat{\mathbf{w}}_m,\tilde S\)-only erf).
- Gates:
  - FD grads (`diagWeightSpace` or extend `testCGp`);
  - MC vs closed form for \(\int\phi\sqrt{p}\,\psi\) (1-D and small \(d\)); explicitly fail a control that matches \(\int\phi\psi\) instead;
  - DTC/DTCVAR finite under StableFactor and LQ with MLP + weight-space;
  - **Informative:** sparse ELBO (or DTCVAR bound) vs exact / dense FTC likelihood gap as `weightVariance` grows with fixed windows (window coverage); record point-inducing contrast;
  - **Sanity only:** \(\kappa(K_{uu})\) flat in `weightVariance` (true by construction of \(K_{uu}=\langle\psi,\psi\rangle\)).
- Default \(s\) from median spacing of weight centres; \(s\) fixed unless explicitly learnable (same caution as CIP-001C: learning \(s\) can reintroduce ill-conditioning).

#### Phase 1b — MLP ARD

- `CMlpardKern` ws\* overrides; diagonal window metric optional (start with isotropic \(s\) in weight space even for ARD \(\Sigma\)). Same \(\sqrt{p}\) Gaussian-product structure with diagonal \(\Sigma\).

#### Phase 2 — Arc-cosine kernel + weight-space

- Implement `CArcCosineKern` (orders 0 and 1) with `testKern`-style checks / FD; stream factory.
- Order 0: infinite-\((w,b)\) / angular weight-space path (simple smoothed units; no learnable \(\Sigma\)).
- Order 1: smoothed ReLU ridge units.
- CLI `-k arccos` (or `arccosine`) with `--arccos-order`.
- Gate: large finite \((w,b)\) on `CMlpKern` ws\* approaches order-0 formula (shared constants documented).

#### Phase 3 — Polish

- Compound rules documented and enforced with clear errors ([CIP-0027](./cip0027.md) reduces accidental Bias/White compounds for regression).
- Stability suite: `ws_wv_sweep_*` emphasises bound/ELBO gap and finiteness; \(\kappa(K_{uu})\) optional sanity.
- README / `docs/numerics.md` sparse section: when to use points vs whitenoise vs greens vs weightspace; MLP vs arccos-0 for finite vs infinite \(\Sigma\).
- Optional: conditioning / bound comparison vs Dutordoir activated features (GPflow) on a shared arc-cosine problem.
- Compression after Close.

#### Follow-on (not this CIP)

- **[CIP-002A](./cip002A.md) SVGP:** teach `CSvgp` to build \(K_{uu}/K_{uf}\) through `CInducing` (as `CGp` already does) so weight-space, white-noise, and greens inducing are available under minibatch SVGP. Small change; track as a CIP-002A backlog task rather than expanding CIP-0028 scope.

### Explicit non-goals

- Green’s-function / causal Matérn features on the input line ([CIP-0029](./cip0029.md) — separate CIP, Closed).
- Deep GP layer stacks / Dutordoir full deep inducing nets (citation only; single-layer MLP/arccos first).
- Psi / Bayesian GP-LVM with weight-space inducing.
- Polynomial kernel weight-space (different feature map; out of scope unless a later CIP).
- Replacing point inducing as default.
- Implementing SVGP×`CInducing` inside this CIP (see Follow-on).

### Alternatives considered

1. **Force MLP through Hankel / spectralDensity.** Rejected: MLP is not stationary on \(\mathbf{x}\); Bochner does not apply.
2. **Finite random features as inducing (Rahimi–Recht / sparse spectrum).** Related but different: that approximates \(k\) with random \(\mathbf{w}_m\), whereas here \(\hat{\mathbf{w}}_m\) (window centres) are variational parameters with kernel-free \(K_{uu}\). Random features can initialise centres.
3. **Hard-code MLP branch in `CGp`.** Rejected (Compose Through Interfaces).
4. **Only ship arc-cosine, treat MLP as legacy.** Rejected: MLP is already in the tree and CLI; users ask for it first.
5. **Coloured-noise inducing \(u=\int\psi\eta\) with \(\mathrm{Cov}(\eta)=p\).** Rejected: puts \(\Sigma\) into \(K_{uu}\), missing REQ-000D.
6. **Omit \(\sqrt{p}\) on `CMlpKern` while keeping learnable \(w,b\).** Rejected for MLP; the omit-\(\sqrt{p}\) formula is reserved for the \(w,b\to\infty\) limit, exposed as `CArcCosineKern` order 0 (or a large-\((w,b)\) sanity bridge), not as a silent MLP mode.
7. **Single `CMlpKern` with an “infinite” flag that drops parameters.** Rejected: stream / `getNumParams` / optimisable-index churn. Two kernels keep contracts stable.
8. **Ship only Dutordoir-style RKHS / harmonic activated features.** Rejected for this CIP: spectral \(K_{uu}\) misses REQ-000D; sphere mapping and series truncation are a different stack (cite and compare, do not reimplement here).

- **Unit:** `wsCrossCompute` vs MC of \(\int\phi\sqrt{p}\,\psi\) (1-D / small \(d\)); control that \(\int\phi\psi\) alone must *not* match; \(K_{uu}\) vs analytic Gaussian Gram in \(d+1\).
- **FD:** kernel params (including `weightVariance` / `biasVariance`), weight centres, \(s\), and data \(X\) when optimised.
- **Sparse integration:** `testCGp` DTCVAR MLP weight-space smoke; stream round-trip.
- **Stability / approximation quality:** `ws_wv_sweep_*` — primary metric is sparse bound vs exact (or dense FTC) gap vs `weightVariance` with fixed windows; finiteness under StableFactor/LQ; \(\kappa(K_{uu})\) recorded as sanity only; point-inducing contrast recorded.
