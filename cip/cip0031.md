# CIP-0031: Split `posteriorMeanVar` into latent and predictive (GPy-style)

> CIPs describe HOW to achieve requirements (WHAT). This CIP owns the cross-model prediction contract that was previously only a Proposed backlog item (`2026-11-19_latent-vs-predictive-meanvar`).

## Summary

Give every prediction surface **two explicit meanings**, matching GPy:

- **Latent** — mean/variance of \(f_*\) (no observation noise); GPy `predict_noiseless` / `_raw_predict`.
- **Predictive** — mean/variance of \(y_*\) under the likelihood; for Gaussian noise, latent plus observation noise once; GPy `predict`.

Replace the overloaded `posteriorMeanVar` (different classes add \(1/\beta\) or not) with `latentMeanVar` / `predictiveMeanVar`, migrate callers, and expose the pair on the Python façade. This is a **contract CIP**, not a new modelling engine.

**Which requirements?** [REQ-000E](../requirements/req000E_gpy-facing-python-facade.md) (façade parity), [REQ-0002](../requirements/req0002_runnable-verification.md) (honest oracles across FTC / sparse / SVGP / PPA), [REQ-0014](../requirements/req0014_observation-noise-in-likelihood.md) (noise counted once via likelihood).

## Motivation

While verifying [CIP-002A](./cip002A.md) SVGP against `CGp` DTCVAR, predictive means agreed to \(10^{-14}\) but variances differed by exactly \(1/\beta\): `CGp::posteriorMeanVar` adds observation noise on sparse paths; `CSvgp::posteriorMeanVar` returns latent variance. The same overload appears across PPA, Bayes GPLVM, and IVM (audit below).

Assert and Verify cannot ship “variances match” gates when the API name means two things. Ecosystem Interoperability wants GPy’s split. CIP-0027 moved observation noise onto the likelihood for FTC; prediction still mixes latent and noisy semantics by class.

## Detailed Description

### Target API

| Method | Meaning | GPy analogue |
|---|---|---|
| `latentMeanVar(mu, varSigma, X)` | \(p(f_* \mid \cdot)\); no observation noise | `predict_noiseless` / `_raw_predict` |
| `predictiveMeanVar(mu, varSigma, X)` | \(p(y_* \mid \cdot)\); Gaussian: add \(\sigma^2\) / \(1/\beta\) **once** via the noise model | `predict` |
| `posteriorMeanVar` | Deprecated alias with **today’s** per-class behaviour until callers migrate; then remove | — |

Non-Gaussian: `predictiveMeanVar` returns moments from the noise model’s predictive path, or throws until defined. Do not silently invent a Gaussian \(+1/\beta\).

### Audit (main @ 2026-11-19; refresh on Accept)

| Class | `posteriorMeanVar` variance today | Notes |
|---|---|---|
| `CGp` FTC | latent; White-in-\(K\) still in \(k(x,x)\) if present | CIP-0027: prefer likelihood noise, not White |
| `CGp` DTC/DTCVAR/FITC/PITC | latent **+ \(1/\beta\)** | FTC vs sparse disagree inside one class |
| `CBayesGplvm` | latent **+ \(1/\beta\)** | |
| `CPpa` (dense) | latent (no \(1/\beta\)) | MATLAB `ppaPosteriorMeanVar` port |
| `CSparsePpa` | via inner `CGp` ⇒ latent **+ \(1/\beta\)** | dense vs sparse PPA disagree before `outerNoise.out` |
| `CSvgp` | latent | |
| `CIvm` | latent (confirm) | |

### Bugs this CIP must fix (not optional polish)

1. **`CGp::out` double-counts noise** on sparse paths: noisy variance passed into `CGaussianNoise::out`, which adds \(\sigma^2\) again (hidden when \(\sigma^2 \approx 10^{-6}\); wrong when learnt).
2. **Dense vs sparse PPA** predictive input to the outer noise must agree at \(M=N\) after the split; document the intended MATLAB/`ppaOut` semantics.

### Locked decisions

1. **Names** are `latentMeanVar` / `predictiveMeanVar` in C++; Python `predict_noiseless` / `predict` (optional `include_likelihood=` on `predict` if cheap).
2. **Gaussian predictive** adds likelihood-owned noise once ([CIP-0027](./cip0027.md) / `likelihood.variance`; sparse algebra may still use \(\beta\) internally).
3. **White-in-\(K\)** is prior structure: included in latent \(k(x,x)\) when the kernel contains White; do not also add it as observation noise.
4. **Output scale/bias** apply in both variants as today.
5. **Scope:** `CGp`, `CBayesGplvm`, `CMrd`, `CPpa`, `CSparsePpa`, `CIvm`, `CSvgp` (and `CSviBayesGplvm` if it exposes the same entry). No new sparse approximation maths.
6. **Rejected:** keeping a single `posteriorMeanVar` with a boolean flag as the long-term public API; putting Python or formatting inside the predict hot path.

### Python façade

Thin bind only ([CIP-001D](./cip001D.md)): map to the two C++ calls; update `subset_checklist.md` / side-by-side. Orthogonal to Python `fix` and sparse-noise *docs* follow-ons (separate backlog under 001D / 0027).

## Implementation Plan

1. **Phase A — `CGp`:** Factor `_posteriorVar`; add `latentMeanVar` / `predictiveMeanVar`; fix `out` double-count; FTC↔sparse agreement gates at \(M=N\), \(Z=X\), signal kernel only.
2. **Phase B — Other models:** Same pair on PPA / sparse PPA / IVM / Bayes GPLVM / MRD / SVGP (+ SVI BGPLVM if needed); PPA dense↔sparse agreement documented.
3. **Phase C — Deprecate and façade:** Mark `posteriorMeanVar` deprecated; migrate internal callers; Python `predict` / `predict_noiseless`; docs + checklist.

## Backward Compatibility

- Existing callers of `posteriorMeanVar` keep current per-class behaviour until Phase C migrates them.
- Public C++ / Python recipe docs should prefer the new names as soon as Phase A lands for `CGp`.
- No `.model` stream field change expected (prediction API only).

## Testing Strategy

- Unit: latent vs predictive differ by exactly the Gaussian observation noise variance on FTC and sparse.
- Cross-model: `CSvgp::latentMeanVar` vs `CGp::latentMeanVar` at matched DTCVAR / inducing (no manual \(1/\beta\) correction).
- Regression: `out` / classification-style paths count noise once; PPA dense↔sparse at \(M=N\).
- Python: façade smoke that `predict` variance = `predict_noiseless` variance + `likelihood.variance` (within tolerance).
