# CIP-0033: Likelihood/inference split — unblock EP and Laplace on CGp

## Summary

Finish the architecture slice CIP-0027 deferred: make likelihoods **pure and batched**, move **EP / ADF / site state** into inference workspaces, then ship **EP and Laplace** on `CGp` for probit-style classification (GPy `GPClassification` parity for the common path).

SVGP ([CIP-002A](./cip002A.md)), PPA ([CIP-0023](./cip0023.md) / [CIP-0026](./cip0026.md)), and IVM already give non-Gaussian routes. This CIP unblocks the **collapsed / site-based** GPy classification story on `CGp` itself, without overloading IVM’s White softener.

**Which requirements?** [REQ-0019](../requirements/req0019_nonconjugate-inference-ep-laplace.md) (primary), [REQ-0014](../requirements/req0014_observation-noise-in-likelihood.md) (likelihood ownership), [REQ-0002](../requirements/req0002_runnable-verification.md), [REQ-0009](../requirements/req0009_gpy-tutorial-parity-native.md) / [REQ-000E](../requirements/req000E_gpy-facing-python-facade.md) (classification tutorials / thin façade).

## Motivation

Today `CNoise` mixes parameters, a pointer to \(Y\), and per-point \(\mu\), \(\mathrm{var}\Sigma\) used as ADF / site caches. That blocks:

- a shared GPc / GPy2 likelihood API (`ep_moments`, …);
- EP / Laplace as **inference** over the same likelihood primitives SVGP already calls via `expectedLogLikelihood`;
- honest “RBF + probit, no White” classification on `CGp`.

CIP-0027 Phase 0 sketched the name map and deferred `ep_moments`. IVM tutorials still say “use IVM until a future CIP adds EP/Laplace.” That future CIP is this one.

## Detailed Description

### Locked architecture

1. **One data owner** — targets / mask / normaliser live on the model (or a dataset object); likelihoods do not copy \(Y\).
2. **Likelihood = parameters + batched functions** — contiguous \((Y_B,\mu_B,v_B)\) in, values / derivatives out. Per-element methods remain oracles only.
3. **Inference state belongs to inference** — EP sites, ADF caches, PPA site parameters, Laplace mode / Hessian workspaces live next to the inference algorithm ([CIP-002D](./cip002D.md) workspace spirit), not as `CNoise` fields.
4. **Canonical paths** — likelihood parameters on the tree (`likelihood.*`); GPy1 aliases where they exist.

### Batched API (extends CIP-0027 Phase 0)

| Name | Role | First consumers |
|---|---|---|
| `log_density` | \(\log p(y\mid f)\) | Laplace, oracles |
| `variational_expectations` | \(\mathbb E_q[\log p(y\mid f)]\) | SVGP (exists) |
| `log_predictive_density` | \(\log\mathbb E_q[p(y\mid f)]\) | ADF / predictive checks |
| **`ep_moments`** | cavity → site moment match | **EP** |
| `predictive_moments` | moments of \(p(y_*\mid\cdot)\) | `predictiveMeanVar` / `out` |

Gaussian helpers already live under `ndlnoise`. This CIP adds probit (and thin Bernoulli–probit) implementations and wires EP/Laplace to them.

### Inference on `CGp`

| Method | Sketch | Gate |
|---|---|---|
| **EP** | Site parameters \((\tau_i,\nu_i)\) (or equivalent); cavity distributions; moment match via `ep_moments`; outer loop updates sites then kernel hypers (SCG / existing optimisers) | Small FTC probit vs GPy fixture or exact orthant on \(N\le 2\)–few; site fixed-point residual |
| **Laplace** | Mode of \(p(f\mid y)\) by Newton / IRLS; Hessian = \(K^{-1}+W\); approx marginal + grads | FD on mode and marginal; compare to EP on easy problems |

Sparse `CGp` (DTC / FITC / …): **out of v1** — **FTC-first locked at Accept** (2026-11-21). GPy also ships `EPDTC`; we add it only after dense EP + Laplace are green.

### Softness story (must document, not invent)

| Mechanism | Where | Status after this CIP |
|---|---|---|
| White-in-\(K\) | IVM default softener | **Kept** as documented CIP-0027 exception unless a later CIP flips it with evidence |
| Likelihood scale (e.g. probit \(\sigma^2\)) | Likelihood parameter | Optional trainable; not required for EP v1 if link is standard probit |
| Site precision | EP / PPA inference state | EP sites; PPA \(\beta\) stays PPA’s augmentation, not observation noise |

GPy-style demos: **RBF (+ Bias optional) + probit + EP**, no auto White.

### Migration of `CNoise`

Phased, not a flag day:

1. Introduce inference workspace types (e.g. sites buffer owned by IVM / PPA / new `CEpInference` / Laplace state on `CGp`).
2. Dual-write or adapter: existing `getMuPtr`-style callers read from workspaces.
3. Remove `py` / `mu` / `varSigma` from likelihood once IVM, PPA, and `CGp` paths compile against workspaces.
4. Stream version bump if layout changes; readers accept old files.

### Explicit non-goals

- Replacing IVM, PPA, or SVGP.
- Poisson / Student-t / warped / heteroscedastic in v1 (hooks via Gauss–Hermite OK; not delivery gates).
- Full paramz / GPy object graph; HMC.
- Python in the EP inner loop — façade is thin (`GPClassification`-shaped) after C++ green.
- Forcing IVM to drop White in this CIP.

## Alternatives considered

| Option | Why not |
|---|---|
| EP only inside IVM | Does not give GPy `GPClassification` on `CGp`; keeps sites on the selection algorithm |
| Laplace-only first | Cheaper, but GPy tutorials and fixtures centre on EP; do Laplace in the same CIP once `ep_moments` exists |
| “Just call SVGP” for classification | Already available; does not unblock collapsed EP/Laplace or clean `CNoise` |
| Big-bang rewrite of all noise classes | Too risky; migrate behind workspaces |

## Implementation Plan

1. **Phase 0 — Spec and inventory**  
   Freeze API signatures (buffers, shapes, error behaviour). Catalogue every `CNoise` / `py` / `mu` / `varSigma` / site touch in IVM, PPA, `CGp`, Python. Decide FTC-only vs sparse EP for v1.

2. **Phase A — Pure likelihood + workspaces**  
   Probit batched `ep_moments` + tests vs one-dimensional quadrature / known moments. Introduce site / marginal workspaces; stop new writes into `CNoise` site fields. Migrate one path (prefer dense PPA or IVM ADF read) as proof.

3. **Phase B — EP on `CGp` (FTC)**  
   Site loop + hyperparameter opt; `testEp` / fixture vs GPy or orthant; tutorial stub replacing “use IVM instead” for a basic classification demo.

4. **Phase C — Laplace on `CGp`**  
   Mode + approximate marginal; compare to EP on shared toys; predictive via [CIP-0031](./cip0031.md) contract.

5. **Phase D — Strip and surfaces**  
   Remove likelihood-owned site storage; stream notes; optional sparse EP or document FTC-only; thin `gpc` classification bind; update CIP-0015 checklist / IVM tutorial cross-links.

## Backward Compatibility

- IVM White default unchanged unless a later CIP says otherwise.
- Existing `.model` / streams load; new inference fields versioned.
- ADF method names may wrap new batched primitives during migration.
- SVGP / PPA behaviour unchanged except where they voluntarily switch to shared `ep_moments` / workspace helpers.

## Testing Strategy

- Unit: `ep_moments` vs quadrature; Laplace mode vs FD; purity (perturb / restore).
- Model: FTC EP vs GPy fixture; \(N=2\) orthant upper bound where applicable; EP vs Laplace agreement on easy separable toys.
- Regression: IVM unitsquare and PPA demos still green after workspace migration.
- No MATLAB required at runtime; fixtures may be GPy-generated text (CIP-0017/0018 style).
