# CIP-0036: Reflect GPy `GPClassification` capabilities in `gpc`

> CIPs describe HOW to achieve requirements (WHAT). This CIP takes **GPy’s classification surface as the capability checklist**, maps it onto `gpc` after [CIP-0033](./cip0033.md) / [CIP-0034](./cip0034.md), and closes the gaps that block a GPy user from porting a basic classification script.  
> **Architecture:** [docs/target-architecture.md](../docs/target-architecture.md) · [docs/python-facade.md](../docs/python-facade.md).  
> **Builds on:** [REQ-000E](../requirements/req000E_gpy-facing-python-facade.md), [REQ-0019](../requirements/req0019_nonconjugate-inference-ep-laplace.md), [REQ-0017](../requirements/req0017_python-facade-help-docstrings.md).  
> Does **not** reopen C++ EP/Laplace algorithms; sparse EP / EPDTC stay deferred.

## Summary

Lead with **GPy capability reflection**. GPy’s usual classification story is:

```python
# GPy
m = GPy.models.GPClassification(X, Y)          # Bernoulli + EP (Laplace optional)
m.optimize()
mu, var = m.predict_noiseless(Xtest)           # latent f_*
p = m.predictive_probabilities(Xtest)        # class probabilities
```

[CIP-0033](./cip0033.md) / [CIP-0034](./cip0034.md) already give dense FTC EP/Laplace in C++ and a thin `gpc.GPClassification`. This CIP audits that bind against GPy’s capabilities, documents match / gap / defer, then implements the **in-scope gaps** so a GPy user can port `basic_classification` without reading C++ tutorials first.

**Which requirements?** [REQ-000E](../requirements/req000E_gpy-facing-python-facade.md) (façade ergonomics), [REQ-0019](../requirements/req0019_nonconjugate-inference-ep-laplace.md) (EP/Laplace WHAT), [REQ-0017](../requirements/req0017_python-facade-help-docstrings.md), [REQ-0009](../requirements/req0009_gpy-tutorial-parity-native.md) / [REQ-0002](../requirements/req0002_runnable-verification.md).

## Motivation

REQ-000E and CIP-001D promised GPy-like recipes for a documented subset. Classification was deferred until EP/Laplace existed on `CGp`. That C++ work is Closed. The remaining question is not “do we have inference?” but **“which GPy classification capabilities does `gpc` reflect, and which gaps still block a port?”**

A capability matrix (below) is the acceptance spine. Notebook, help, and wheel work are how we deliver and verify reflection — they are not the headline.

## GPy ↔ `gpc` capability matrix

Status key: **Match** = usable now · **Gap** = in scope for this CIP · **Defer** = documented non-goal / later CIP · **N/A** = GPy-only concept we refuse.

### Model construction and inference

| GPy capability | GPy surface (typical) | `gpc` today | Status | Notes |
|---|---|---|---|---|
| Binary GP classifier | `GPClassification(X, Y)` | `gpc.GPClassification(X, Y)` | **Match** | Thin façade (CIP-0033 Phase D) |
| Bernoulli observation | Bernoulli likelihood | `CProbitNoise` + labels `{0,1}`/`{-1,1}` | **Match** | Probit link; document vs GPy Bernoulli+Probit |
| EP inference (default) | EP approx | `inference="ep"` → `setEpInference` | **Match** | GPy default path |
| Laplace inference | Laplace approx | `inference="laplace"` | **Partial** | Construct + `objective`/`optimize` work; **predict unwired** → Gap |
| Kernel choice | `kern=` / default RBF | `kernel="rbf"` / `gpc.kern.*` | **Match** | CIP-0027: no auto White |
| No White softener | RBF-only default | Signal-only compound | **Match** | Softness in sites / Hessian |
| Sparse EP / DTC EP | `EPDTC` / sparse classifiers | Raises on non-FTC inference | **Defer** | CIP-0033 FTC-first lock |
| Multi-class / other likelihoods | Limited / extensions | None | **Defer** | REQ-000E / CIP-0015 non-goals |

### Prediction and probabilities

| GPy capability | GPy surface (typical) | `gpc` today | Status | Notes |
|---|---|---|---|---|
| Latent predictive \(f_*\) | `predict_noiseless(X*)` | `predict_noiseless` (EP only) | **Gap** | Wire Laplace; keep CIP-0031 naming |
| Class probabilities | `predictive_probabilities(X*)` | `predict_proba` (EP only) | **Gap** | Same Laplace hole; **name alias** Gap (below) |
| Latent + noise naming | `predict` / `predict_noiseless` | No `predict` on classifier | **Gap** | Decide: alias `predict`→proba, or document “use `predict_proba`” only |
| GPy name `predictive_probabilities` | method | `predict_proba` only | **Gap** | Add alias or document mapping in side-by-side |
| Log predictive density | `log_predictive_density` (where present) | Missing | **Defer** | Nice-to-have; not needed for basic tutorial |

## Detailed Description

### In-scope work (driven by Gaps above)

1. **Phase A — Predictive parity with GPy (EP + Laplace)**  
   - Wire Laplace `predict_noiseless` / probability path (mirror EP’s `epLatentMeanVar`).  
   - Resolve `predict` vs `predict_proba` vs GPy `predictive_probabilities`: prefer **aliases** that keep CIP-0031 latent naming clear in docs (`predict_noiseless` = \(f_*\); probabilities = class probs).  
   - Tests: both inferences return finite latent bands and probabilities in \((0,1)\); loose EP↔Laplace agreement on a separable toy.

2. **Phase B — Capability docs + teaching**  
   - Publish the matrix (this section) into [`python/docs/gpy_side_by_side.md`](../python/docs/gpy_side_by_side.md) (classification section) and keep it honest as code moves.  
   - `python/examples/basic_classification.ipynb` mirrors a minimal GPy script (construct → optimize → `predict_proba`).  
   - Move checklist row for `basic_classification` into the in-subset table; IVM remains the large-\(N\) pointer.

3. **Phase C — Discoverability + install**  
   - Help/docstrings for `GPClassification` and prediction methods ([CIP-002F](./cip002F.md) expansion).  
   - TestPyPI alpha bump + Colab pins so reflected capabilities are what users actually `pip install`.

### Out of scope (Defer rows)

- Sparse EP / EPDTC / FITC classification.  
- IVM / PPA / SVGP Python classifiers.  
- Multi-class, Poisson, Student-t, `set_XY`, full `m.plot()`, log predictive density.  
- C++ EP/Laplace algorithm changes; reopening CIP-0033/0034/001D.

## Alternatives considered

| Option | Why not |
|---|---|
| Ship notebook/wheel only | Does not close Laplace predict or naming gaps vs GPy |
| “API identity with GPy” | Rejected by REQ-000E; reflect capabilities, not paramz |
| IVM-first Python API | Wrong GPy default; confuses White softener story |
| Wait for sparse EP before teaching | Blocks the common dense GPy path we already implemented |

## Implementation Plan

1. Accept CIP; freeze the matrix statuses (Match / Gap / Defer) for v1.  
2. Phase A — close predictive Gaps (Laplace + naming aliases).  
3. Phase B — side-by-side + notebook + checklist.  
4. Phase C — help + wheel + pins.  
5. Close when every **Gap** row is Match or explicitly reclassified Defer with checklist text.

## Backward Compatibility

- Existing EP callers keep working.  
- New aliases are additive.  
- FTC-only errors for sparse inference stay.  
- Regression façade unchanged.

## Testing Strategy

- Façade tests for EP and Laplace latent + probability shapes/ranges.  
- Optional objective smoke vs `./testEp` twin.  
- Doc/notebook: pinned wheel version assert; one GPy-shaped script cell.  
- Checklist/matrix reviewed so no **Gap** remains silent.
