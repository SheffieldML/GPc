# CIP-0037: Fix `makeRidgeInit` — one-sided offsets and directions before offsets

> CIPs describe HOW to achieve requirements (WHAT). This CIP is a [CIP-0028](./cip0028.md) follow-on. It was drafted as CIP-0035 Phase 0c and split out so deep-GP work does not change weight-space defaults for every model. Evidence comes from the [CIP-0035 prototype](./cip0035/prototype/).

## Summary

Change `CInducingWeightSpace::makeRidgeInit` so the default layout (i) uses **one-sided** offsets and (ii) prefers **more directions than offsets** once \(D'\) is moderate. Re-record any fixtures pinned to the old layout. No legacy flag.

## Motivation

Two findings from the deep-GP prototype apply to every weight-space user, not only deep GPs:

1. **Symmetric offsets waste half the windows.** erf is odd, so windows at \(\pm a\) on one direction give \(K_{fu}\) columns that are exact negatives: with offsets on \([-2.5,2.5]\), \(\operatorname{rank}K_{fu}=M/2\) exactly. One-sided offsets (e.g. \([1,2.5]\)) restore full rank.
2. **Directions before offsets once \(D'\) is moderate.** At \(M=128\), 128 directions × 1 offset beat 32 × 4: variance captured 0.974 vs 0.920 at \(d=16\), 0.818 vs 0.397 at \(d=64\); offsets win only at \(d=4\) (0.944 vs 0.822). The current cap of \(D'\) directions (CIP-0028 §3 preference \(n_{\mathrm{off}}\approx4\)) is the wrong way round above small \(d\).

Keeping this inside CIP-0035 would contradict that CIP's non-goal of no `CSvgp` / `CGp` default-behaviour changes.

## Detailed Description

### One-sided offsets

Replace the default offset grid on \([-2.5,2.5]\) (skipping \(a=0\)) with a one-sided grid on a positive interval such as \([1,2.5]\) (or an equivalent positive span chosen so CIP-0028 \(\kappa(K_{uu})\) and variance-captured gates still pass). Keep the existing \(a\neq0\) guard as defence in depth.

### Directions before offsets

Change the `nDir` / `nOff` allocation so that, for moderate-to-large \(D'\), the layout grows \(M\) primarily by adding directions (allowing \(nDir>D'\) with non-orthogonal random directions when needed) rather than capping at \(D'\) and stacking offsets. Retain a small-\(d\) path where multiple offsets per direction remain useful (prototype: offsets win at \(d=4\)).

Document the new rule in CIP-0028 / `docs/numerics.md` and update the comment block above `makeRidgeInit`.

### Fixtures

Re-record any tests or reference artefacts that pin absolute window positions or variance-captured numbers under the old layout. Prefer re-record over a legacy flag.

## Implementation Plan

1. Implement one-sided offsets and the new \(nDir\)/\(nOff\) policy in `makeRidgeInit`.
2. Add `testInducing` / `testCGp` gate: \(\operatorname{rank}K_{fu}=M\) for the default layout; CIP-0028 variance-captured gates still pass.
3. Re-record fixtures; update CIP-0028 docs and `docs/numerics.md`.
4. Unblock CIP-0035 Phase 2 (weight-space deep layers).

## Backward Compatibility

- Changes the **default** weight-space initialisation for `CGp`, `CSvgp`, and any caller of `makeRidgeInit`.
- Users who set `W` explicitly are unaffected.
- No legacy flag; re-record fixtures.
