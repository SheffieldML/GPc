# CIP-0039: PR-time Coverage and `CHECKS=full` gates that CIP-002E demoted

> **Note**: CIPs describe HOW to achieve requirements (WHAT).

## Summary

Restore **pre-merge** protection for coverage regressions and for `CHECKS=full` property asserts, without undoing CIP-002E’s goal of not paying full gcov+lcov+Codecov on every docs/CIP PR.

Two complementary changes:

1. **Coverage back on PRs as tier 2 (path-triggered)** — same spirit as Numerical stability / Bench: run when library / test / workflow paths that affect measured coverage change; keep `workflow_dispatch` and `push` to `main`.
2. **Hard-gate the unique Coverage executables on Reference (or a sibling PR job)** — today Coverage alone builds and runs `testSvgp` / `testSparsePpa` (and related) under `CHECKS=full`. Those are correctness gates, not coverage measurement. They must not wait for a post-merge soak.

**Which requirements?** [REQ-0002](../requirements/req0002_runnable-verification.md) (trustworthy gate before merge); [REQ-0001](../requirements/req0001_contemporary-build.md) (contemporary CI still meaningful). Revises the trigger map in [CIP-002E](./cip002E.md) without reopening wheel policy.

## Motivation

[CIP-002E](./cip002E.md) demoted Coverage to **main push + dispatch** because it largely re-ran matio under gcov and burned minutes on governance-only PRs. Merge policy became Compile + Reference.

That demotion left two holes:

| Hole | What failed | Why PR CI missed it |
| --- | --- | --- |
| **A — Property asserts under `CHECKS=full`** | [#141](https://github.com/SheffieldML/GPc/pull/141) `upperCholOfS` omitted `setTriangular(true)`; `pdinv` / `logDet` threw under `GPC_CHECKS=2`. Fixed in [#143](https://github.com/SheffieldML/GPc/pull/143). | Reference does **not** build or run `testSvgp`. Local / PR `./testSvgp` often uses default `GPC_CHECKS=1`, where `MATRIXPROPERTIES` is a no-op. Coverage is the only workflow that ran `testSvgp` with `CHECKS=full` — and only **after** merge. |
| **B — Patch / project coverage drops** | Codecov patch status and the `CGp.cpp` ≥ 95% gate ([CIP-0011](./cip0011.md)) only update when Coverage uploads. | No Coverage job on the PR → no pre-merge signal for uncovered new library lines or a dipping `CGp` rate. |

Assert and Verify wants the assert to fire **before** ship. CIP-002E’s CI thrift still holds: do not pay cibuildwheel or full gcov on a backlog markdown edit — use **paths**, not “never on PRs”.

## Detailed Description

### Keep CIP-002E thrift; fix the tier map

| Tier (revised) | Workflows | When |
| --- | --- | --- |
| **1 — Every code PR / push to `main` (hard)** | Compile; Reference (+ expanded executables below) | Unchanged `paths-ignore` for governance/markdown |
| **2 — Path-triggered** | Numerical stability; Bench; **Coverage**; Wheels | Coverage paths: library / native tests / coverage scripts / `codecov.yml` / `coverage.yml` (see below) |
| **3 — Main / schedule / dispatch** | *(Coverage no longer exclusive to this tier)* | Optional: keep `push` to `main` for a full soak even when path filter skipped a docs merge that somehow touched measured surface later |
| **4 — Release / dispatch** | Publish wheels | Unchanged |

Wheels stay packaging-path only (CIP-002E / CIP-002C). This CIP does not change soft→hard for wheels or Windows.

### Part 1 — Path-triggered Coverage on PRs

Restore `pull_request` on `.github/workflows/coverage.yml` with a `paths:` allowlist, for example:

- Core / model sources that Coverage instruments: `CMatrix.*`, `CKern.*`, `CNoise.*`, `CGp.*`, `CSvgp.*`, `CAdam.*`, `CStochasticOptimisable.*`, `CSparsePpa.*`, `CPpa.*`, `CInducing.*`, `CDeepGp.*`, `CCholAdjoint.*`, `CLQAdjoint.*`, `CEpInference.*`, `CLaplaceInference.*`, `ndl*.*`, `CTransform.*`, `COptimisable.*`, `CDist.*`, `CMltools.*`, `CClctrl.*`
- Native test drivers and CLIs Coverage builds: `test*.cpp`, `bgplvm.*`, makefile / `make.linux` / `make.osx`
- Coverage tooling: `scripts/check_cgp_coverage.sh`, `codecov.yml`, `.github/workflows/coverage.yml`

Governance paths stay off the allowlist (no Coverage on CIP/docs-only PRs). Keep `workflow_dispatch` for forced soaks.

**Codecov on PRs:** once Coverage runs on the PR and uploads with the PR head SHA, existing `codecov.yml` patch / project status can annotate the PR again. Confirm `CODECOV_TOKEN` and that the action is not restricted to `main` only.

**Cost control:** one Ubuntu gcov job (unchanged); no macOS Coverage; path filter avoids docs noise. Accept that a PR which only changes an unlisted file that still affects coverage is a rare false negative — prefer expanding the allowlist over “every PR”.

### Part 2 — Move correctness-only Coverage steps onto the hard gate

Coverage today does three jobs glued together:

1. Build matio-tests + extras with `COVERAGE=1 CHECKS=full`
2. Run matio + `testSparsePpa` + `testSvgp` + `bgplvm` smoke
3. lcov filter + `check_cgp_coverage.sh` + Codecov upload

(1)+(2) for **non-gcov** binaries are **correctness**. (3) is **measurement**.

**Proposal (preferred):** extend Reference (Ubuntu matrix entry is enough; macOS can stay matio-only if time-bound) to:

```text
make USE_MATIO=1 CHECKS=full matio-tests testSparsePpa testSvgp
make run-matio-tests && ./testSparsePpa && ./testSvgp
```

Optionally add `testDeepGp` when that binary is a standing regression gate for CIP-0035. Do **not** require `COVERAGE=1` on Reference.

**Alternative:** a thin `checks-full-gates.yml` (tier 1 or path-triggered on `CSvgp.*` / `CDeepGp.*` / `testSvgp.cpp` / …) that only builds and runs those binaries under `CHECKS=full`. Prefer extending Reference unless job time on macOS becomes the blocker — then Ubuntu-only sibling job.

After Part 2, Coverage’s PR role is primarily **lcov + Codecov + CGp rate gate**, not the first place `MATRIXPROPERTIES` is ever exercised in CI.

### Non-goals

- Undoing Compile/Reference `paths-ignore` for docs/CIP
- Hard-gating Wheels or Windows MSVC
- Raising the CIP-0011 threshold above 95%
- Replacing matio Reference with Coverage

### Interaction with CIP-002E

CIP-002E remains the tier framework. This CIP **amends** its Coverage row from “main/dispatch only” to “path-triggered PR + main/dispatch”, and **clarifies** that `CHECKS=full` executable gates belong with Reference (tier 1), not only with Coverage (measurement).

## Implementation Plan

1. **Reference / hard gate**
   - Add `testSparsePpa` and `testSvgp` to the Ubuntu Reference build+run under `CHECKS=full`.
   - Document in `docs/build-and-ci.md` that these are merge gates, not Coverage-only.
   - Spot-check: cherry-pick or temporarily revert the #143 triangular flag on a throwaway branch and confirm Reference fails.

2. **Coverage triggers**
   - Add `pull_request` + `paths:` allowlist to `coverage.yml`; keep `push: main` and `workflow_dispatch`.
   - Update the CIP-002E tier comment at the top of the workflow.
   - Verify Codecov patch status posts on a library-touching PR.

3. **Optional follow-on**
   - Ubuntu-only `testDeepGp` under `CHECKS=full` if not already covered.
   - Trim Coverage job runtime by relying on Reference for non-gcov runs (Coverage still needs gcov builds of the same targets for line data).

4. **Docs / CIP-002E pointer**
   - Short note in `docs/build-and-ci.md` and a one-line “amended by CIP-0039” on CIP-002E (Closed CIPs stay historical; amendment lives here).

## Backward Compatibility

No library API change. Contributors touching listed paths see Coverage (and possibly longer Ubuntu Reference) on the PR again. Docs/CIP-only PRs stay cheap. Maintainers can still `workflow_dispatch` Coverage anytime.

## Testing Strategy

- Docs-only PR: no Coverage; Compile/Reference still `paths-ignore`.
- `CSvgp.cpp` / `testSvgp.cpp` PR: Reference runs `testSvgp` with `CHECKS=full`; Coverage path filter fires; Codecov patch status present.
- Reintroduce a deliberate missing `setTriangular` (or equivalent `MATRIXPROPERTIES` miss) on a throwaway branch → Reference red before merge.
- `main` push: Coverage still runs (full soak + upload).
