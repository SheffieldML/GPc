## Summary

Add the convolutional covariance function of van der Wilk, Rasmussen and Hensman (2017): a weighted sum over image patches of a covariance function on patches. It enters GPc as a kernel wrapper, `CConvKern`, around any existing patch kernel, together with an inter-domain inducing family, `CInducingPatches`, whose inducing variables are values of the patch process at inducing patches. No change to the inducing formalism is needed: the convolutional covariance is a linear operator applied to a GP on patches, and inter-domain inducing variables compose with linear operators. With an MLP-family patch kernel the existing weight-space families also apply unchanged, and then the model is an infinitely wide convolutional layer whose inducing variables are smoothed filters. Phase 1 delivers a convolutional first layer for `SparseGPRegression`, `DeepGP` and the classification models; translation-insensitive kernels and image-shaped hidden layers are later phases.

## Motivation

- **Architecture, not inference, is the MNIST gap.** On MNIST, GPc's three-layer deep GP with an isotropic RBF covariance on raw pixels reaches 2.20% test error (NLL 0.112, ECE 0.006) against 0.99% for a two-layer convolutional network and 1.98% for a 2 × 512 MLP. The deep GP has no translation structure; a convolutional covariance supplies it.
- **The weight-space view extends naturally.** CIP-0028 writes the MLP covariance as a white-noise process over weights. With patches,
  \[
  f(\mathbf x) = \sigma\int \Big[\sum_{p} w_p\,\operatorname{erf}\!\big(\bm\omega^\top\hat{\mathbf x}^{[p]}\big)\Big]\sqrt{\mathcal N(\bm\omega;\mathbf 0,\mathbf I)}\;u(\bm\omega)\,\mathrm d\bm\omega,
  \]
  an infinitely wide convolutional layer (one filter per point of weight space) read out by the patch weights. Windows over \(\bm\omega\) are windows over filters; \(K_{uu}\) is the MLP kernel's window overlap in a space of dimension (patch size + 1), independent of images and hyperparameters; and the posterior mean is a finite convolutional layer with interpretable filters plus an account of the variance it misses.
- **GPy and GPflow users expect it**, and the deep GP paper's comparison with convolutional networks needs it.

## Detailed Description

### Covariance function

Inputs are flattened images, one row per image, of shape \(H\times W\times C\). For patch shape \(h\times w\) and stride \(t\), let \(\mathbf x^{[p]}\in\mathbb R^{q}\), \(q = hwC\), be patch \(p = 1,\dots,P\). With a patch covariance \(k_g\) and patch weights \(\mathbf w\in\mathbb R^P\),
\[
k(\mathbf x,\mathbf x') = \sum_{p,p'} w_p w_{p'}\,k_g\!\big(\mathbf x^{[p]},\mathbf x'^{[p']}\big),
\qquad f(\mathbf x) = \sum_p w_p\, g\!\big(\mathbf x^{[p]}\big),\quad g\sim\mathcal{GP}(0,k_g).
\]

`CConvKern : CKern` owns a patch kernel (any `CKern` with input dimension \(q\), including ARD and MLP variants) and holds the image and patch geometry and \(\mathbf w\) (initialised to \(1/P\), learnable, with an option to tie them). It implements:

- `compute` and `diagCompute`: patches of a batch are stacked into a \((BP)\times q\) matrix; the patch kernel is called once on stacked patches and the result is contracted with \(\mathbf w\) (a weighted block sum). The diagonal needs the \(P\times P\) patch Gram matrix per image, \(O(P^2q)\) per image; see *Cost* below.
- `getGradParams`: gradients for the patch kernel's parameters (by passing the \(\mathbf w\)-expanded covariance gradient to the patch kernel on stacked patches) and for \(\mathbf w\).
- `getGradX` is not needed while the convolutional kernel is only used in the first layer, and is left for Phase 4.
- Stream I/O (`writeParamsToStream`, `readKernFromStream`) with the geometry, the patch kernel and \(\mathbf w\).

### Inducing patches

`CInducingPatches : CInducing` with `domainDim() = q` (inter-domain; supported since CIP-001C) and `kuuDependsOnKernel() = true`. Its inducing variables are \(u_m = g(\mathbf z_m)\) with \(\mathbf z_m\in\mathbb R^q\):
\[
K_{uu} = k_g(\mathbf Z,\mathbf Z),\qquad
K_{uf}[m, n] = \sum_p w_p\,k_g\!\big(\mathbf z_m,\mathbf x_n^{[p]}\big).
\]
`computeKuf` is one patch-kernel call on \(\mathbf Z\) against the stacked patches, then the weighted block sum. `gradFromKuuKuf` passes the expanded gradient to the patch kernel's `getGradParams` and `inducingGradZ` (batched by CIP-003F A2), and accumulates \(\partial/\partial\mathbf w\). Initialisation: \(k\)-means or random patches from the training images, with a PCA-filter option.

`CInducingPatches` reaches the patch kernel through a narrow interface on `CConvKern` (`patchKernel()`, `extractPatches(X, P)`, `patchWeights()`), so other inducing families are unaffected.

### Weight-space inducing variables over filters

`CInducingWeightSpace` and `CInducingHermite` call the kernel hooks `wsRidgeCrossCompute`, `wsRidgeGrad*`, `wsHermiteCrossCompute` and `wsHermiteGrad*`. `CConvKern` implements each by forwarding to the patch kernel on the stacked patches and contracting with \(\mathbf w\):
\[
K_{fu}[n, m] = \sum_p w_p\,k^{\text{ridge}}_{f\lambda}\!\big(\mathbf x_n^{[p]}, m\big).
\]
\(K_{uu}\) is unchanged (window overlap only). These hooks require an MLP-family patch kernel; anything else raises with a clear message. The bulk ridge path from CIP-003F A3 makes the forward one GEMM of stacked patches against window directions followed by elementwise operations.

Expectation from CIP-0035: image patches lie on a low-dimensional subset of patch space, so data-blind windows are likely to trail mobile inducing patches. Inducing patches are therefore the default; windows are offered for their filter interpretation and as an initialisation (for example, ridge directions from PCA filters).

### Cost

Per minibatch of \(B\) images with \(M\) inducing variables:

| Term | Cost |
|---|---|
| \(K_{uf}\) (patches or windows) | \(O(BPMq)\) — one GEMM on stacked patches |
| \(K_{uu}\) and its Cholesky | \(O(M^2q + M^3)\) (patches); fixed or \(O(M^3)\) when windows move |
| \(k(\mathbf x,\mathbf x)\) for the residual variance | \(O(BP^2q)\) |

The diagonal dominates for small strides: 28 × 28 images with 5 × 5 patches at stride 1 give \(P = 576\), about \(8\times10^6\) multiply–adds per image. Options, in order of preference:
1. **Stride** (\(t=2\) gives \(P=144\), 16× cheaper).
2. **Unbiased estimate** of \(\sum_{p,p'}\) from \(S\) sampled patch pairs per image. With a Gaussian likelihood the variance enters the bound linearly, so the bound estimate stays unbiased; for non-Gaussian likelihoods it is biased and the façade refuses it unless explicitly requested.
3. **Exact**, for small images or final evaluation.

### Façade

- `gpc.kern.Conv(base, image_shape, patch_shape, stride=1, weights='learned'|'tied'|'fixed')`.
- `SparseGPRegression`, the classification models and `DeepGP` accept the convolutional kernel; for `DeepGP` it applies to the first layer through CIP-0041 B1 (`kernel=[Conv(...), 'rbf', 'rbf']`, `inducing=['patches', 'points', 'points']`).
- `inducing='patches'` (default for convolutional kernels), `'weightspace'` or `'hermite'` (MLP-family patch kernels only).
- `diag='exact'|'estimate'` with `diag_samples`.
- Learned filters and patch weights are reported by `describe()`, and the posterior mean's filters (windows or inducing patches mapped back to \(h\times w\times C\)) are returned for plotting.

### Phases

1. **Phase 1 — weighted convolutional kernel, inducing patches, first layer.**
2. **Phase 2 — weight-space inducing over filters** (ridge and Hermite), after CIP-003F A3.
3. **Phase 3 — translation-insensitive kernel** (Dutordoir et al., 2020): \(k = \sum_{p,p'} k_g(\mathbf x^{[p]},\mathbf x'^{[p']})\,k_{\text{loc}}(\ell_p,\ell_{p'})\) with inducing pairs (patch, location).
4. **Phase 4 — deep convolutional GPs**: layers whose outputs are feature maps (Blomqvist et al., 2019; Dutordoir et al., 2020), requiring `getGradX` on `CConvKern`, image-shaped mean functions and multi-channel hidden layers in `CDeepGp`. Scoped here; its detailed design is a separate CIP.

### Verification oracles

| ID | Check | Oracle |
|---|---|---|
| C1 | Reduction | One patch equal to the image and \(\mathbf w = 1\): `CConvKern` equals the patch kernel in `compute`, `diagCompute` and all gradients; `CInducingPatches` equals `CInducingPoints` (round-off) |
| C2 | Linearity | \(K_{uf}\) and \(k(\mathbf x,\mathbf x)\) equal a direct double loop over patches with per-pair kernel calls (round-off) |
| C3 | Gradients | Finite differences for patch-kernel parameters, \(\mathbf w\), \(\mathbf Z\) and window parameters, through `CSvgp` and `CDeepGp` |
| C4 | Weight-space consistency | Monte Carlo over \(\bm\omega\) for \(K_{fu}\) with ridge and Hermite windows (as CIP-0028 / CIP-003D); \(K_{uu}\) unchanged from the plain MLP case |
| C5 | Diagonal estimator | Mean of the estimated diagonal within 4 standard errors of the exact one; Gaussian-likelihood ELBO estimate unbiased within Monte Carlo error |
| C6 | Shift sanity | For a circularly shifted image with tied weights and stride 1, \(k(\mathbf x,\mathbf x)\) changes only through boundary patches |
| C7 | End-to-end | MNIST, convolutional first layer, inducing patches: test error and NLL recorded against the GPc deep GP without convolution (2.20%) and the published convolutional GP results; target set at acceptance |

### Tenets

- **Compose through interfaces:** a kernel wrapper plus an inducing family; no convolution-specific code in `CSvgp` or `CDeepGp` in Phases 1–3.
- **Assert and verify:** exact reductions (C1, C2) before any approximation (C5).
- **LAPACK owns the linear algebra:** stacked-patch GEMMs, no per-patch kernel loops.

## Implementation Plan

1. **Phase 1a — `CConvKern`:** geometry, patch extraction, `compute`, exact `diagCompute`, `getGradParams`, stream I/O. Gates: C1 (kernel part), C2, C3 for kernel parameters and \(\mathbf w\).
2. **Phase 1b — `CInducingPatches`:** `computeKuu`/`Kuf`/`Kux`, `gradFromKuuKuf`, initialisation. Gates: C1, C3 through `CSvgp` and `CDeepGp`.
3. **Phase 1c — cost options:** stride, diagonal estimator. Gate: C5; timing case added to `bench/timing_cases.json` (MNIST-sized synthetic images).
4. **Phase 1d — façade:** `gpc.kern.Conv`, model integration, filter extraction for plotting. Gates: Python tests; C7 run recorded.
5. **Phase 2 — weight-space over filters** (after CIP-003F A3). Gates: C4, C3 for window parameters.
6. **Phase 3 — translation-insensitive kernel.** Gates: C1 with \(k_{\text{loc}}\equiv 1\) reducing to the weighted kernel with tied weights; C3.
7. **Phase 4 — deep convolutional GP:** separate CIP.

## Backward Compatibility

All additions: a new kernel, a new inducing family, new façade options. Existing kernels, inducing families, streams and defaults are unchanged. The stream format gains a `conv` kernel type that older readers reject with an unknown-type error.

## Testing Strategy

- `testConvKern` (C1–C3, C6) and an extension of `testInducing` (C1, C4) in the hard tier.
- `testSvgp` and `testDeepGp` cases with a convolutional first layer (C3) in the hard tier.
- Diagonal-estimator statistics (C5) in the numerics tier.
- MNIST end-to-end (C7) as a recorded experiment, not a CI gate; a small synthetic image task (for example shifted bars) as a smoke test.
