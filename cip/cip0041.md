# CIP-0041: Per-layer `DeepGP` façade

> CIPs describe HOW to achieve requirements (WHAT). This CIP serves [REQ-001A](../requirements/req001A_deep-gaussian-processes.md) (deep GPs), with gates under [REQ-0002](../requirements/req0002_runnable-verification.md). It was split from the first draft of [CIP-003F](./cip003F.md) (training speed), which is pure equivalence work; this CIP changes user-visible behaviour and has different risks. [CIP-0040](./cip0040.md) (convolutional covariance functions) depends on B1.

## Summary

The Python `DeepGP` façade applies one kernel string and one inducing string to every layer, initialises the MLP covariance at a scale that saturates on high-dimensional inputs, does not offer ARD covariances per layer, and has a Jacobian diagnostic that is uninformative at initialisation. This CIP adds a per-layer choice of kernel and inducing family, an optional scaled MLP initialisation (default unchanged), `mlpard` and `rbfard` per layer, a prior-draw mode for `jacobian_spread`, and BLAS thread control, so that the configurations recommended by CIP-0035 (for example weight-space windows in the input layer and inducing points in hidden layers) can be built and measured.

## Motivation

- One `kernel` and one `inducing` string apply to every layer. The CIP-0035 findings recommend inducing points in hidden layers and, if anywhere, weight-space windows in a high-dimensional input layer; that combination cannot be built.
- The MLP covariance is initialised with weight variance 1 per input (`wrap_deepgp.cpp`). On 784-D pixels \(\|\tilde{\mathbf x}\|^2\approx 100\), so the kernel starts deep in saturation, where it is almost a function of angle and its hyperparameter gradients are small. The CIP-0035 prototype scaled the weight variance by the input dimension.
- `mlpard` (`CMlpardKern`, with the weight-space ridge overrides from CIP-0028 Phase 1b) is not offered per layer.
- `jacobian_spread` differences the current \(q\) path with fixed noise, not prior draws, so at initialisation it returns about 0 whatever the depth scaling (seen in `deepgp-mlp/notebooks/04_depth_defaults`). CIP-003C covers rectangular Jacobians; the prior-draw mode is new here.
- Timing studies (CIP-003F Phase 0) need a fixed BLAS thread count.

## Detailed Description

**B1. Per-layer kernel and inducing family.** `kernel` and `inducing` accept a string (as now, applied to every layer) or a length-\(L\) sequence. Validation is per layer: `'weightspace'` and `'hermite'` require an MLP-family kernel on that layer; Hermite capacity checks use that layer's input dimension. Errors name the layer index. Example: `DeepGP(X, Y, layers=3, kernel='mlp', inducing=['weightspace', 'points', 'points'])`.

**B2. MLP covariance initialisation.** Add `mlp_init: 'unit' | 'scaled'` (a string for all layers or a length-\(L\) sequence). `'unit'` is the current behaviour and **remains the default**. `'scaled'` sets the initial weight variance to \(1/\overline{\|\mathbf h\|^2}\), the inverse mean squared norm of the layer's inputs pushed through the mean maps (\(1/d_{\mathrm{in}}\) when inputs are standardised), and the bias variance to 0.1, so that \(\|\hat{\mathbf x}\|^2\) starts near one.

*Decision recorded:* changing the default would alter results for existing MLP-kernel scripts, so it is not done in this CIP. A follow-up may change the default once paper benchmarks (CIP-0035 composite task and MNIST) show `'scaled'` is no worse; that follow-up must note the change in the release notes.

**B3. `kernel='mlpard'` and `'rbfard'` per layer,** through the existing `CMlpardKern` and ARD RBF. ARD weights are reported by `describe()`.

**B4. `jacobian_spread(prior=True)`.** Draw the whitened variables \(\mathbf v_\ell\sim\mathcal N(\mathbf 0,\mathbf I)\) per layer (rather than using the current \(q\)), propagate with the mean maps, and report the median spread and the median mean log singular value over draws. The default stays `prior=False`. Combined with CIP-003C's rectangular support, this is the V7 check CIP-0035 intended.

**B5. BLAS threads.** `gpc.set_num_threads(n)` and `gpc.get_num_threads()` wrapping the linked BLAS's thread control (OpenBLAS; a documented no-op returning 1 on builds where the control is unavailable, for example Accelerate).

### Out of scope

- Speed work in kernels and `CSvgp` ([CIP-003F](./cip003F.md)).
- Convolutional layers ([CIP-0040](./cip0040.md)).
- Multi-class likelihoods ([CIP-003E](./cip003E.md)).

## Implementation Plan

1. **Phase 1 — B1.** Per-layer kernel and inducing sequences with per-layer validation.
   - Gates: per-layer configurations construct, train and stream round-trip; invalid combinations raise with the layer index in the message; scalar strings behave exactly as before (existing `python/tests/test_deepgp.py` unchanged).
2. **Phase 2 — B3, B5.** ARD kernels per layer; thread control.
   - Gates: ARD weights appear in `describe()` and survive a stream round-trip; `get_num_threads` reflects `set_num_threads`.
3. **Phase 3 — B2.** `mlp_init`.
   - Gates: `'scaled'` gives \(\|\hat{\mathbf x}\|^2\) within \([0.5, 2]\) at initialisation on standardised data; `'unit'` is bit-identical to current behaviour.
4. **Phase 4 — B4.** Prior-draw Jacobian.
   - Gates: reproduces the CIP-0035 prototype trend (flat spread under \(\chi/L\), growing without mean functions) within Monte Carlo error.

## Backward Compatibility

- Old string forms keep their meaning; `mlp_init` defaults to `'unit'`; `jacobian_spread` defaults to `prior=False`.
- No change to the C++ library or the stream format.

## Testing Strategy

- Python tests in `python/tests/test_deepgp.py` for each of B1–B5, including the error messages for invalid per-layer combinations.
- Regression test that default constructions give identical objective values and parameters to the pre-change façade.
