# CIP-0042: Deep convolutional Gaussian processes

> CIPs describe HOW to achieve requirements (WHAT). This CIP serves [REQ-001D](../requirements/req001D_convolutional-gps-for-images.md) (convolutional GPs for images) and [REQ-001A](../requirements/req001A_deep-gaussian-processes.md) (deep GPs), with gates under [REQ-0002](../requirements/req0002_runnable-verification.md). It is Phase 4 of [CIP-0040](./cip0040.md), split out as that CIP specified. It is a proposal: no code has been written.

## Summary

[CIP-0040](./cip0040.md) added a convolutional kernel that *sums* a patch kernel over positions, so a convolutional layer maps an image to one scalar function value per output. That is enough for the first layer of a shallow model. Deep convolutional GPs (Blomqvist et al., 2019; Dutordoir et al., 2020) need a different object: a GP layer that is applied *at every patch* and whose outputs, arranged by patch position, form the feature map that the next layer reads as an image. This CIP adds that layer type to `CDeepGp`, the input gradients that stacking requires, an image-shaped mean function, and a `gpc.models.DeepGP` interface for it.

## Motivation

- The literature reports that stacking convolutional GP layers improves on single-layer convolutional GPs for image classification (Blomqvist et al., 2019; Dutordoir et al., 2020); we have not reproduced those numbers here. For this library the deep variant is also the natural next test of the doubly stochastic machinery in `CDeepGp` on image data.
- `CDeepGp` already stacks `CSvgp` layers with mean maps and propagates samples through hidden layers (CIP-003F, CIP-0041). The missing pieces are specific and enumerable, which makes this a tractable extension rather than a new model class.
- It exercises the tenets directly. *Compose through interfaces*: the new layer must be a `CSvgp`-compatible layer, not a bespoke solver. *Assert and verify*: every new gradient needs a finite-difference gate before it is used in a stack.

## Detailed Description

**1. Patchwise layer.** A layer takes \(N\) images of shape \(H\times W\times C\) and has a patch kernel \(k_g\) on \(\mathbb R^{q}\), \(q=hwC\), with \(C'\) output channels and inducing patches \(\mathbf Z\in\mathbb R^{M\times q}\) (shared across channels, or per channel as a later option). For each patch \(\mathbf x_n^{[p]}\) the layer returns the SVGP marginal \(q(g_c(\mathbf x_n^{[p]}))\) for \(c=1..C'\). The outputs, indexed by \((n,p,c)\), are reshaped to \(N\times(P\,C')\), which is the next layer's flattened input image of shape \(H'\times W'\times C'\) with \(H'\), \(W'\) the patch-grid size. Cost per layer is \(O(NPMq + NPM^2)\) for the marginals, against \(O(NP\cdot P\,q)\) for the diagonal of the summed kernel in CIP-0040, so this layer is cheaper per image than the summed kernel's exact diagonal but multiplies the effective batch by \(P\).

Marginals are used per patch and samples are drawn independently across patches and channels, as in the doubly stochastic scheme of Salimbeni and Deisenroth (2017); correlations between neighbouring patches are dropped. This is an approximation and is stated as such in the documentation.

**2. Layer kinds in `CDeepGp`.** Layers become one of: the existing dense SVGP layer, the CIP-0040 summed convolutional layer (final layer, scalar or class-logit outputs), and the new patchwise layer. The kind is a property of the layer, set through the same per-layer sequences CIP-0041 introduced (`kernel=[...]`, `inducing=[...]`), so that existing code paths and streams are unchanged when only dense and CIP-0040 layers are present.

**3. Input gradients.** Stacking requires \(\partial\mathcal L/\partial\mathbf x\) through patch extraction. Extraction is a gather, so its adjoint is a scatter-add of patch gradients back onto pixels (overlapping patches accumulate). We implement `CConvKern::getGradX`, `getDiagGradX` and `CInducingPatches` input gradients (currently throwing `NotImplementedError`, with the message pointing at this phase) through that adjoint, reusing the patch kernel's own `getGradX`.

**4. Mean function.** Hidden layers in `CDeepGp` use a mean map that passes information from the input to the output (CIP-003F/0041). For feature maps the analogue is a convolutional mean: output channel \(c\) of patch \(p\) is a linear function of the patch, initialised to pass the central pixel (and, when \(C'\neq C\), a fixed projection), which is the choice in Dutordoir et al. The mean parameters are either fixed or learned; both are tested.

**5. Geometry and validation.** Each layer records \((H,W,C)\) in and \((H',W',C')\) out, validated at construction (the previous layer's output geometry must equal the next layer's input geometry), with the layer index in every error message, as in CIP-0041.

**6. Facade.** `gpc.models.DeepGP(X, Y, kernel=[ConvLayer(...), ConvLayer(...), Conv(...)], ...)`, where `ConvLayer` is the descriptor for a patchwise layer (patch kernel, patch shape, stride, output channels, mean function) and the final `Conv` is the CIP-0040 kernel. `inducing_filters()` is extended to take a layer index.

## Implementation Plan

Gates are the oracles in [CIP-0040](./cip0040.md) (C1–C3) plus the following.

| ID | Check | Oracle |
|---|---|---|
| D1 | Single patch | One patch equal to the image and \(C'=1\): the patchwise layer equals a dense `CSvgp` layer with the patch kernel (round-off) |
| D2 | Marginals | Per-patch marginals equal a loop over single-patch `CSvgp` predictions (round-off) |
| D3 | Adjoint | Scatter-add is the adjoint of patch extraction: \(\langle \mathrm{extract}(\mathbf x),\mathbf g\rangle=\langle \mathbf x,\mathrm{scatter}(\mathbf g)\rangle\) for random \(\mathbf x,\mathbf g\), all strides |
| D4 | Gradients | Finite differences of the stacked objective with frozen noise through two patchwise layers plus a summed final layer, for kernel, inducing, mean and variational parameters |
| D5 | Streams | Round trip of a stacked model: parameters, geometry and predictions (E6-style validation for malformed geometry) |
| D6 | Equivalence | A one-layer stack equals CIP-0040 where the two descriptions coincide |

Phases:

1. Adjoint scatter and `CConvKern`/`CInducingPatches` input gradients (D3, and C3 with \(\mathbf x\) gradients).
2. Patchwise layer in `CSvgp`/`CDeepGp` with marginals, mean function and geometry validation (D1, D2).
3. Stacking, objective and gradients, streams (D4–D6).
4. Facade, then a two-layer MNIST experiment recorded against the single-layer C7 result, with the same honesty about training budget as there.

## Backward Compatibility

No change for dense, CIP-0040 or CIP-0041 models: the layer kind defaults to the existing behaviour and old `.model` streams load unchanged. New stream keys are versioned and written only for the new layer kind.

## Testing Strategy

Every new gradient has a finite-difference gate before it is used downstream, and every structural claim (D1, D2, D3, D6) has an exact or round-off oracle. Training-quality results are reported as measured, with the budget used, and are not a gate.

## Risks

- **Memory and time.** The effective batch is \(N\cdot P\) patches per layer; for \(28\times28\) images with \(5\times5\) patches at stride 1, \(P=576\). A stride of 2 or minibatching bounds this; we report the cost of each configuration rather than claim a speed.
- **Independence across patches.** The marginal-per-patch scheme drops spatial correlation. It matches the published approach but is an approximation.
- **Scope.** Per-channel inducing patches, pooling and multi-channel mean functions beyond the central-pixel choice are deferred.
