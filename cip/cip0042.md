# CIP-0042: GPy-aligned mean functions

> CIPs describe HOW to achieve requirements (WHAT). This CIP serves [REQ-001E](../requirements/req001E_gpy-aligned-mean-functions.md), with gates under [REQ-0002](../requirements/req0002_runnable-verification.md) and parameter paths under [REQ-0008](../requirements/req0008_gpy-like-parameter-access.md).

## Summary

Add a `CMean` interface for parametric prior mean functions \(\mu(\mathbf x)\), a catalogue of implementations that mirrors `GPy.mappings` (`Constant`, `Linear`, `Identity`, `Additive`, `Compound`, `Kernel`, `MLP`, `PiecewiseLinear`), and an optional `CMean` held by `CGp` and `CSvgp`. The mean enters in one place on the training side — the centred target \(\mathbf m\) that `CGp::updateM()` already builds — and in one place on the prediction side. Phase 1 delivers dense (FTC) regression with the first four mappings and a GPy reference check; later phases cover sparse approximations, SVGP, the remaining mappings, EP/Laplace, and the Python façade.

## Motivation

- **A gap against GPy.** GPy's `GP`, `SparseGP` and `SVGP` take `mean_function=`. GPc has no equivalent. Every prior scope document records "mean functions" as a non-goal ([CIP-0015](./cip0015.md), [REQ-0009](../requirements/req0009_gpy-tutorial-parity-native.md), [REQ-000E](../requirements/req000E_gpy-facing-python-facade.md)); this CIP is the follow-on that lifts it.
- **What GPc has instead is too narrow.** `CGp` carries a per-output constant `bias` and a `scale` (`updateM()` forms \(\mathbf m=(\mathbf y-\text{bias})/\text{scale}\)). Neither depends on \(\mathbf x\). `CDeepGp` carries fixed linear maps `meanP[ℓ]` that act as skip paths ([CIP-0035](./cip0035.md)), but those live inside the deep GP and cannot be learned, combined or reused by a shallow model.
- **Modelling consequence.** A GP with zero mean must explain a linear trend with the kernel. The usual symptoms are inflated length scales, reverting to the offset away from the data, and poor extrapolation. A linear-plus-GP model fixes all three at the cost of a few parameters.
- **Tenet alignment.** *Compose Through Interfaces*: a mean function is another contract (`CMean`) that models consume, as kernels (`CKern`) and noises (`CNoise`) are. *Interoperate With the GP Ecosystem*: parameter names, units and the catalogue follow GPy. *Assert Invariants*: GPy asserts "no mean function" where it has not derived the gradient; we do the same, loudly, and add finite-difference checks where we do derive it.

## Detailed Description

### Reference behaviour in GPy

Read from `GPy` source (`core/gp.py`, `mappings/`, `inference/latent_function_inference/`):

| Aspect | GPy behaviour |
|---|---|
| Training target | Inference receives \(\mathbf Y-\mu(\mathbf X)\); the mean enters only through this shift. For exact Gaussian: `m = mean_function.f(X)`, `alpha = K⁻¹(Y − m)`, `grad_dict['dL_dm'] = alpha`. |
| Mean gradient | `mean_function.update_gradients(dL_dm, X)` accumulates parameter gradients; `gradients_X(dL_dF, X)` gives the input gradient (used by `predictive_gradients`). |
| Prediction | `mu += mean_function.f(Xnew)`; variance unchanged. |
| Parameter names | The mapping is a linked parameter named by its default (`constmap`, `linmap`, `mlpmap`, `kernmap`, `piecewise_linear`) with leaves `C`; `A`; `W1,b1,W2,b2`; `A`; `values,breaks`. |
| Normalisation | The mean function acts in the *normalised* output space (`Y_normalized`). |
| Support matrix | Exact Gaussian, Student-t, EP, `VarDTC`, SVGP: supported. `Laplace`, `FITC`, `DTC`, `PEP`: `assert mean_function is None`. `VarDTC` additionally raises with heteroscedastic noise or uncertain inputs. |
| SVGP | Mean evaluated at both \(\mathbf X\) and \(\mathbf Z\) (`prior_mean_f`, `prior_mean_u`); gradients flow to the mean's parameters from both and to \(\mathbf Z\) through `gradients_X`. |
| Catalogue | `Constant(input_dim, output_dim, value)`, `Linear` (matrix `A`, no intercept), `Identity`, `Additive(m1, m2)`, `Compound(m1, m2)` (\(m_2\circ m_1\)), `Kernel(input_dim, output_dim, Z, kernel)` (\(k(\mathbf x,\mathbf Z)\mathbf A\)), `MLP` (one tanh hidden layer), `PiecewiseLinear`. |

Phase 0 reruns these readings as executable reference fixtures (below) so the table is tested, not trusted.

### D1. The `CMean` contract

A new header `CMean.h`, following the style of `CKern`/`CNoise`:

```cpp
class CMean : public CStreamInterface, public CTransformable, public CRegularisable /* as CKern; CMatInterface only if the MATLAB bridge survives */ {
public:
  virtual unsigned int getInputDim()  const = 0;
  virtual unsigned int getOutputDim() const = 0;
  // M(n, d) = mu_d(X(n,:)).  Whole-matrix, so a linear mean is one GEMM.
  virtual void compute(CMatrix& M, const CMatrix& X) const = 0;
  // Parameter gradient given dL/dM (N x D) and the inputs it was evaluated at.
  virtual void updateGradients(CMatrix& g, const CMatrix& dLdM, const CMatrix& X) const = 0;
  // Input gradient: gX(n,q) = sum_d dLdM(n,d) dmu_d/dx_q.
  virtual void gradX(CMatrix& gX, const CMatrix& dLdM, const CMatrix& X) const = 0;
  // Parameters: same pattern as CKern (count, get/set opt params, names, transforms, paths).
  virtual unsigned int getNumParams() const = 0;
  virtual void getOptParams(CMatrix& p) const = 0;
  virtual void setOptParams(const CMatrix& p) = 0;
  virtual CMean* clone() const = 0;
};
```

Design points:

- **Coarse virtual boundary.** One virtual call per evaluation of \(\boldsymbol\mu(\mathbf X)\), never per element. This keeps the interface cost out of the inner loop (*Flexibility Without a Performance Tax*).
- **Mathematical conventions.** `compute` evaluates all \(N\) rows at once; `updateGradients` takes the full \(N\times D\) upstream gradient. Linear, identity and constant are single BLAS calls (`dgemm`, `dcopy`, column sums). MLP uses two GEMMs and an elementwise tanh. Nothing is hand-rolled that LAPACK/BLAS covers (*LAPACK Owns the Linear Algebra*).
- **Composition is a first-class implementation, not a switch.** `CAdditiveMean` and `CCompoundMean` own child `CMean`s, as `CCmpndKern` owns kernels. `CMean` composes by interface; no model code knows which concrete mean it holds.
- **Mean parameters are optimisable parameters.** `CGp::getOptParams`/`setOptParams` concatenate `[kernel | noise | mean]`. The ordering is recorded in the stream version (see Backward Compatibility) and in `paramPaths()`.

### D2. Where the mean enters `CGp` (dense, Gaussian)

`CGp::updateM()` is the choke point where the centred target is built. Today:

\[
\mathbf m = (\mathbf y-\mathbf b)\oslash\mathbf s .
\]

With a mean function \(\boldsymbol\mu(\mathbf X)\) acting on the latent function \(f\) (the space the GP prior lives in):

\[
\mathbf m = (\mathbf y-\mathbf b)\oslash\mathbf s-\boldsymbol\mu(\mathbf X),
\qquad
\mathbb E[f_\ast]=\mathbf s\odot\big(\mathbf k_{\ast}^\top\boldsymbol\alpha+\boldsymbol\mu(\mathbf X_\ast)\big)+\mathbf b .
\]

**Decision recorded.** The mean function lives in *the same space as the kernel*, after `bias`/`scale`. This matches GPy where users use `normalizer=True` (GPy's mean function acts on `Y_normalized`) and reduces to GPy exactly when `scale=1, bias=0`, the default. It also keeps the existing bias/scale transforms, their gradients (`g_scaleBias`), and old `.model` files untouched.

Gradients. Because \(\boldsymbol\mu\) enters \(\mathbf m\) linearly with a minus sign, \(\partial\mathcal L/\partial\boldsymbol\mu=-\partial\mathcal L/\partial\mathbf m\). For the dense Gaussian marginal likelihood \(\mathcal L=-\tfrac12\mathbf m^\top(\mathbf K+\sigma^2\mathbf I)^{-1}\mathbf m+\dots\) this equals \(+\boldsymbol\alpha\), which is GPy's `dL_dm`. `CGp` passes it to `pmean->updateGradients`. Kernel and noise gradients are unchanged because they see \(\mathbf m\) exactly as before; only \(\mathbf m\) differs.

Caching. \(\boldsymbol\mu(\mathbf X)\) is cached with the same up-to-date flag pattern as `mupToDate`: it is recomputed only when the mean parameters or \(\mathbf X\) change. With no mean function the field is null and `updateM()` takes its current path unchanged — that is the bit-identical guarantee.

### D3. Per-approximation support

`CGp` supports FTC, DTC, DTCVAR, FITC and PITC, and EP/Laplace non-conjugate inference. Every path reads \(\mathbf m\) (or `*py` for EP) so each needs an explicit decision:

| Path | GPy | This CIP | Notes |
|---|---|---|---|
| FTC (dense Gaussian) | supported | **Phase 1** | D2. |
| DTCVAR (variational) | supported (`VarDTC`) | **Phase 2** | Shift \(\mathbf m\); \(\partial\mathcal L/\partial\mathbf m\) from the existing \(\mathbf m^\top\mathbf m\) and \(\mathbf K_{uf}\mathbf m\) terms (`gbetaM2L`, `Bbar`, …). Assert when noise is heteroscedastic (as GPy raises). |
| DTC, FITC, PITC | **asserts "not implemented"** | **Phase 2, derive and check (required)** | The shift is the same; the work is the gradient. Each gets a finite-difference test before it is enabled; until then it throws a typed `NotImplementedError` naming the approximation. We do not copy GPy's silence. |
| SVGP (`CSvgp`) | supported | **Phase 3** | Mean at \(\mathbf X\) (or the minibatch) and at \(\mathbf Z\); whitened parameterisation means the posterior over \(\mathbf u\) is centred on \(\boldsymbol\mu(\mathbf Z)\); input gradient to \(\mathbf Z\) through `gradX`. |
| EP | supported | **Phase 4** | Prior mean in the site update (GPy: `mean_prior`). `CGp` EP currently reads `*py`; the route is to pass \(\boldsymbol\mu\) as the EP engine's prior mean rather than shifting \(\mathbf y\), because the target is discrete for classification. |
| Laplace | **asserts** | **Phase 4** | Mode finding with prior mean is the standard formulation \(f=\boldsymbol\mu+\mathbf K\mathbf a\); we implement it, with a gradient check, going beyond GPy. |
| `CIvm`, `CGplvm`, `CBayesGplvm`, uncertain inputs | n/a / raises | **Typed refusal** | A model that holds a mean function on a path that ignores it is a silent correctness bug; each refuses. |
| `CDeepGp` | n/a | **Phase 5, optional** | Replace `meanP[ℓ]` with `CLinearMean` (fixed) so shallow and deep models share one concept; learned skip paths become possible. Must reproduce CIP-0035/0041 numerics bit-for-bit with fixed maps. |

### D4. Mapping catalogue

| Class | GPy | Parameters (paths follow GPy names) | Phase |
|---|---|---|---|
| `CConstantMean` | `Constant` | `C` (per output) | 1 |
| `CLinearMean` | `Linear` | `A` (\(q\times D\); no intercept, as GPy) | 1 |
| `CIdentityMean` | `Identity` | none (requires \(q=D\)) | 1 |
| `CAdditiveMean` | `Additive` | children's parameters | 1 |
| `CCompoundMean` | `Compound` | children's parameters | 3 |
| `CKernelMean` | `Kernel` | `A` (\(M\times D\)); basis points \(\mathbf Z\) fixed | 3 |
| `CMlpMean` | `MLP` | `W1, b1, W2, b2` | 3 |
| `CPiecewiseLinearMean` | `PiecewiseLinear` | `values, breaks` | 3 |

Relation to existing `bias`: a `CConstantMean` is the learnable analogue of the constant offset and overlaps with `bias`. We keep both. The `bias` is in original output units, belongs to the noise parameter block (`outputBiasLearnt`), and carries the gradient `g_scaleBias`; a `CConstantMean` is a mapping like any other and composes under `CAdditiveMean`. Nothing is deprecated here. Using both on one model is allowed but unidentifiable (the two constants trade off); we document it rather than forbid it, and a test confirms that a `CConstantMean` with fixed `bias` gives predictions identical to a learnt `bias` with no mean.

### D5. Persistence and parameter paths

- **Stream.** `CGp::writeParamsToStream` adds an optional versioned `meanFunction` block, using the same type-string-plus-parameters convention as kernels (`CStreamInterface`). `readParamsFromStream` treats an absent block as "no mean function". Files written before this change load unchanged; files written with a mean function carry a bumped `version` so older readers fail rather than ignore it (*Interoperate With the GP Ecosystem*: version a field change, never silently reinterpret).
- **Paths.** `paramPaths()` lists mean parameters under the model with GPy's default names: `constmap.C`, `linmap.A`, `mlpmap.W1`, …, duplicates numbered `constmap_1` as for kernels. Get/set, fix and constraint APIs from [CIP-0014](./cip0014.md) / REQ-0008 apply with no new mechanism.
- **Interchange.** The `CMatInterface` (MATLAB) bridge is not extended; the retirement plan ([REQ-0003](../requirements/req0003_matlab-bridge-retirement.md)) owns that path. Shared-model interchange ([REQ-000A](../requirements/req000A_shared-model-interchange.md)) gets a mean-function field in the interchange schema, in Phase 6.

### D6. Python façade

`gpc.mappings` mirrors `GPy.mappings` (`Constant`, `Linear`, `Identity`, `Additive`, `Compound`, `Kernel`, `MLP`, `PiecewiseLinear`), including `+` for `Additive`. `GPRegression`, `SparseGPRegression` and `SVGP`-style models accept `mean_function=`, with GPy's validation: the mapping's input and output dimension must match the data, else `ValueError` with both numbers. Predictions go through the existing `predict`, `predict_noiseless`, `posterior_samples_f`, which add \(\boldsymbol\mu\) automatically. `plot` shows the mean-function contribution alongside the posterior.

### Out of scope

- Sparse spectral and warped GPs.
- Mean functions on GPLVM latent space (needs \(\partial\boldsymbol\mu/\partial\mathbf X\) in the latent gradient; `gradX` is in the contract so this is a clean follow-on).
- Hierarchical or input-dependent *noise* means (heteroscedastic).
- Deprecating `bias`/`scale`.
- GPU backends.

## Implementation Plan

1. **Phase 0 — GPy reference fixtures.**
   - Script (`scripts/gen_mean_fixtures.py`, run against the local GPy checkout) producing `.csv`/`.model` fixtures for `GPRegression` with `Constant`, `Linear` and `Additive(Linear, Constant)` means: optimised parameters, log marginal likelihood, gradients, predictive mean/variance at fixed test points.
   - Gate: fixtures regenerate deterministically (fixed seeds); a README states the GPy commit used.
2. **Phase 1 — `CMean` and dense FTC.**
   - `CMean.h/.cpp`; `CConstantMean`, `CLinearMean`, `CIdentityMean`, `CAdditiveMean`; `CGp::setMean`, `updateM`, prediction paths (`latentMeanVar`, `predictiveMeanVar`, `posteriorMean`), parameter concatenation, `checkGradients`, stream, `paramPaths`.
   - `DIMENSIONMATCH` on input/output dimension at `setMean`; typed refusal on every unsupported approximation (D3).
   - Gates: with no mean function, objective, gradient, predictions and stream output are bit-identical to `main`; with a mean function, `checkGradients` passes for every parameter of every Phase 1 mapping; GPy fixtures agree within `ndlutil::MATCHTOL`; stream round-trip with `equals`.
3. **Phase 2 — Sparse regression.**
   - DTCVAR, then DTC, FITC, PITC (each gated separately; all four are required).
   - Gates: `checkGradients` per approximation; with all inducing points equal to the data, the sparse mean-function model equals FTC; DTCVAR agrees with GPy `SparseGPRegression(mean_function=…)`.
4. **Phase 3 — SVGP and the remaining mappings.**
   - `CSvgp` mean at \(\mathbf X\) and \(\mathbf Z\), `CCompoundMean`, `CKernelMean`, `CMlpMean`, `CPiecewiseLinearMean`.
   - Gates: SVGP objective agrees with GPy on a fixed minibatch; `checkGradients` for every new mapping, including `gradX`; `CMlpMean`/`CKernelMean` match GPy forward values.
5. **Phase 4 — EP and Laplace.**
   - Prior mean through the EP engine; Laplace with \(f=\boldsymbol\mu+\mathbf K\mathbf a\).
   - Gates: EP posterior agrees with GPy `EP` with `mean_function` on a classification fixture; Laplace passes `checkGradients` and agrees with an independent dense Newton solve with the mean added.
6. **Phase 5 — Deep GP unification (optional).**
   - `CDeepGp::meanP` becomes fixed `CLinearMean`; no behaviour change.
   - Gates: existing `testDeepGp` and `python/tests/test_deepgp.py` unchanged; CIP-0035 prototype trend reproduced.
7. **Phase 6 — Python façade and interchange.**
   - `gpc.mappings`, `mean_function=` on the regression models, plotting, interchange schema field, docs.
   - Gates: a GPy script using `mean_function=` runs in `gpc` with only the import changed; Python tests for dimension-mismatch errors and `+` composition.

## Backward Compatibility

- Default behaviour is unchanged: no mean function means `pmean == nullptr` and every existing path is taken as before. The regression gate in Phase 1 enforces this.
- `.model` files written without a mean function load unchanged. Files with one carry a bumped version so older GPc builds refuse them.
- `bias`/`scale` semantics, order of existing optimisable parameters, and `paramPaths()` for models without a mean function are unchanged. Mean parameters are appended *after* existing parameters so existing index-based code remains valid.
- No change to `CKern`, `CNoise`, or `COptimisable` contracts.

## Testing Strategy

- **Gradients (primary gate).** `checkGradients` for every mapping × every supported approximation. Per the *Assert Invariants* tenet this is the release gate: if the gradient disagrees with the finite difference, the combination is a typed refusal, not a shipped feature.
- **Reference.** GPy fixtures from Phase 0, compared with `ndlutil::MATCHTOL`, for FTC, DTCVAR, SVGP and EP.
- **Identities.** (a) Zero `CConstantMean` equals no mean function. (b) Fixed `CConstantMean(c)` plus zero bias equals zero mean plus `bias=c`. (c) Data \(y=\mathbf A\mathbf x+\epsilon\) with a `CLinearMean` and a kernel variance fixed near zero recovers the ordinary least squares \(\mathbf A\). (d) With \(\mathbf Z=\mathbf X\), sparse equals FTC.
- **Invariants.** Dimension mismatch at `setMean`; heteroscedastic/uncertain-input combinations throw; stream round-trip preserves a model with a nested `CAdditiveMean`.
- **Performance.** A micro-benchmark confirms that a model without a mean function pays no measurable overhead, and that `CLinearMean` evaluation is one GEMM.
- Tests land in `testMean.cpp` (mappings, gradients), additions to `testGp.cpp` and `testCGp.cpp` (model integration), and `python/tests/test_mean_function.py`.

## Decisions

Resolved at review, 2026-11-28:

1. **Space of the mean.** After `bias`/`scale`, in the same space as the kernel (GPy-aligned), as in D2.
2. **Sparse approximations.** DTC, FITC and PITC are in scope alongside DTCVAR, each with a derived gradient and a `checkGradients` test. GPy refuses these, so there is no GPy reference for them; the reference is the FTC model at \(\mathbf Z=\mathbf X\) and finite differences.
3. **`bias` and `CConstantMean`.** Kept separate. A later CIP may make `bias` a view of a constant mean; nothing here precludes it.
4. **Laplace.** In scope in Phase 4, going beyond GPy.
